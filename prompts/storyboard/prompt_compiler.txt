你将收到一个分镜镜头的结构化上下文 JSON。

任务：
1. 生成一条可直接用于“首帧图片生成”的中文静态提示词 `visual_prompt_static`。
2. 生成一条可直接用于“首帧图生视频”的中文运动提示词 `visual_prompt_motion`。
3. 生成负面提示词 `negative_prompt`。
4. 返回本次真正使用到的资产 `used_assets`。
5. 返回需要提醒给用户的 `warnings`。
6. 返回镜头唯一核心动作 `core_action`、按时长拆分的动作节拍 `action_beats`、入镜承接状态 `continuity_in` 和出镜结束状态 `continuity_out`。

强制规则：
- 静态提示词只能描述第一帧画面，不得写成任务说明或系统指令。
- 运动提示词只能描述镜头运动、人物动作、情绪推进、开始 / 过程 / 结束，不得重复大段静态提示词。
- 不允许输出“请生成”“用于首帧”“输出应为”“你需要”“不要暴露”“必须从首帧”等任务说明。
- 不允许输出 `Scene:`、`Shot:`、`Lighting:`、`Camera movement:`、`Action beats:`、`Preserve first-frame composition` 等模板字段。
- 不允许输出角色台词标签，如“姐姐：”“阿宁：”“和尚甲：”，也不允许输出对白正文、旁白正文、内心独白正文。
- 不允许输出 `[ ... ]`、`【 ... 】` 这类舞台提示、调度提示、剪辑提示或注释格式。
- 不允许把人物/场景/道具“参考图生成模板”原样写进分镜静态提示词。例如“人物定妆设定板”“六个视角”“上排为脸部特写”“下排为全身展示”“正面、侧面、45度”“标准六视图参考”“2行3列”“纯白背景”等只属于资产参考图生成，不属于当前分镜首帧画面。
- 不允许编造未绑定资产。
- 已绑定且有参考图的资产必须进入 `used_assets`。
- 已锁定参考图的关键资产必须在静态提示词里被自然提及，可使用资产名或 `reference_token`。
- 如果上下文中存在 `required_used_assets`，必须把这些资产全部保留在输出的 `used_assets` 中，不得漏掉。
- 如果某个角色、场景、道具存在 `reference_token`，优先把它作为显式参考锚点自然写入静态提示词，尤其是锁定参考图资产。
- 仅仅提及资产名或 `reference_token` 还不够；如果场景或道具存在权威原文，静态提示词还必须吸收具体视觉事实。
- 运动提示词必须包含一致性约束，强调角色、服装、场景、道具与首帧保持一致。
- `core_action` 只能有一个，是本镜头最重要的戏剧/视觉动作；如果动作链过载，应在 `warnings` 中明确提示需要延长或拆镜。
- `action_beats` 必须是当前镜头内可执行的动作节拍，优先使用 `start`、`end`（秒）和 `action` 字段；不要把多个连续动作压成一个长句。
- `continuity_in` 描述镜头开始时承接的可见状态，`continuity_out` 描述镜头结束时交给下一镜的可见状态。
- 结果必须是自然中文，不要乱码，不要 Markdown，不要解释，不要额外字段。
- 如果 `repair_request.rewrite_constraints.full_rewrite_required = true`，说明上一版已经出现对白稿残留；本次必须整体重写，不允许在原句上做轻微修补。

权威继承规则：
- 如果结构化上下文里出现 `authority_prompt_raw` 或 `authority_prompt_parts`，它们就是该资产的最高优先级权威原文。
- 如果结构化上下文里出现 `canonical_prompt_profile` 或 `canonical_prompt_parts`，必须把它们视为“已经清洗过、优先级最高、最适合下游继承”的规范资产描述；它们优先于松散概括和自由发挥。
- 对人物来说，必须优先继承权威原文中关于面部一致性、发型一致性、体型一致性、服装一致性、气质一致性的描述，再补当前镜头状态变化。
- 对人物来说，若绑定资产中存在 `gender` 且值不是“人物/未识别”，该性别是锁定权威事实：静态提示词必须明确写出对应性别，不得省略、替换或与定妆资产冲突。
- 对人物来说，若 `canonical_prompt_profile` 中存在 `identity / temperament / appearance / hairstyle / outfit / accessories / makeup_expression / scene_effects / consistency_notes`，应优先吸收这些字段，先保身份和一致性，再写当前镜头中的动作与状态。
- 若人物存在变体信息，如 `scope / stage_name / variant_name / shot_ids`，要把它理解为“当前镜头所使用的人物状态版本”；静态提示词要继承该版本的服装、发型、妆面、污渍、湿痕、损耗、配饰与情绪状态，而不是回退成泛化基础人设。
- 对场景和道具来说，必须优先继承权威原文中已有的空间、材质、陈设、状态、时代、限制条件，不得无根据改写。
- 对场景来说，若存在 `canonical_prompt_profile.description / style / lighting_mood / color_palette / core_visual`，要优先继承空间结构、时代感、材质氛围、光线情绪、色彩基调，不要擅自切换场景风格。
- 对道具来说，若存在 `canonical_prompt_profile.description / category / importance / core_visual`，要优先继承形制、材质、磨损与功能状态；若 `importance = high`，该道具应尽量在静态提示词中被明确提及。
- 对场景来说，不能只写“场景参考 @某场景”；至少补入 2 个来自权威原文的具体视觉细节，例如空间结构、地面材质、墙体 / 梁柱、光线、色调、湿痕、陈设。
- 对高重要度道具来说，不能只写“拿着木桶 / 某道具”；至少补入 2 个来自权威原文的具体视觉细节，例如形制、材质、颜色、磨损、结构、功能状态。
- 如果当前镜头命中了人物变体，应在继承基础定妆稳定性的前提下，吸收当前变体中的服装、妆面、湿痕、损耗、动作状态等差异。
- `used_assets` 应尽量覆盖本次提示词真正继承和引用到的权威资产，而不是只返回部分名字。
- 如果上下文中存在 `visual_fact_targets`，必须把它理解为“本镜头首轮编译必须显式吸收的视觉事实清单”；静态提示词要优先满足这些目标。

编译策略：
- 先读取 `asset_bindings.scene / characters / props`，判断本镜头真正绑定了哪些资产。
- 再读取 `compile_prompt_contract.summary_lines`，把它们当作本次首轮编译的硬约束摘要。
- 如果上下文中存在 `model_adapter`，其中的 `static_prompt / motion_prompt / negative_prompt` 是 Rule Compiler + Prompt IR + Model Adapter 生成的确定性基线；你可以做自然语言润色和模型偏好优化，但不得删除其中的资产锚点、动作阶段、一致性约束和负面约束。
- 如果 `model_adapter.static_prompt_sections.schema_version = storyboard_image_prompt_sections_v1`，必须先按该结构理解“分镜图提示词”：`frame_focus` 是画面定格，`asset_anchors` 是场景/人物/道具锚点，`composition` 是构图关系，`frozen_action` 是当前帧动作，`asset_visual_facts` 是必须继承的资产视觉事实，`lighting_emotion` 是光线与情绪，`constraints` 是一致性和禁止项。最终 `visual_prompt_static` 仍要写成自然中文画面描述，不要把这些字段名原样输出。
- 资产锚点只负责告诉模型“哪张参考图对应哪个场景/人物/道具”；资产视觉事实只继承当前镜头需要的外观、空间、材质、光线、状态。不得把参考图生成模板、设定板排版、六视图说明当作资产视觉事实。
- 若存在 `visual_fact_targets`，逐项检查每个资产至少应吸收多少条 `required_facts`，不要只写资产名，要把这些视觉事实自然编译进静态提示词。
- 若存在 `required_used_assets`，输出 `used_assets` 时必须完整覆盖它们；即使表达做了改写，也不能丢掉这些绑定资产。
- 再优先读取每个资产下的 `canonical_prompt_profile`，将其当作静态提示词的视觉事实来源。
- 若 `canonical_prompt_profile` 缺失，再退回 `authority_prompt_parts` 和 `authority_prompt_raw`。
- 若存在 `repair_request.priority_fixes`，必须按顺序优先修复前面的失败项，不要跳过最高优先级问题。
- 静态提示词应当明确写出：场景空间与光色、主体人物与相对位置、关键服装 / 发型 / 妆面、关键道具、画面情绪。
- 若上下文存在 `motion_contract`，它是运动提示词不可删除的结构化来源。必须将其中的 `start_state`、`camera`、全部 `action_beats`、`end_state` 和 `preserve_first_frame` 自然编译为一段可直接用于视频模型的中文运动描述；不得遗漏、改写成对白，或把字段名原样输出。
- 运动提示词必须让人能辨认出：起始可见状态 → 镜头方式（固定镜头也要明说）→ 中段动作推进 → 结束可见状态 → 与首帧一致的连续性约束。
- 不要把 `canonical_prompt_profile` 原样逐字段复述成清单；要把它们编译成自然、可执行的中文画面描述。
- 如果存在 `repair_request.failed_checks`，必须逐条修复；尤其当 `authority_prompt_inheritance.details` 提供了"资产名：补入 关键词A / 关键词B / 关键词C"时，要把这些缺失的视觉事实自然吸收到修复后的静态提示词里。
- 如果存在 `repair_request.screenplay_residue_details`，必须把这些残留模式全部清除，最终结果中不能再出现角色名加冒号、方括号提示、剪辑口令或对白句子。

摄影术语规范：
- 如果上下文中存在 `camera_library`，镜头运动描述必须使用词典中的标准化术语。`camera_movement` 对应词典 key，`camera_speed` 对应速度变体。
- 镜头运动描述格式示例："镜头固定不动"、"镜头缓慢向主体推进"、"镜头环绕主体向左旋转"。
- 景别描述优先使用 `shot_size_library` 中的中文术语（如"大远景"、"特写"、"极特写"），而非英文缩写。
- 角度描述优先使用 `camera_library.camera_angles` 中的中文术语（如"平视"、"仰拍"、"倾斜构图"）。

情绪运动编排：
- 如果上下文中存在 `emotion_library`，情绪运动描述必须使用词典中的标准化 motion_zh 描述，不要自行发明情绪肢体语言。
- 情绪运动描述格式示例：紧张情绪 → "手微微攥紧，呼吸变得急促"，悲伤情绪 → "肩膀微微塌下，目光低垂"。

Retention 维护：
- 如果上下文中存在 `retention`，它是镜头间视觉一致性的维护规则。`face / hair / costume` 必须 fully_preserved，`background` 应 mostly_preserved，`composition` 为 free 时允许调整构图。
- 静态提示词中必须体现保留项的约束：如果 face 为 fully_preserved，提示词中应包含与首帧一致的面部描述。

Continuity 连续性：
- 如果上下文中存在 `continuity` 且 `has_previous = true`，静态提示词的起始状态应与上一镜头的 `previous_end_state` 衔接。
- 运动提示词应自然承接上一镜头的结束状态，避免跳跃式突变。

Shot Purpose 目的导向：
- 如果上下文中存在 `shot_purpose`，它指示了该镜头的叙事目的。编译时应确保提示词服务于该目的。
- 例如 `shot_purpose = "suspense"` 时，运动提示词应强调缓慢推进、光影渐变等悬念元素。

Emotion Arc 情绪弧线：
- 如果上下文中存在 `emotion_arc`，编译运动提示词时应体现从 `start` 到 `end` 的情绪渐变过程，`intensity` 控制变化幅度。

短剧节奏引擎：
- 如果上下文中存在 `short_drama_library`，本镜头必须遵循单集节奏引擎的节奏约束。
- 前3秒（hook）：必须出现异常事件，不解释背景，主角必须在画面中做出反应。镜头必须用最具冲击力的画面开场。
- 3-15秒（setup）：快速交代核心矛盾、人物关系、主角目标，不需要解释前因后果。
- 15-60秒（friction）：每20-30秒设置一处情绪节点，压抑-爆发交替，台词短碎锋利。
- 高潮/尖峰（spike）：必须是本集最大的单一冲击——证据转移、视角翻转、代价支付。要出乎意料但情理之中。
- 结尾按钮（button）：在情绪最高点戛然而止，黑屏收尾。钩子力度必须大于本集所有冲突。比你觉得安全的时刻早2秒切断。
- 不要解释悬念，观众会感受到未完成感。

短剧钩子策略：
- 如果上下文中存在 `hook_library`，编译时必须遵循钩子策略。
- 开场钩子类型：直接冲突型（当众打脸）、强悬念型（枪口对准主角）、极致反差型（从巅峰到谷底）、震撼揭示型（身份曝光）、时间压力型（倒计时）。
- 结尾悬念钩子类型：悬念钩（身份疑问，黑屏留白）、危机钩（迫在眉睫的危险）、反转钩（一句颠覆所有剧情的台词）、情感钩（关键瞬间被打断）、信息钩（监控画面/证据出现）。
- 中段钩子：每15秒一次认知变化，新证据/新选择/隐藏信息曝光/关系突然变化。
- 黄金法则：把高潮「切开」，一半留到下一集。

短剧冲突结构：
- 如果上下文中存在 `conflict_patterns`，冲突必须是结构性的——内置在前提中，而非场景中临时制造。
- 身份反转（hook_power=10）：表面身份 vs 真实身份的巨大落差。短剧最核心的爆款公式。
- 当众羞辱→打脸反击（hook_power=9）：主角被当众羞辱→亮出证据→反转打脸。情绪爽点，完播率保障。
- 重生复仇（hook_power=10）：回到过去，带着前世记忆复仇。长线叙事核心驱动力。
- 秘密揭露（hook_power=9）：隐藏的秘密逐步被发现。悬念驱动，每集揭露一层。
- 倒计时（hook_power=8）：有限时间内必须完成某事。制造紧迫感。

短剧对白铁律：
- 如果上下文中存在 `dialogue_rules`，台词必须遵循以下原则。
- 每一句要么推进冲突，要么揭示角色，否则删掉。
- 台词是动作——不是解释，不是抒情，是推进。
- 用最少的词传递最大的信息量。
- 潜台词比明台词更有力。
- 冲突台词（你真以为我不知道你是谁？）/ 揭示台词（明天股东大会，我会让你一无所有）/ 悬念台词（你知道那天晚上真正发生了什么……）/ 沉默（比任何台词都重的停顿）。

短剧视觉语法：
- 如果上下文中存在 `visual_grammar`，必须遵循竖屏短剧的视觉约束。
- 竖屏构图：特写/近景为主，面部和眼睛是核心。人物居中，两个角色对话用正反打。竖屏中垂直运动比横向运动更有效。
- 镜头时长：单镜头3-8秒，适合AI视频生成。每个镜头只有一个主要动作。
- 表情优先：竖屏短剧靠脸吃饭。情绪微表情比任何对白都重要。反应镜头是最重要镜头之一。
- AI一致性：主角用2-3个锚点属性。每条提示词逐字重复人物一致句。

短剧情绪卡点：
- 如果上下文中存在 `emotion_checkpoints`，每集选1-2个情绪主基调，纯度越高越容易爆。
- 虐（被冤枉/被抛弃/被背叛）→ 压抑→爆发，制造情绪低谷，为爽点蓄力。
- 爽（打脸/复仇/逆袭/身份曝光）→ 释放→满足，情绪高点，完播率保障。
- 甜（亲吻/告白/守护/误会解除）→ 温暖→心动，CP线情感驱动。
- 燃（对抗强敌/逆风翻盘/觉醒）→ 压抑→爆发→升华，高潮时刻，情绪顶峰。
- 悬（秘密揭露/身份疑问/危机逼近/倒计时）→ 好奇→紧张→焦虑，悬念驱动，追更动力。

短剧致命坑规避：
- 如果上下文中存在 `common_pitfalls`，编译时必须规避以下错误。
- 开场铺垫超过10秒 → 直接划走。开篇直接上高潮。
- 结尾没有钩子 → 冲突平缓收尾，没有追更欲望。卡在情绪最高点。
- 长时间持续虐主角 → 观众弃剧。虐-爽交替。
- 大段长篇对话 → 节奏拖沓。台词短碎锋利。
- 解释性旁白/设定堆砌 → 3秒划走。用动作和画面传递信息。

短剧系列架构：
- 如果上下文中存在 `series_architecture`，编译时必须遵循系列架构约束。
- 开篇1-3集：极速铺世界观、立牢主角人设、抛出主线大矛盾。
- 剧集中段：三集一次小反转爽点，五集一次大型高潮。爽点和虐点交替穿插。
- 临近大结局：叠加连环反转，放出终极冲突，把全剧情绪推到顶峰。
- 支点集：关键转折集，重新定价整个故事。不要把最好的beat留到第8集。
- 系列长度：60-100集，每集60-120秒，总计90-150分钟，3-5个大弧线。
