# 2026-08-27 机器提示词二段式 H3 真实提交链路验收记录

## 结论

本轮已把机器提示词 API 提交任务从“只登记意图”升级为二段式真实提交第一版。

当前链路为：

1. 正式工作台登记 `machine_prompt_api_submission` 任务，`actual_provider_submission = false`。
2. 用户在高级导出区点击“真实提交 H3”，浏览器二次确认。
3. 后端校验确认口令 `CONFIRM_MINIMAX_H3_SUBMIT`。
4. 后端要求视频模型 provider 必须为 `minimax-h3-async`。
5. 从 H3 导出字段 `integrated_multimodal_description` 构造视频 prompt。
6. 若当前镜头存在采纳首帧，优先提交首帧图生视频；否则提交文生视频。
7. provider 返回视频 URL 后写回当前镜头视频资产，并保留 `externalTaskId / providerRequestPayload / providerResponse`。

## 安全边界

- 导出仍不等于提交。
- “登记 API 提交任务”仍不会调用真实 provider。
- “真实提交 H3”必须经过前端二次确认和后端确认口令。
- 如果当前默认视频模型不是 `minimax-h3-async`，后端会拒绝真实提交。
- 单元测试使用 mock provider 回包，不发真实外网请求、不产生费用。

## 已完成实现

- 新增接口：
  - `POST /api/prototyping/tasks/{task_id}/submit-machine-prompt-provider`
- 任务状态升级：
  - 保留 `kind = machine_prompt_api_submission`
  - 升级 `target_kind = video`
  - 写入 `actual_provider_submission = true`
  - 写入 `provider = minimax-h3-async`
- 视频资产回写：
  - 复用现有创意视频任务资产写回链路。
  - 支持后续 task center reconcile 继续回收 MiniMax H3。
- 正式工作台：
  - 高级导出区新增“真实提交 H3”。
  - 任务中心文案区分“只登记”和“已真实提交”。
