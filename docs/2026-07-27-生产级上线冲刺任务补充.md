## 二、P0 冲刺任务与验收标准

### P0-1 主链路完整跑通

任务：

- 用不少于 3 个真实项目跑通  
  `内容准备 -> 改编方向 -> 剧本 -> 分镜 -> 资产 -> QA -> 导出`
- 清点所有需要人工改库或改 JSON 才能继续的断点
- 把断点转成正式页面动作、恢复动作或阻塞提示

验收标准：

- 真浏览器完整路径可复现
- 不依赖人工改数据库或手工改 JSON
- 每个阶段都能看清当前状态、阻塞和下一步

### P0-2 分镜提示词质量达标

任务：

- 继续整改静态提示词和运动提示词生成方法
- 强化人物、场景、道具、状态、镜头意图的结构化继承
- 建立镜头样本抽检记录

验收标准：

- 抽检不少于 30 个镜头
- 提示词格式符合既定策划结构
- 不再大面积出现空泛、跑偏、错人、错装、错景

### P0-3 多变体资产继承稳定

任务：

- 稳定人物 `基础定妆 / 分集默认 / 分镜精调` 三层继承
- 补齐场景与道具多版本命中规则
- 保证资产中心与镜头工作台显示口径一致

验收标准：

- 同一镜头引用的资产版本可解释、可追踪
- 跨集、跨阶段、跨镜头状态下命中稳定
- 真浏览器下页面显示与实际生成输入一致

### P0-4 真实生成恢复链路可用

任务：

- 继续打通任务中心、镜头工作台、资产中心之间的恢复动作
- 补齐失败重试、重编后继续生成、按原始输入重发、按最新状态重生成样本

验收标准：

- 任务来源、提示词版本、输入摘要、失败原因全部可见
- 恢复动作执行后，状态能正确回写
- 不出现恢复后来源不明、状态错乱、版本丢失

### P0-5 QA 放行机制成型

任务：

- 继续把 QA 问题落到具体修复动作
- 完善 QA 生命周期与导出阻塞读取

验收标准：

- QA 问题可阻塞、可修复、可复检、可放行
- 导出中心读取真实 QA 阻塞，而不是依赖文案猜测

### P0-6 数据脏值与乱码系统清理

任务：

- 清理正式工作台剩余乱码、转义串、问号占位、历史脏字段直出
- 为典型脏值建立回归测试

验收标准：

- 核心模块不再暴露 `\uXXXX` 裸转义
- 不再随机出现明显乱码或历史脏值直出

## 三、P1 冲刺任务与验收标准

### P1-1 模型管理彻底收口

验收标准：

- 模型命名、别名、能力说明、默认模型和适配层行为一致
- 图像/视频模型能力可见：参考图、首尾帧、负向词、轮询能力

### P1-2 资产中心闭环增强

验收标准：

- 参考图预览、删除、默认、锁定、回写、镜头绑定稳定可用
- stale prompt 资产有明确修复动作

### P1-3 镜头工作台提交前确认

验收标准：

- 用户在生成首帧/视频前能看清实际提交的提示词版本、首帧、参考图、模型和任务模式
- 输入不完整时前端直接阻断

### P1-4 导出中心接近交付标准

验收标准：

- 阻塞项清晰
- 可直接回跳到对应修复模块
- 历史交付记录与阻塞回溯可读

### P1-5 回归样本库建立

验收标准：

- 至少 5 个代表性真实项目
- 覆盖古风、都市、多人、多场景、多道具
- 每轮关键改动后都可重跑
