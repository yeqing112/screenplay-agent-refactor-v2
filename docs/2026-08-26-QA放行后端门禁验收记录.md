# 2026-08-26 QA 放行后端门禁验收记录

## 背景

上一轮已经让前端导出中心读取真实 QA workbench 生命周期，但生产交付不能只依赖前端判断。本轮把同一 QA lifecycle gate 下沉到后端导出记录与 PDF 直出接口，避免前后端口径漂移。

## 本轮改动

- 后端新增统一 QA lifecycle 判断：
  - 放行：`recheck_passed`、`resolved`、`closed`、`accepted`、`workflow_status=resolved`、`workflow_status=wont_fix`
  - 阻塞：开放问题、修复中、已修复待复检、复检中等可执行问题
- `/api/books/{book_id}/qa/workbench` 的 `qa_summary` 现在返回：
  - `open_issue_count`
  - `in_progress_count`
  - `resolved_count`
  - `high_open_issue_count`
  - `blocking_issue_count`
- `POST /api/books/{book_id}/export-records` 增加后端 authoritative gate：
  - 如果前端误传 `status=completed`，但后端发现 QA 仍阻塞，会强制保存为 `blocked`
  - 自动补入 `blocked_codes=["qa_blocked"]`
  - 自动写入 `meta_info.qa_delivery_gate`
- `GET /api/books/{book_id}/export-pdf` 增加 QA 阻塞保护：
  - 仍有可执行 QA 问题时返回 `409 qa_blocked`
  - 已解决或 `wont_fix` 豁免的问题不阻塞
