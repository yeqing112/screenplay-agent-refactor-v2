# 2026-08-03 项目列表同名项目识别修复验收记录

## 问题背景

项目列表中存在同名项目时，首页会按标题做聚合去重，导致：

- 同名项目被错误合并，只显示一张卡片
- 真实用户和真浏览器验收都容易进入错误项目
- 例如 `三个和尚` 的 `book 14` 与 `book 17` 会互相覆盖

## 根因

文件：`web/src/pages/ProjectsPage.tsx`

历史逻辑会以 `displayTitle` 作为 key 做“最佳项目”筛选，只保留一个状态更高的同名项目：

- 这不是展示问题，而是数据直接被首页列表吞掉

## 修复内容

### 1. 取消同名项目聚合

- 首页项目列表改为保留全部项目，不再按标题去重

### 2. 增加稳定识别信息

- 项目标题在同名情况下显示为：`项目名 · #bookId`
- 卡片底部新增：
  - `ID {bookId}`
  - 创建日期
  - `同名 N`

### 3. 增加稳定自动化定位能力

- 卡片新增 `data-book-id`
- 卡片新增 `aria-label`

## 自动化验证

### 单测

- 命令：`cd web && npm run test -- ProjectsPage projectDisplayText`
- 结果：通过

覆盖点：

- 同名项目不再被合并
- 同名标题会自动追加 `#bookId`
- 单项目标题不追加多余后缀
- 旧乱码/失败标题兜底逻辑仍正常

### 构建

- 命令：`cd web && npm run build`
- 结果：通过

## 真浏览器验收

访问首页后确认：

- `三个和尚 · #14` 可见
- `三个和尚 · #17` 可见
- `[data-book-id="14"]` 可命中
- `[data-book-id="17"]` 可命中
- 卡片元信息中可见：
  - `ID 14`
  - `ID 17`

## 结论

本次修复后，项目首页已经可以稳定区分同名项目。

这项修复直接提升了：

- 真实用户选项目的准确率
- 正式产品工作台的真浏览器验收稳定性
- 后续以 `bookId` 为中心的任务恢复、镜头验收与问题复现效率
