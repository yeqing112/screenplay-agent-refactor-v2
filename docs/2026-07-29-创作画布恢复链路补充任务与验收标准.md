# 2026-07-29 创作画布恢复链路补充任务与验收标准

## 背景

截至 2026-07-29，`任务中心 -> 创作画布 Beta -> 镜头工作台` 的恢复链路已经具备真实上下文透传、跨刷新延续、missing 异常态识别与回退能力。

下一阶段不应只继续补“说明文案”，而要把这条链路推进成更接近 LibTV 的连续创作工作面。

## 任务一：missing 恢复目标闭环验收归档

### 执行内容

- 归档并固化 `创作画布 Beta -> 前往镜头工作台` 的 missing 态闭环验收
- 确保异常恢复目标场景下，镜头工作台仍能接住任务上下文

### 验收标准

1. 真浏览器中可复现 `暂未定位到恢复目标`
2. 画布横幅显示：
   - `恢复收口待人工确认`
   - `回任务中心`
   - `前往镜头工作台`
3. 不再显示 `定位恢复节点`
4. 点击 `前往镜头工作台` 后，镜头工作台横幅显示：
   - `恢复目标未命中`
   - `第 1 集 / 镜头 999`
   - `任务 ID：missing-task-001`
   - `回任务中心`
   - `我知道了`

### 当前状态

- 已完成
- 对应记录：`docs/2026-07-29-创作画布Beta缺失恢复目标回镜头工作台闭环验收记录.md`

## 任务二：创作画布从“恢复调度面”升级为“继续创作面”

### 执行内容

- 把画布中的恢复上下文继续推进成可执行创作动作，而不只是说明和跳转
- 优先围绕分镜节点补“继续创作”动作编排

### 建议拆解

1. 在画布分镜节点详情中拆出三类动作：
   - 查看当前状态
   - 继续当前创作
   - 回上游确认
2. 按恢复状态生成不同动作组合：
   - `closed`：继续生成下游内容
   - `changed`：先确认最新版本
   - `missing`：先确认镜头结构、候选镜头或同镜头最新任务
3. 让镜头工作台与画布共用同一套动作语义与说明

### 验收标准

1. 用户在画布中能直接理解“下一步继续创作什么”
2. 不是所有情况都必须先跳回任务中心或镜头工作台
3. 画布与镜头工作台对同一恢复状态给出的动作建议一致
4. 真浏览器完成至少 1 条 `恢复 -> 继续创作` 连续链路验收

## 任务三：镜头工作台补强 missing 态的本地修复动作

### 执行内容

- 在 `恢复目标未命中` 横幅中补充更强的本地修复动作
- 避免用户只能“知道了”或“回任务中心”

### 建议动作

1. 查看同镜头最新任务
2. 查看同集候选镜头
3. 重新同步镜头结构

### 验收标准

1. 用户在 missing 态下至少有 1 个可直接继续排查的动作
2. 不需要先回其他页面，仍能在镜头工作台内继续确认
3. 所有动作都保留当前恢复上下文，不丢 `episode / shotId / taskId`
