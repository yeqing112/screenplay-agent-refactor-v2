# 2026-07-21 首轮视觉事实覆盖诊断接入验收记录

## 本轮目标

把前面已经接入首轮编译上下文与模板的 `visual_fact_targets`，真正推进成运行态诊断能力：

1. 后端在静态提示词诊断时，按 `visual_fact_targets` 检查首轮视觉事实覆盖
2. 自动修复上下文能读懂这类诊断详情
3. 历史镜头在读取 outputs 时也能自动刷新出这条新检查
4. 真浏览器中能看到这条新诊断

## 本轮实现

### 1. 新增首轮视觉事实覆盖诊断

文件：

- `api/server.py`

新增检查：

- `visual_fact_target_coverage`

规则：

- 读取 `context.visual_fact_targets`
- 按资产逐条检查静态提示词是否满足 `min_facts_to_include`
- 如果不满足，就输出更具体的缺失详情，例如：
  - 该资产至少还差几条视觉事实
  - 还缺哪些视觉事实

这一层比旧的 `authority_prompt_inheritance` 更接近“首轮编译合同”。

### 2. 接入自动修复上下文

文件：

- `api/server.py`
- `tests/test_storyboard_prompt_repair_context.py`

处理：

- `visual_fact_target_coverage` 现在进入 `repair_request.visual_fact_targets`
- 修复阶段能直接拿到“缺哪几个事实”，而不是只看一条模糊 warning

### 3. 补齐历史镜头自动刷新

文件：

- `api/server.py`
- `tests/test_storyboard_prompt_context_legacy_refresh.py`

处理：

- 新增 `_prompt_compiler_diagnostics_need_refresh(...)`
- 如果历史 `compiler_diagnostics` 里还没有 `visual_fact_target_coverage` 等当前必需检查项
- 则在读取 outputs 时自动重建运行态诊断

这解决了一个真实问题：

- 不是所有老镜头都需要人工重新编译一次，才能看到新诊断
