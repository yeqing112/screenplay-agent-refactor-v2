# 2026-07-21 首轮编译硬约束模板接线与工作台可见性验收记录

## 本轮目标

把前一轮已经进入 `prompt_compile_context` 的首轮编译硬约束，真正接到两端：

1. 接到 `prompts/storyboard/prompt_compiler.txt`，让首轮 LLM 编译显式消费这些约束
2. 接到正式工作台镜头详情页，让操作员能直接看到“本镜头首轮编译到底该继承什么”

## 本轮实现

### 1. Prompt 模板接线

文件：

- `prompts/storyboard/prompt_compiler.txt`
- `tests/test_storyboard_prompt_compiler_template.py`

新增模板规则：

- 如果存在 `required_used_assets`，这些关键资产必须完整保留在 `used_assets`
- 如果存在 `visual_fact_targets`，要把它们理解为首轮编译必须显式吸收的视觉事实清单
- 首轮编译阶段明确读取：
  - `compile_prompt_contract.summary_lines`
  - `visual_fact_targets`
  - `required_used_assets`

这意味着：

- 新增的结构化上下文不再只是“埋在 JSON 里”
- 首轮编译模板已经明确要求模型消费这些字段

### 2. 工作台可见性补齐

文件：

- `web/src/prototyping/sceneComposerData.ts`
- `web/src/components/ProductWorkspaceStoryboardSection.tsx`
- `web/src/components/ProductWorkspaceStoryboardSection.test.tsx`

新增展示：

- `首轮编译硬约束摘要`
- `视觉事实目标`
- `必须保留在 used_assets 的关键资产`

现在在镜头详情页里，用户可以直接看到：

1. 这个镜头首轮编译时，场景 / 人物 / 道具分别要求继承哪些关键视觉事实
2. 哪些关键资产必须出现在 `used_assets`
3. 当前首轮编译的硬约束摘要，而不需要自己翻原始 JSON
