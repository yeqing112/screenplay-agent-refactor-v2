# 智能导演台 Agent：深度调研与架构建议

日期：2026-09-05  
对象：AI 影视生产系统的产品与工程决策  
结论状态：研究建议，**不构成开发授权**。

## 结论

可以做，而且本项目比一般“视频生成器”更适合做；但目标不应是一个可以任意调用模型和工具的聊天机器人，而应是一个可追溯的**受控导演编排 Agent**。

它的职责是理解创作意图、盘点当前事实、提出可执行的生产计划、调度既有工作流、发现质量风险、将问题路由到正确的修复链路，并在发生费用、覆盖版本、对外提交或不可逆变更前暂停等待确认。它不应替代用户的创作判断，更不应绕过当前的版本、证据、锁定资产和验收门槛。

## 外部事实与启示

### 1. 领先视频工具的方向是“可控创作资产”，不是自由自动化

- [Google Flow 官方介绍](https://blog.google/technology/ai/google-flow-veo-ai-filmmaking-tool/) 明确提供可复用的角色/场景 `ingredients`、从场景图发起新镜头、镜头控制、Scene Builder 和资产管理。它证明：资产、构图和镜头关系是视频工作流的一等对象；但其公开产品描述并没有把自由对话直接等同于不可审核的生产执行。
- [Runway Gen-4 官方介绍](https://runwayml.com/research/introducing-runway-gen-4) 把“世界一致性”建立在视觉参考与文字指令共同输入之上，并强调跨视角、人物、地点、对象的保持。它支持本项目把“分镜构图图 + 人物定妆图 + 场景/道具图”视为不同语义角色的输入，而非一组无差别图片。

**工程含义**：智能导演台必须先有资产语义、空间调度、镜头状态和连续性合同，再谈自动化；不能把文本 Prompt 当作唯一真相。

### 2. Skill 的合理形式是可发现、按需加载、带资源的能力包

- [Anthropic Agent Skills 官方文档](https://docs.anthropic.com/en/docs/agents-and-tools/agent-skills/overview) 将 Skill 定义为含元数据、指令及可选脚本/模板/资料的模块化能力，并采用按需加载（progressive disclosure），避免所有专业知识同时塞进对话上下文。

**工程含义**：本系统可支持 TVC、儿童教育、短剧、产品演示等 Skill，但 Skill 不是一段大 Prompt，也不是可执行任意代码的插件。它应被版本化，并声明输入合同、输出合同、允许调用的系统工具、证据前提、审批等级、预算与评估规则。

### 3. 生产型 Agent 的必要模式是暂停、审批、恢复与可追溯

- [OpenAI Agents SDK 的 Human-in-the-loop 文档](https://openai.github.io/openai-agents-python/human_in_the_loop/) 说明，高风险工具调用应产生可持久化的暂停状态；用户审批或拒绝后，原运行可恢复。文档还强调审批范围可以覆盖嵌套 Agent 与工具调用。
- [OpenAI Agents SDK Guardrails 文档](https://openai.github.io/openai-agents-python/guardrails/) 将输入、输出和工具调用都视为可设置边界与中断条件的对象。

**工程含义**：现有 `DecisionPacket`、草案、版本、锁定、验收记录和真实调用二次确认，已经是智能导演台最难得的基础。应把它们提升为 Agent 的运行协议，而不是另建一套聊天日志。

### 4. 成片与外部生成必须保留来源链

- [C2PA Content Credentials 规范](https://spec.c2pa.org/specifications/specifications/2.2/specs/C2PA_Specification.html) 定义了声明、清单、绑定、校验及处理链记录等内容来源机制。
- [Content Credentials 介绍](https://contentcredentials.org/) 将其定位为展示创作方式与编辑历史的可验证媒介来源信息。

**工程含义**：即使暂不直接写入 C2PA，系统也应先保存兼容的内部 provenance：素材来源、上传者/生成模型、Prompt Version、参考图集合、模型参数、外部任务号、文件哈希、验收结论和后续编辑链。以后才能安全导出或接入来源凭证。

## 对当前项目的适配判断

项目已具备以下底座，不必重写：

- `DecisionPacket`：事实、未知项、冲突、允许操作、证据指纹与草案去重。
- Prompt Compiler / Shot IR：导演语言与机器提示词的分层、模型适配、版本和回滚。
- 资产锁定与参考图：人物、场景、道具、分镜图、状态和可追溯引用。
- QA / Acceptance：生成物验收、失败标签、回退与重试谱系。
- 连续性合同：相邻镜头、交接帧及模型能力约束。
- 生产 Skill Runtime：已存在项目级生产规范和内建 Skill 状态。

缺失的是一个统一的“导演运行时”：它要把用户意图解析为计划，并将计划安全地映射到这些已有对象和 API。

## 建议的目标架构

```text
导演对话 / 工作台行动
        ↓
意图与范围解析器（只读）
        ↓
导演计划器 → DirectorPlan（步骤、依赖、风险、预算、审批点）
        ↓
证据装配器 → DecisionPacket / Shot IR / 资产快照 / QA / 连续性
        ↓
受限工具编排器 → 既有脚本、资产、分镜、Prompt、生成、QA 工具
        ↓
审批与执行状态机 → 草案 / 等待确认 / 执行中 / 验收 / 完成或阻塞
        ↓
版本、任务、验收和来源记录
```

### DirectorPlan 必须是独立的一等对象

每次对话不能直接“执行”。先产生一个可查看、可编辑、可恢复的计划，至少包括：

- `objective`：用户目标与创作约束；
- `scope`：书、集、镜头或资产范围；
- `evidence_snapshot`：所依据的资产、版本、QA、模型能力与预算快照；
- `steps`：只读诊断、草案生成、待确认外部调用、写入、验收等；
- `preconditions` / `blocking_issues`：缺图、资产未锁定、Prompt 过期、模型不支持等；
- `approval_policy`：哪些步骤可自动做，哪些必须确认；
- `cost_envelope`：模型、次数、预计图片/秒数，超出即停止；
- `rollback_anchor`：将影响的版本与可恢复点。

### 工具权限分四档

| 档位 | 示例 | Agent 行为 |
|---|---|---|
| A：只读 | 审查剧本、诊断连续性、生成证据包 | 可自动执行 |
| B：可逆内部草案 | 生成修复建议、Prompt 候选、拆镜方案 | 可自动保存为草案，绝不生效 |
| C：版本化写入 | 确认资产治理、创建 Prompt Version、采纳分镜 | 证据未变化且用户确认后执行 |
| D：外部成本/不可逆 | 调 LLM、生成图/视频、上传第三方、删除 | 明确展示参数、成本和影响后逐次确认 |

这与现有受控 LLM 和真实 H3 提交流程一致；Agent 只能调用权限更低或相等的操作，不能因“智能”而获得更高权限。

## Skill 规范建议

一个导演 Skill 应是目录/注册表实体，而非只是一段提示词：

```yaml
id: tvc-production-v1
name: TVC 创作与生产
version: 1.0.0
intent_patterns: ["做一支广告片", "创作 TVC"]
input_schema: brief + audience + product + duration + channels
required_evidence: [brand_constraints, legal_notes, target_platform]
allowed_tools: [script_plan, storyboard_plan, prompt_draft, qa_read]
external_tools: [image_generation, video_generation]
approval_policy:
  image_generation: explicit_each_batch
  video_generation: explicit_each_submit
quality_gates: [brand_safety, claim_check, shot_executability]
outputs: [creative_brief, beat_sheet, storyboard_plan, production_plan]
rollback: versioned_outputs_only
```

首批不应超过 3 个：

1. `短剧生产 Skill`：承接当前全链路；
2. `TVC Skill`：Brief、卖点、时长、品牌禁忌、平台规格、镜头节奏；
3. `儿童教育 Skill`：年龄段、知识目标、家长/儿童安全、语言难度、互动节奏和内容审查。

每个 Skill 首先只输出结构化计划和草案，复用共同的资产、分镜、Prompt、生成及 QA 工具。不要为每个品类复制一套数据库、页面或生成链路。

## 明确不建议做的事

- 不做“用户一句话，Agent 自动多轮花费并发布”的黑箱模式。
- 不允许第三方 Skill 获得数据库直写、密钥读取、任意 Shell、任意网络上传或绕过确认的权限。
- 不将聊天历史当作项目事实；事实只能来自版本化对象与冻结证据快照。
- 不用单一总分替代 QA。身份、服装、构图、连续性、叙事、品牌/合规应保留可解释失败标签。
- 不先做多 Agent 群聊。没有稳定的计划、工具合同和验收闭环时，多 Agent 只会放大不可控性。

## 分阶段落地建议（尚未实施）

### Phase 0：导演运行时设计与模拟

新增 `DirectorPlan` 领域模型、状态机和只读计划 API；拿真实项目做“只产计划、不执行”的影子运行，对比人工操作链路。验收标准是：计划能准确指出缺失资产、过期 Prompt、待确认调用和质量风险。

### Phase 1：对话式导演助手（只读 + 草案）

在正式工作台增加对话入口，先支持查询、解释、任务建议、证据包和草案。对话输出必须链接具体对象和版本，不能只给自然语言结论。

### Phase 2：受控编排

将既有 API 映射为 A–D 档工具；支持暂停/确认/恢复、成本上限、失败重试和任务时间线。外部生成仍逐次确认。

### Phase 3：首批垂直 Skill

以 TVC 和儿童教育为首批能力包。先以“规划与审核质量”衡量，后再扩展到资产/视频生成调度。

### Phase 4：来源与交付治理

补齐内部 provenance 图谱、导出清单，并评估 C2PA/Content Credentials 的可行接入；不要在没有来源数据的情况下只加一个“认证”按钮。

## 调研局限

本备忘录采用官方公开资料与当前代码结构；没有宣称 Google、Runway、Adobe 等产品提供本项目所需的完整 Agent 编排能力。市场产品页面会快速变化，任何具体 API、价格、地区可用性或商用权利，应在接入前再次按目标版本核验。
