# 2026-08-21 长任务状态持久化验收记录

## 背景

上一轮已补齐 API 安全边界、上传安全和 QA 修复 E2E。本轮继续推进生产硬化，聚焦长任务状态：

- 剧本 pipeline
- 分镜 pipeline
- 创意图像/视频生成 task

这些任务此前主要保存在进程内 dict 中。服务重启、进程切换或内存丢失后，前端继续查询同一个 task id 会得到 404，不利于真实生产恢复。

## 改动

### 新增持久化模型

- 新增 `models/task.py`
- 新增 `TaskRun`：
  - `task_id`
  - `task_kind`
  - `status`
  - `progress`
  - `book_id`
  - `episode`
  - `payload`
  - `error`
  - `created_at`
  - `updated_at`
  - `finished_at`

### 新增数据库迁移

- 新增 `alembic/versions/d4e5f6a7b8c9_add_persistent_task_runs.py`
- 当前 Alembic head 已收敛为：
  - `d4e5f6a7b8c9`

### API 状态恢复

- `/api/pipeline/task/{task_id}`
  - 内存 miss 时从 `task_runs` 恢复。
- `/api/pipeline/storyboard/task/{task_id}`
  - 内存 miss 时从 `task_runs` 恢复。
- `/api/prototyping/tasks/{task_id}`
  - 内存 miss 时从 `task_runs` 恢复。
- `/api/books/{book_id}/creative-tasks`
  - 合并当前内存任务与 DB 历史任务。
  - 当前进程内任务优先展示，避免历史状态抢占正在运行的状态。

### 分镜恢复文案

- 将分镜截断、结构错误、缺少剧本、未知失败等 guidance 改为干净中文。
- 断点恢复提示包含“已完成到 / 可继续”等稳定语义。

## 当前边界

- 本轮没有引入独立任务队列或 worker。
- `task_runs` 当前是状态恢复底座，不负责重新调度已中断任务。
- visual setup task 与 storyboard prompt compile task 仍未完全接入统一任务表。
- 尚未实现任务 TTL、归档或清理策略。

## 后续建议

1. 增加 `task_runs` TTL 清理命令或 API。
2. 将 visual setup task 与 prompt compile task 纳入同一持久化机制。
3. 修复 `tests.test_visual_asset_library`，恢复视觉资产接口测试基线。
