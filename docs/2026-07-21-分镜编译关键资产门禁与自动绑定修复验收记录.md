# 2026-07-21 分镜编译关键资产门禁与自动绑定修复验收记录

## 本次修复目标

围绕分镜提示词编译链路，完成两件事：

1. 防止 LLM 输出退化版本时覆盖已有可用 prompt version。
2. 修复真实运行态中自动绑定漏掉人物/道具，导致门禁失效的问题。

## 关键问题

### 问题 1：退化候选会覆盖旧版本

真实验收中，`book 14 / episode 1 / shot 1` 曾出现：

- 当前镜头已有场景、人物、道具信息
- LLM 编译结果只保留场景提示词与场景 `used_assets`
- 系统仍然保存为新版本

这会导致：

- 最新版提示词丢失人物与关键道具
- 最新 `used_assets` 与真实镜头语义脱节
- 后续分镜出图继续沿用错误上下文

### 问题 2：真实自动绑定上下文不完整

进一步排查发现，门禁在真实运行态没有触发，不是门禁逻辑本身失效，而是编译前的 `structured_seed` 过瘦：

- 只带了 `scene_name` 与 `action_process`
- 没带 `start_state` / `end_state` / `dialogue`

而 `book 14 / shot 1` 的人物和木桶关键词主要出现在 `end_state` 中，因此真实编译时没有绑定出：

- `和尚丙`
- `和尚乙`
- `和尚甲`
- `木桶`

这样一来，`critical_bound_asset_usage` 在真实链路里就看不到这些资产，自然无法阻断“场景-only”结果。

## 本次代码修复

### 1. 编译安全门

文件：`api/server.py`

- 新增 `critical_bound_asset_usage` 诊断项。
- 检查以下关键绑定资产是否仍保留在本次编译的 `used_assets` 中：
  - 已绑定且有参考图的场景
  - 已绑定且有参考图的人物
  - 已绑定、已存在参考图、且 `importance = high` 的道具
- 将该项加入：
  - 自动修复重试触发条件
  - 自动修复后的硬阻断条件
- 422 阻断响应中补回：
  - `repair_attempted`

### 2. 自动绑定真实上下文补全

文件：`api/server.py`

在编译入口与结构获取入口中，补齐 `structured_seed`：

- `dialogue`
- `start_state`
- `end_state`
- `duration`
- `camera_angle`
- `camera_movement`
- `transition`

修复后，真实镜头可从 `end_state` 中自动识别出人物与木桶绑定。

### 3. 输出序列化容错补强

文件：`api/server.py`

额外修复了一个运行态健壮性问题：

- 当 `prompt_compile_context.asset_bindings.scene` 被旧数据或手工结构写成 `null`
- 输出接口在序列化时会直接对 `None` 调用 `.get()`，导致 `/api/pipeline/book/{book_id}/outputs` 500

现已改为先校验 `scene_binding` 是否为字典，不是则回退为空字典，避免半成品结构把整个项目输出接口带崩。
