# 2026-08-21 视觉资产接口测试基线修复验收记录

## 背景

在完成长任务状态持久化后，后端完整测试仍暴露 `tests.test_visual_asset_library` 失败。失败集中表现为 `GET /api/books/{book_id}/visual-assets` 返回 404，导致测试中期望的 `locations / props / characters` payload 缺失。

## 根因

`get_visual_assets(book_id)` 的实现仍存在，但未注册为 FastAPI 的 GET 路由。应用中只注册了视觉资产的 PATCH、参考资产 POST/PATCH/DELETE 等写入路由，因此真实 HTTP GET 请求无法命中读取接口。

## 修复

- 在 `api/server.py` 为既有 `get_visual_assets(book_id)` 添加：
  - `@app.get("/api/books/{book_id}/visual-assets")`
- 未改变原有数据查询、参考图归一化、场景/道具/角色序列化和 storyboard 同步逻辑。

## 结论

## 后续建议

1. 增加 API 路由清单/契约测试，覆盖前端依赖的关键 GET/POST/PATCH/DELETE 路径是否已注册。

3. 为 `task_runs` 设计 TTL、归档或清理策略，避免生产数据库长期膨胀。
