## 3. 提示词诊断细化：从“继承不足”升级到“缺哪些视觉事实”

### 发现的问题

进程内复核 `book 14 / shot 1` 时，`authority_prompt_inheritance` 仍失败，说明静态提示词虽已引用：

- `@寺庙后院水房`
- `木桶`

但没有真正吸收足够的场景/道具权威视觉细节。

同时，旧诊断细节对人物会出现“定妆板模板废话”一类噪音，不能直接指导修复。

### 整改

调整文件：

- [api/server.py](D:/Work/Project/screenplay-agent-refactor-v2/api/server.py)
- [prompts/storyboard/prompt_compiler.txt](D:/Work/Project/screenplay-agent-refactor-v2/prompts/storyboard/prompt_compiler.txt)

#### 3.1 诊断优先读取 canonical parts

`authority_prompt_inheritance` 的关键词来源改为：

- 优先读取 `canonical_prompt_parts`
- 仅当 canonical 缺失时，才退回 `authority_prompt_parts`

这样可以避免把“定妆板布局说明”当成人物视觉缺口。

#### 3.2 诊断细节改为输出可执行补词建议

现在失败检查会输出类似：

- `寺庙后院水房：补入 寺庙后院的水房 / 青石板铺地 / 中央一口老井`
- `木桶：补入 木质或竹编水桶 / 圆柱形 / 外壁多道竹箍或铁...`

而不是只给出资产名。

#### 3.3 修复上下文保留 failed check details

`_build_prompt_repair_context(...)` 现在会把失败检查的 `details` 一并传给重修提示词链路。

这让后续自动修复有机会明确知道：

- 场景缺了哪些结构和材质
- 道具缺了哪些形制和磨损信息

#### 3.4 prompt compiler 模板强化

在 [prompts/storyboard/prompt_compiler.txt](D:/Work/Project/screenplay-agent-refactor-v2/prompts/storyboard/prompt_compiler.txt) 中新增了更明确的硬性约束：

- 不能只写资产名或 `reference_token`
- 场景至少补入 2 个具体视觉事实
- 高重要度道具至少补入 2 个具体视觉事实
- 如果 `repair_request.failed_checks` 里带了 `authority_prompt_inheritance.details`，必须逐条吸收
