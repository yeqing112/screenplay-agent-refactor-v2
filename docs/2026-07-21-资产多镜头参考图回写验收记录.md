本轮针对一个真实生产缺口做复验：

- 资产中心已经能推断某资产影响多个镜头，例如 `木桶` 显示 `影响镜头 6 / 待同步绑定 6`
- 但旧逻辑在资产还没正式保存 `shot_ids` 时，只会把单个 `metaInfo.shotId` 传给后端

## 本次修复

### 前端

- 文件：`web/src/components/productWorkspaceAssetActions.ts`
- 调整：
  - `resolveAssetReferenceShotTarget(...)` 现在除了主目标 `shotId`，还返回整组 `relatedShotIds`
  - 资产中心生成参考图并回写时，会把 `metaInfo.shotIds` 一并提交给后端

### 后端

- 文件：`api/server.py`
- 调整：
  - `_mirror_reference_asset_to_storyboard(...)` 现在会把 `meta_info.shotIds` 透传进 storyboard reference metadata
  - `_save_reference_asset_to_storyboard(...)` 在没有正式 `shot_ids` 绑定时，会优先读取 `metadata.shotIds` 作为多镜头兜底，而不是只认单个 `shotId`

## 对应验收标准

本次修复满足以下落地标准：

1. 当资产中心已推断出多个影响镜头，但资产记录尚未保存正式 `shot_ids` 时，参考图回写不能只命中单镜头。
2. 前端提交参考图时，必须把可用的推断镜头范围显式传给后端。
3. 后端在没有正式绑定时，必须支持按多镜头兜底回写 storyboard references。
4. 真浏览器下，资产卡状态必须从 `待补图` 更新为 `可引用`，且预览/默认参考计数同步变化。
5. 真接口下，reference token 必须可在全部目标镜头的 `asset_links.references` 中查到。
