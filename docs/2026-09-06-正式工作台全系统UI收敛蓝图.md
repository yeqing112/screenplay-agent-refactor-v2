# 正式工作台全系统 UI 收敛蓝图

## 目标与边界

目标用户是正在完成一部 AI 影视作品的普通创作者，而不是需要理解所有底层对象、模型协议和审计字段的系统操作员。界面必须在任意时刻回答：当前在做什么、为什么不能继续、下一步点哪里、点完会发生什么。

本轮不删除生产能力，不改变真实模型调用的双确认边界，不删除历史媒体、Prompt Version、验收或审计；仅重构信息架构、状态投影与组件层级。技术细节保留在“高级 / 历史 / 管理”层。

## 唯一主线

```
准备故事 → 锁定创作方向 → 完成剧本 → 准备资产 → 制作镜头 → 检查成片 → 导出交付
```

每个项目只有一个 `current_stage` 和一个 `primary_action`。它们由既有锁稿、放行、资产、Prompt、视频验收、连续性和 QA 状态计算，不由页面局部猜测。

- 上游阻断时：只展示阻断原因和可执行的上游动作；下游按钮改为“完成前一步后开放”，不再并列展示多个不可执行操作。
- 同阶段存在多个问题时：先显示影响生产的最高优先级问题；其余放入“还有 N 项待处理”。
- 有真实外部费用的操作：保持既有明确确认，不用“下一步”语义掩盖成本或外部提交。

## 全局组件规范

### 项目阶段条

位于每个正式工作台页面标题下方，显示 7 个阶段及当前阶段。只显示已完成、当前、被阻断和待开始，不显示内部诊断项。点击当前阻断项可转到唯一处理页面。

### 当前行动卡

页面首屏只能有一张高强调卡：

- 当前结果：例如“剧本还未放行”
- 原因：一句人话
- 主按钮：例如“去完成剧本放行”
- 影响范围：例如“镜头、资产和视频生成会在放行后开放”

次要操作不使用与主按钮同等级的视觉强调。

### 状态字典

全系统统一采用：`未开始 / 进行中 / 待确认 / 待检查 / 需处理 / 已通过 / 已归档`。业务细节只在二级文案中表达，例如“需处理：上一镜版本已更新”。

禁止同一语义同时以 `待补齐、缺图、未同步、阻塞、待治理、待重编` 等多个一级标签呈现。旧代码状态可映射为统一标签，保留原始码用于审计。

### 高级层

Prompt、机器导出、版本、诊断、对象存储、模型能力、原始 JSON、审计记录默认收进折叠区。折叠标题必须说明用户收益，例如“高级：查看版本和恢复记录”，不能只写“高级”。

## 页面收敛设计

### 项目控制台

- 保留项目摘要和唯一下一步。
- 指标压缩为一行：剧本、资产、镜头、验收、阻断。
- 单集 readiness 从技术统计改为“第 1 集正在：完成剧本放行”。
- 不重复展示导出、QA 和镜头页面已经解释过的阻断详情。

### 镜头工作台

首屏固定为：镜头列表、当前镜头、生产状态、唯一主操作、连续性状态。导演分镜语言是默认创作内容。

- 图片/视频/参考资产以“当前可用输入”和“当前成片”卡片显示，不在首屏并列全部历史版本。
- 连续性卡维持当前的普通语言设计；仅当本镜与上一镜需要承接时展示。
- Prompt 草案、机器导出、诊断、历史、拆镜和恢复归入高级生产工具。
- 上游未放行时，停止渲染“重编提示词、上传、生成、验收”类执行入口，只展示只读摘要和上游行动。

### 创作画布

创作画布保留为全局关系检查与上下文跳转工具，不作为替代镜头工作台的日常生产入口。

- 首层先说明它连接剧本、分镜、资产、媒体、QA 与交付，并展示当前项目的规模摘要。
- 搜索、视图重置、节点类型、状态与资产分组筛选都默认折叠为“高级”工具；关系图、节点详情和原有跳转/恢复能力不删除。
- 用户需要完成生产时，应使用项目阶段条引导到资产、镜头、QA、任务或交付；画布只在需要理解关联、定位卡点和跨模块跳转时打开。

### 资产中心

资产卡只显示：可用状态、资产缩略图/缺图、影响范围、下一步。默认视图按“影响生产的待处理资产”排序。

- “影响 19 镜头”可点击进入抽屉，不在右栏平铺 19 张重复卡。
- 视觉事实、结构化 Prompt、治理证据、绑定差异、版本历史归入详情。
- 人物、场景、道具使用相同卡片结构；人物 QA 作为人物详情的一个标签页。

### QA 修复

默认仅显示“待处理且影响当前生产”的工单，已解决/不修复默认进入历史。

- 每个工单只有一个推荐修复路径：自动草案、人工编辑或不处理。
- 原文、修复稿、diff 组成单一对比面板；版本列表默认折叠。
- 工单列表显示严重级、影响阶段和预计下一步，避免重复的状态胶囊。

### 模型与存储

分为两个层级：

1. 生产默认：当前 LLM、图片、视频模型与“可用 / 需配置”状态。
2. 管理员设置：注册表、能力矩阵、供应商协议、对象存储、迁移。

页面第一层只能引用当前真实生效配置；任何“建议切换”必须与真实默认值分开，且不能产生“当前是 A，但界面说应该是 B”的冲突。

### 任务与导出

- 任务中心按“需要你处理 / 正在执行 / 历史”组织，而不是任务类型和原始状态。
- 导出中心以交付检查清单呈现；只有一个首要阻断，其他问题折叠为按完成顺序排列的清单。

## 智能导演台 Agent（独立产品层，前置启动）

来源：\docs/2026-09-05-智能导演台-Agent-深度调研与架构建议.md\  
落档：\docs/2026-09-06-智能导演台Agent-用户决策与落档方案.md\  
状态：用户决策已对齐，进入阶段化落档与实施准备。

### 用户决策

1. 抽屉式对话窗口：右侧弹出，可隐藏，不影响工作台。
2. Agent 模型独立配置：在「模型管理 → 管理员配置」中单独指定与计费。
3. 显式确认门槛：创作预览、解释与诊断不需确认；改资产、提交生成、覆盖版本必须由用户显式确认。
4. Skill：首批内置 TVC、儿童教育、短剧、连续性；并允许第三方或自研扩展。
5. 审计与回放：所有 Agent 操作纳入审计日志，支持按项目、Skill、模型、时间段、风险等级过滤回放。

### 目标架构

\\\	ext
导演对话 / 工作台行动
        ↓

        ↓

        ↓

        ↓

        ↓

        ↓
版本、任务、验收、来源记录与 Agent 审计日志
\\\

### 工具权限四档

| 档位 | 示例 | Agent 行为 |
|---|---|---|
| A：只读 | 审查剧本、诊断连续性、生成证据包 | 自动执行 |
| B：可逆内部草案 | 修复建议、Prompt 候选、拆镜方案 | 自动保存为草案，不生效 |
| C：版本化写入 | 确认资产治理、创建 Prompt Version、采纳分镜 | 证据未变化且用户确认后执行 |
| D：外部成本/不可逆 | 调 LLM、生成图/视频、上传第三方、删除 | 逐次确认 |

### 阶段化落地

- Phase 0：DirectorPlan、agent_session、agent_audit_log 领域模型与只读计划 API（影子运行，不接 UI）。
- Phase 1：全局抽屉式对话 UI，输出必须可链接到对象与版本；不触发 C/D 档。
- Phase 2：受控编排，A–D 档工具映射、暂停/恢复、成本上限、失败重试、任务时间线。
- Phase 3：首批 4 个 Skill（短剧 / TVC / 儿童教育 / 连续性），支持第三方受控扩展。
- Phase 4：内部 provenance 与 C2PA / Content Credentials 可行接入评估。

### 与现有 UI 收敛的关系

- 抽屉默认隐藏，不影响\"当前状态 / 原因 / 唯一下一步\"首屏设计。
- 工作台选中对象可作为上下文注入对话；对话中确认的操作在原页面回显。
- Agent 操作审计与现有 DecisionPacket、Prompt Version、资产历史对齐，不重复建表。
- 本层是独立产品线，与\"正式工作台全系统 UI 收敛\"的发布候选解耦；其上线清单独立于本蓝图。
