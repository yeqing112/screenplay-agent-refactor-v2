# 生产级上线冲刺清单

日期：2026-07-27

## 1. 目标定义

本清单用于把“产品重构蓝图”推进到可上线判断阶段。

这里的“上线”分为两层：

- 内测上线：服务项目团队自身真实生产，可接受少量人工兜底
- 生产级上线：能够稳定承载真实项目生产，不依赖频繁人工修补，不因常见异常中断主链路

当前判断：

- 正式工作台整体达成率：约 70% - 78%
- 生产级可上线达成率：约 55% - 65%

结论：

- 当前适合继续作为内测版推进
- 当前不建议直接按“生产级产品已可对外上线”判断

---

## 2. 冲刺分级

### P0：必须先完成，否则不上线

1. 主链路完整跑通  
从 `内容准备 -> 改编方向 -> 剧本 -> 分镜 -> 资产 -> QA -> 导出` 至少跑通 3 个真实项目。

2. 分镜提示词质量达标  
静态提示词、运动提示词达到既定结构和质量标准，且可稳定引用资产与状态。

3. 多变体资产继承稳定  
人物、场景、道具在跨集、跨阶段、跨镜头状态下，能够稳定命中正确版本。

4. 真实生成恢复链路可用  
失败任务、重编后继续生成、按原始输入重发、按最新状态重生成都必须可追踪、可恢复、可解释。

5. QA 放行机制成型  
不是只有 QA 页面，而是有明确的阻塞、修复、复检、放行标准。

6. 数据脏值与乱码系统清理  
正式工作台各核心模块不再随机暴露乱码、转义串、问号占位或历史脏字段。

### P1：强烈建议上线前完成

1. 模型管理彻底收口  
统一模型命名、别名、能力说明、默认值与适配层行为。

2. 资产中心闭环增强  
参考图预览、删除、默认、锁定、回写、镜头绑定和 stale prompt 修复动作全部顺手可用。

3. 镜头工作台提交前确认  
生成首帧/视频前，用户能看清本次实际提交的提示词版本、参考图、首帧、模型和模式。

4. 导出中心更接近交付标准  
所有阻塞项可见、可回跳、可追溯。

5. 回归样本库建立  
至少覆盖 5 个代表性项目，支持每轮关键改动后重跑。

### P2：可灰度后补

1. 批量任务进一步自动化
2. 更细的运营/统计面板
3. 更完整的权限/协作能力
4. 更丰富的导出模板
5. 更深的提示词审计报表
6. 更细的模型成本与配额控制

---

## 3. 当前推荐冲刺顺序

1. 分镜提示词质量稳定化
2. 多变体资产命中稳定化
3. 主链路真实项目跑通
4. QA 放行与导出阻塞收口
5. 恢复链路与异常场景补齐
6. 模型管理与旧数据兼容收尾

---

## 4. 每项验收标准

### 4.1 主链路完整跑通

验收标准：

- 至少 3 个真实项目从内容准备走到导出中心
- 每个阶段都有明确输入、输出和下一步建议
- 不出现必须人工改库或改 JSON 才能继续的断点
- 真浏览器完整操作可复现

### 4.2 分镜提示词质量达标

验收标准：

- 抽检不少于 30 个镜头
- 静态提示词包含人物、场景、道具、状态、时间、机位、质感等必要信息
- 运动提示词能表达明确的镜头运动和动作变化
- 正确继承资产版本与分镜状态
- 不再出现大面积模板化、空泛化、错误角色、错误服装、错误场景

### 4.3 多变体资产继承稳定

验收标准：

- 人物支持基础定妆、分集默认、分镜精调三层稳定引用
- 场景与道具支持多版本命名、筛选、引用和回看
- 同一镜头引用的资产版本可解释、可追踪
- 真浏览器下，资产中心与镜头工作台显示一致

### 4.4 恢复链路可用

验收标准：

- 任务中心能显示真实任务链路、版本关系、输入摘要、失败原因
- 支持刷新、继续回收、按原始输入重发、按最新状态重生成
- 恢复后状态能回写到镜头工作台和资产中心
- 不出现恢复后任务来源不明、状态错乱、版本丢失

### 4.5 QA 放行机制成型

验收标准：

- 每个 QA 问题都可落到具体修复动作
- QA 生命周期至少包括 `open / in_progress / resolved / wont_fix`
- 修复后可复检，可回写状态
- 导出中心能读取真实 QA 阻塞而不是仅看文案猜测

### 4.6 数据脏值与乱码系统清理

验收标准：

- 正式工作台主要模块不再出现 `\uXXXX` 裸转义
- 不再出现明显乱码或 `???`
- 历史项目中常见旧数据能正常展示
- 对典型脏值建立回归测试

---

## 5. 上线策略建议

### 阶段 A：内测上线

目标：

- 用于团队自身真实生产
- 允许少量人工判断和兜底

前提：

- P0 全部完成

### 阶段 B：生产级上线

目标：

- 可稳定承载真实项目生产
- 大多数常见异常可在系统内恢复

前提：

- P0 全部完成
- P1 至少完成 70%
- 已建立真实项目回归样本库

---

## 6. 执行要求

- 之后的推进优先以本清单作为“上线判断门槛”
- 新功能不应优先级高于 P0 风险收口
- 每完成一项关键冲刺内容，都要同步：
  - 蓝图
  - 阶段任务与验收标准
  - 对应验收记录

---

## 7. 当前状态结论

当前产品已不再是纯演示原型，但仍处于：

- `可持续迭代的内测版`

尚未达到：

- `可放心对外承诺稳定交付的生产级产品`

下一步默认执行方向：

- 先完成 P0
- 再压缩 P1
- 最后再考虑生产级上线判定
