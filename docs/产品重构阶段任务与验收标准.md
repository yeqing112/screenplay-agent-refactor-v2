# 产品重构阶段任务与验收标准

更新时间：2026-08-27

## 1. 文档目标

本文档用于把《产品重构蓝图》与《产品重构实施方案》落成可执行的阶段任务，并给出统一验收口径。

当前要求不是继续堆单点功能，而是稳定推进以下正式主链路：

`内容准备 -> 改编方向 -> 剧本工作台 -> 镜头工作台（导演分镜语言） -> 资产中心 -> 提示词编译与多模型导出 -> QA 修复 -> 导出中心`

其中，分镜提示词生产链路统一按以下四层推进：

`导演分镜语言（系统生成 + 用户可改） -> Shot Schema / Prompt IR -> 标准化机器语言 -> 多模型导出（WebUI / Markdown / CSV / API JSON） -> 可选 API 提交`

同时保证以下支撑模块持续可用：

- 项目控制台
- 创作画布
- 任务中心
- 模型管理

## 1.0 2026-08-22 单一正式工作台口径

从 2026-08-22 开始，前端产品入口收敛为一个正式工作台。

### 已移除的并行入口

- 旧版生产
- 创作沙盘
- 高级编排
- 产品原型 Demo

### 保留原则

- 正式工作台继续承载真实项目主链路。
- 删除旧前端控制台前，已先把 QA 人工预览/应用/回滚、镜头提示词锁定、验收记录提交迁入正式工作台。
- `/api/prototyping/*` 中仍被正式工作台调用的创意任务接口暂时保留。
- 历史 workflow/run/task 数据不作为代码清理对象。

### 新增验收口径

- 首页和项目内不再出现旧控制台入口。
- 生产构建不再生成 `ProductionMode`、`DirectorMode`、`SceneComposer`、`NodePanel`、`NodeConfigPanel`、`ProductBlueprintDemoPage` 相关 chunk。
- 前端源码不再保留不可达的旧节点执行层组件：`AgentNode`、`HistorySidebar`、`PromptSelector`、`ResultsPanel`、`pipelineLayout`、`types/nodes`。
- 正式工作台 QA 修复页可完成：生成方案 -> 预览 diff -> 应用修复并复检 -> 回滚脚本修复版本。
- 正式工作台镜头工作台可完成：提示词锁定/解除锁定 -> 保存验收记录。
- `npm run e2e:business` 作为正式工作台真实业务流回归基线，覆盖入口收敛、候选选择、Production Skill 锁定、主方向锁定、跨模块浏览、创作画布、模型管理、提示词锁定、验收记录、QA 修复、脚本回滚，以及镜头工作台显式提示词修复入口的真浏览器点击、异步重编译、版本增长和结构状态落库。
- QA 脚本回滚版本 label 不得出现 `鍥炴粴` 等历史乱码；真浏览器回归必须断言回滚版本显示正常中文 `回滚到`。

### 后续文档口径

- 文档历史段落中的 `创作画布 Beta` 只代表当时阶段名称；当前统一称为 `创作画布`。
- 后续任务不得再把旧版生产、创作沙盘、高级编排、产品原型 Demo 作为新增能力承载面。
- `/api/prototyping/*` 仍属于正式工作台创意任务兼容接口；`/api/workflows*`、`/api/nodes*`、`/api/runs*` 进入下一阶段后端旧执行层审计范围。

## 1.1 2026-08-15 剧本结构化生成整改补记

从 2026-08-15 开始，剧本链路新增一条高优先级执行原则：

### 暂停继续扩大启发式修补

后续剧本整改不再以“遇到一个真实样本问题，就继续补一条标题触发规则”为主路径。

原因：

- 这类修补会让规则越堆越多，但真实样本分数并不稳定上升
- Rewrite 更容易引入新的二次连续性错误
- QA / Rewrite 会越来越依赖当前样本表述方式，迁移性变差

### 改为推进结构化生成整改

后续剧本整改的正式路径改为：

1. 先定义结构化中间层
2. 再由结构化中间层编译剧本
3. QA 重点检查结构字段闭环
4. Rewrite 重点回写结构缺口，而不是继续扩写样本导向命中规则

## 1.2 2026-08-16 剧本生产 Skill 主路径重构

从 2026-08-16 开始，剧本链路新增一条更高优先级的实施口径：

### 废弃“自由文本直写整集”作为长期主路径

`Production Skill + Rewrite prompt -> 直接重写整集剧本` 只保留为兼容回退路径。

正式主路径改为：

`Story Fact Sheet -> Scene Execution Cards -> Screenplay Compiler -> Structure QA`

### 新增阶段 S1：剧本结构中间层落地

#### 目标

把剧本生成从“结果修补”改造成“结构先行”。

#### 任务

- [ ] 在 Script Skill foundation 中新增 `story_fact_sheet`
- [ ] 在 Script Generation Brief 中新增 `scene_execution_cards`
- [ ] 在 Execution Plan 中新增结构化编译阶段：
  - `fact_generation`
  - `scene_execution`
  - `screenplay_compile`
  - `structure_qa`
- [ ] 让 Rewrite / QA 开始读取这些新结构，而不是只读旧的 scene goal / issue title
- [ ] 为新结构补齐单测与真实样本回归口径

#### 验收标准

- `build_script_skill_foundation` 返回 `story_fact_sheet`
- `build_script_generation_brief` 返回 `scene_execution_cards`
- `build_script_skill_execution_plan` 明确包含新的结构化阶段
- 新结构字段进入 `foundation prompt block / generation brief / execution plan / repair packet`
- 单测通过，且真实样本回归时能证明链路已从“提取失败”转向“结构一致性问题”

### 新增阶段 S2：结构校验优先化

#### 目标

让 QA 先校验事实层和场景执行层，再评价成品剧本。

#### 任务

- [ ] 增加事实层一致性校验：
  - 物证唯一性
  - 物证流转闭环
  - 人设公开面连续性
  - 隐藏层触发器存在性
  - 帮助行为动机存在性
  - 机关操作路径完整性
- [ ] 增加场景执行卡兑现校验：
  - 开场状态
  - 必需视觉证明
  - 结束状态
  - 下一场承接条件
- [ ] 让 QA 输出优先映射到结构缺口，而不是只停留在 prose complaint

#### 验收标准

- QA 至少能指出一个明确结构字段缺口
- QA 报告能区分“事实层错误 / 场景执行层错误 / 编译层错误”
- 新增修复建议能定位到具体结构对象，而不是只说“重写这一场”

## 1.3 2026-08-25 分镜提示词编译与多模型导出口径

从 2026-08-25 开始，分镜提示词链路不再按“用户/系统写一段 prompt 然后直接提交模型”理解。

正式执行口径：

- `导演分镜语言` 是创作层：由系统生成，也允许用户在正式工作台中修改。
- `Shot Schema / Prompt IR` 是事实层：承载资产、动作、机位、连续性、首帧、参考图等可验证信息。
- `标准化机器语言` 是编译层：由系统把导演分镜语言和结构事实编译成模型更容易执行的标准描述。
- `多模型导出` 是交付层：同一机器语言可导出为 MiniMax H3 WebUI、通用视频 WebUI、Markdown、CSV、API JSON 等。
- `API 提交` 是可选生成动作：必须由 Generation Adapter 和任务中心承接，不属于 Prompt Compiler 本身职责。

本口径的落地记录：

- `docs/2026-08-25-导演分镜语言到机器提示词编译与导出备忘.md`
- `core/machine_prompt.py`
- `scripts/preview-storyboard-machine-prompt-export.py`
- `tests/test_machine_prompt_export.py`

## 2. 当前阶段结论

截至 2026-08-25，正式产品工作台已经完成“单一入口 + 可连续操作骨架闭环 + 业务流回归基线”，并开始把分镜提示词从字段修补推进为“导演语言可编辑、机器语言可编译、多模型格式可导出”的生产链路；但距离生产级上线仍有差距。

### 已经稳定的能力

- 正式产品工作台主导航已经收敛为唯一用户入口
- 内容准备 / 改编方向 / 剧本 / 镜头 / 资产 / QA / 导出 / 任务中心 / 模型管理 已接入正式入口
- `book 14 / 三个和尚` 这类真实项目可以在正式工作台中读取真实数据
- 镜头工作台、创作画布、任务中心之间已经具备真实镜头上下文联动
- 长任务恢复链路已经回到任务中心，并可重新进入镜头或资产工作台
- QA 修复与镜头验收的关键能力已迁入正式工作台
- `npm run e2e:business` 已覆盖正式工作台真实业务流的最小闭环

### 当前仍需持续推进的重点

- 主文档与规则文档的编码治理
- 正式工作台全链路真浏览器回归样本库扩展
- 提示词质量、资产继承、变体体系、机器提示词导出与模型执行链路的生产级补完
- LibTV 化创作体验继续落地，而不只停留在关系图

### 验收标准

- 用户能在正式工作台看到并修改导演分镜语言。
- 修改导演分镜语言后，系统能重新编译标准机器提示词；该保存动作不创建 Prompt Version，也不自动反写 Shot Schema。
- 同一镜头在不改 Shot Schema 的前提下，可导出至少两种模型格式。
- 用户能一键复制 MiniMax H3 全字段或单字段，并能保存“仅导出、不提交”的导出快照。
- 用户能下载 Markdown / CSV / API JSON 文件，且 API JSON 明确不触发生成提交。
- MiniMax H3 导出至少包含：
  - `integrated_multimodal_description`
  - `overall_soundscape`
  - `non_diegetic_music`
  - 参考图 / 首帧使用策略
- 导出预览明确显示 `api_submission = false`，API 提交必须通过单独动作进入任务中心。
- API 提交动作必须区分两段：登记阶段只保存任务意图和导出 payload，`actual_provider_submission = false`；真实提交阶段必须显式确认，任务中心要显示 MiniMax H3 provider 状态，并不得把普通导出误判为 provider 已提交。
- 机器提示词包含可观察动作时间线、镜头运动、连续性约束和负面约束，不再只是“情绪逐步增强”的模板句。
- 机器提示词提交字段不得残留 `画面开场 / 画面切 / [画面` 等导演剪辑口令；但导演分镜语言本身允许保留这些创作表达。

## 2026-08-26 补充：真实 LLM clone-only 灰度前置验证

### 已完成

- 新增 `scripts/validate-storyboard-real-llm-gray.py`，用于真实分镜样本的 clone-only 编译灰度验证。
- 新增 npm 入口：`npm run validate:storyboard-real-llm-gray`。
- 灰度验证默认不运行真实模型；未设置模式时只输出安全拒绝说明，不修改真实项目数据。
- 支持两种显式模式：
  - `STORYBOARD_REAL_LLM_GRAY_MOCK=1`：使用确定性 Model Adapter payload 验证克隆、编译、审计、回滚、清理安全路径。
  - `STORYBOARD_REAL_LLM_GRAY_RUN=1` + `STORYBOARD_REAL_LLM_GRAY_USE_REAL_LLM=1`：使用真实 LLM 验证 JSON 稳定性和编译质量。
- 支持通过 `STORYBOARD_REAL_LLM_GRAY_TARGETS=book_id:episode:shot_id` 精确指定样本，也支持 `STORYBOARD_REAL_LLM_GRAY_BOOK_IDS` 与 `STORYBOARD_REAL_LLM_GRAY_SHOT_COUNT` 控制灰度范围。
- 每轮输出 `artifacts/storyboard-real-llm-gray-*.json` 与 `artifacts/storyboard-real-llm-gray-*.md`，记录样本、模式、诊断状态、失败阶段和审计结果。
- 已使用 model registry 默认 LLM `mimo / mimo-v2.5` 完成真实 clone-only 灰度：
  - 单样本 `book 75 / 1 / 1`：`passed=1 / failed=0 / 0 error / 0 warning`。
  - 跨项目样本 `book 5 / 1 / 1`、`book 3 / 1 / 1`、`book 14 / 1 / 1`：首次结果 `passed=3 / failed=0 / 0 error / 2 warning`。
  - 五项目样本 `book 75 / 5 / 3 / 14 / 1` 各 1 个首镜：`passed=5 / failed=0 / 0 error / 1 warning`，总耗时 `376.624s`，主要耗时集中在真实 LLM compile 阶段。
- 已根据真实灰度暴露的问题补齐：
  - clone 脚本保留无法映射但源结构已有的人物/道具资产 id，避免克隆样本制造源项目没有的 warning。
  - LLM 输出进入诊断前统一执行 `sanitize_machine_prompt_text()`，清洗 `镜头推进为`、`动作推进为` 等导演标签化句式。
  - 复合场景名匹配从整串连续包含升级为分词包含，解决 `水房·清晨` 与“寺庙后院水房……清晨”这类格式差异误报。
  - LLM 静态提示词漏掉精确场景名时，编译链路会自动把真实 `scene_name` 前缀补回，解决 `麻栗山村口空地` 被泛化成“湘西苗寨村口空地”的灰度 warning。
  - 灰度报告新增逐样本 clone / compile / audit / rollback / 总耗时统计，以及 compiler diagnostics warning 摘要。

### 补充验收标准

- 默认执行不触发真实模型调用，也不写入真实项目。
- mock 灰度必须能完成真实镜头克隆、编译 API 调用、审计、回滚验证和临时书清理。
- real LLM 灰度必须在缺少有效密钥或缺少 `STORYBOARD_REAL_LLM_GRAY_RUN=1` 时拒绝执行。
- 任一样本编译失败、回滚失败、审计存在 error，命令必须非 0 退出。
- 真实项目批量 apply 仍必须走独立 preflight + confirmation token，不允许由灰度脚本直接写源项目。
- 真实 LLM 灰度过程需要保留逐样本报告，并在后续补充耗时统计。
