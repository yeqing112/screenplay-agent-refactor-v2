## 1.0a 2026-09-02 生产审计真实性与受控草案治理

此前历史记录中的“五项目 `0 error / 0 warning`”只能视为当时规则集下的结果，不能继续作为生产放行依据。已确认旧审计门禁未消费共享 Prompt Compiler 的 `warnings` 与失败 `checks[]`，形成假绿；现已修复，审计报告会完整保留 error、warning 和失败检查。默认 `zero-error-gate` 以 error 为生产阻断、warning 为必须可追踪的质量债；需要零 warning 的发布批次可设置 `AUDIT_STORYBOARD_STRICT=1`。

最新只读抽样基线（5 项目 / 50 镜头）为 `13 error / 170 warning`。这些问题多数属于历史 Prompt 或过期诊断，禁止直接批量覆盖、自动重编译或触发生成。整改统一遵循：

`证据包（只读） -> 显式确认真实 LLM -> 候选草案（不生效） -> 人工审核/编辑 -> 版本化确认写入/回滚`

当前 P0：先处理人物已知性别等权威事实未继承的阻塞项；再按资产参考图缺失、视觉事实覆盖不足、过期诊断分类建立治理队列。只有所有阻塞与告警收敛后，才可重跑生产门禁、真实浏览器主链路与真实模型灰度。

从 2026-08-15 开始，剧本链路新增一条高优先级执行原则：

### 暂停继续扩大启发式修补

后续剧本整改不再以“遇到一个真实样本问题，就继续补一条标题触发规则”为主路径。

原因：

- 这类修补会让规则越堆越多，但真实样本分数并不稳定上升
- Rewrite 更容易引入新的二次连续性错误
- QA / Rewrite 会越来越依赖当前样本表述方式，迁移性变差

### 改为推进结构化生成整改

后续剧本整改的正式路径改为：

1. 先定义结构化中间层
2. 再由结构化中间层编译剧本
3. QA 重点检查结构字段闭环
4. Rewrite 重点回写结构缺口，而不是继续扩写样本导向命中规则

## 1.2 2026-08-16 剧本生产 Skill 主路径重构

## 1.3 2026-08-25 分镜提示词编译与多模型导出口径

从 2026-08-25 开始，分镜提示词链路不再按“用户/系统写一段 prompt 然后直接提交模型”理解。

正式执行口径：

- `导演分镜语言` 是创作层：由系统生成，也允许用户在正式工作台中修改。
- `Shot Schema / Prompt IR` 是事实层：承载资产、动作、机位、连续性、首帧、参考图等可验证信息。
- `标准化机器语言` 是编译层：由系统把导演分镜语言和结构事实编译成模型更容易执行的标准描述。
- `多模型导出` 是交付层：同一机器语言可导出为 MiniMax H3 WebUI、通用视频 WebUI、Markdown、CSV、API JSON 等。
- `API 提交` 是可选生成动作：必须由 Generation Adapter 和任务中心承接，不属于 Prompt Compiler 本身职责。
