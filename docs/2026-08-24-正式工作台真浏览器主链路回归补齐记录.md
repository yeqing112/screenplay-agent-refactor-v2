# 2026-08-24 正式工作台真浏览器主链路回归补齐记录

## 背景

上一轮手工真浏览器测试已经验证：正式工作台可以从项目列表进入，并完成改编方向、镜头验收、QA 修复、脚本回滚、创作画布和模型管理等主链路操作。

但固定自动化回归 `npm run e2e:business` 中，仍有一部分关键动作由 API 直接代替 UI 操作，尤其是：

- 改编方向锁定
- Production Skill 锁定
- QA 修复 diff 预览
- 应用修复
- 回滚脚本版本

这会导致“接口可用但真实用户点不通”的问题无法被固定回归及时发现。

## 本轮补齐内容

### 1. 改编方向与 Production Skill 改为真实 UI 操作

`scripts/e2e-formal-workspace-business-flow.js` 现在会：

1. 进入「改编方向」。
2. 点击第一个候选方向「竖屏情绪悬疑短剧」。
3. 点击「锁定 Production Skill」。
4. 点击「锁定为主方向」。
5. 读取 `/api/books/{book_id}/adaptation-state` 和 `/api/books/{book_id}/production-skill-state`，确认真实落库。

### 2. QA 修复改为真实 UI 操作

脚本现在会：

1. 进入「QA 修复」。
2. 在「修复后片段」文本框中填写人工修复片段。
3. 点击「预览 diff」。
4. 确认 UI 中出现 `修复 Diff` 和修复后的证据文本。
5. 点击「应用修复并复检」。
6. 确认脚本文本真实更新，并生成 `semi_auto_fix` 版本。
7. 点击「回滚到修复前」。
8. 点击「确认回滚并复检」。
9. 确认脚本文本恢复原文，并生成 `rollback` 版本。

### 3. 创作画布与模型管理纳入主链路断言

固定回归新增断言：

- 「创作画布」必须展示剧本、分镜、资产、图片、视频、QA 与交付图谱。
- 「模型管理」必须展示 `文本 / LLM`、`向量 / Embedding`、`图像 / Image`、`视频 / Video` 默认模型链路。

### 4. 修复回滚版本乱码

真浏览器测试暴露：QA 脚本回滚版本标题出现 `鍥炴粴鍒?` 乱码。

本轮已修复后端 label：

- 修复前：`v3 鍥炴粴鍒?v2 ...`
- 修复后：`v3 回滚到 v2 ...`

并增加断言：

- 后端专项测试必须包含 `回滚到`。
- 后端专项测试与真浏览器 E2E 都不得出现 `鍥炴粴`。

## 验证结果

- `python -m unittest tests.test_qa_workbench_flow.QAWorkbenchFlowTests.test_rollback_restores_previous_script`：通过
- `node --check scripts/e2e-formal-workspace-business-flow.js`：通过
- `npm run e2e:business`：通过

## 当前结论

`npm run e2e:business` 已从“最小业务闭环”升级为“正式工作台真浏览器主链路回归”。它不只验证页面可渲染，而是验证真实用户路径中的核心状态写入、版本生成、回滚恢复和跨模块可见性。

后续正式工作台大改后，应优先运行该回归，再补跑 smoke、QA 专项或更细模块测试。
