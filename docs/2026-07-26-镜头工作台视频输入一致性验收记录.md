# 2026-07-26 镜头工作台视频输入一致性验收记录

## 本轮目标

沿《产品重构蓝图》和《产品重构阶段任务与验收标准》继续推进镜头工作台生产链路，补齐一个容易误伤生产判断的运行态一致性问题：

- 页面上已经能看到“结构化绑定参考图”和“当前编译实际使用参考图”的差异
- 但视频生成请求仍直接提交结构化 `referenceAssetIds`
- 这会导致：
  - 用户看到的输入摘要
  - 当前提示词实际编译上下文
  - 发给后端的视频任务输入
  三者不完全一致

这与蓝图中“输入可追溯、任务可恢复、页面语义与真实提交一致”的要求不符。

## 本轮改动

### 1. 抽离统一参考图载荷解析

新增文件：

- [productWorkspaceStoryboardReferencePayload.ts](D:\Work\Project\screenplay-agent-refactor-v2\web\src\components\productWorkspaceStoryboardReferencePayload.ts)

新增统一能力：

- `collectStructuredReferenceAssetIds(...)`
- `collectCompiledReferenceAssetIds(...)`
- `resolveEffectiveReferenceAssetIds(...)`

统一规则：

1. 如果当前镜头的 `prompt_compile_context` 已沉淀 `compiled_reference_asset_ids`，则视频生成优先沿用这套“编译时实际使用”的参考图
2. 如果没有显式 `compiled_reference_asset_ids`，则回退到 `asset_bindings` 中可用的参考图引用
3. 如果编译上下文仍没有可用参考图，再回退到结构化 `reference_images`

这样可以保证：

- 当前提示词
- 当前视频输入
- 当前任务中心记录

尽量使用同一份参考图语义。

### 2. 单镜头视频生成改为使用有效参考图载荷

修改文件：

- [ProductWorkspaceStoryboardSection.tsx](D:\Work\Project\screenplay-agent-refactor-v2\web\src\components\ProductWorkspaceStoryboardSection.tsx)

调整内容：

- 镜头工作台本地推导 `effectiveReferenceAssetIds`
- `generate-video` 请求改为提交 `effectiveReferenceAssetIds`
- `predictedVideoTaskMode` 也改为基于实际将提交的参考图集合计算

### 3. 批量视频生成改为复用同一规则

修改文件：

- [productWorkspaceBatchActions.ts](D:\Work\Project\screenplay-agent-refactor-v2\web\src\components\productWorkspaceBatchActions.ts)

调整内容：

- `getShotReferenceAssetIds(...)` 改为复用 `resolveEffectiveReferenceAssetIds(...)`
- 批量视频生成与单镜头视频生成保持同一参考图选择逻辑

### 4. 镜头工作台补充用户可见摘要

镜头工作台“本次视频输入摘要”中新增：

- `本次视频实际提交：...`
- 当前输入来源说明：
  - 优先沿用已编译版本实际使用的参考图
  - 或直接使用结构化绑定里的参考图

同时把原有漂移提示改得更明确：

- 如果结构化绑定与编译载荷不一致，本次仍优先沿用编译载荷
- 如果用户要切换到最新绑定，应先重编提示词

## 当前剩余问题

虽然“视频输入一致性”已经收口，但距离生产级还有两项应继续推进：

1. 镜头工作台还应继续显式展示：
   - 当前视频任务会使用哪一版运动提示词
   - 当前负向提示词是否来自最新编译版本

2. 当结构化绑定与编译载荷漂移时，除了提示用户先重编之外，还可以进一步提供：
   - 一键重编入口
   - 重编后再生成视频的连续动作
