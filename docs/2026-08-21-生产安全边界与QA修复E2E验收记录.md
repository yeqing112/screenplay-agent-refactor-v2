# 2026-08-21 生产安全边界与 QA 修复 E2E 验收记录

## 背景

全面复盘后，项目当前最值得优先推进的不是继续新增创作功能，而是补齐生产级边界与高风险写入链路验证。

本轮目标：

1. 收紧 API CORS 默认配置。
2. 加固上传接口，避免路径穿越、任意扩展名与无限制大文件。
3. 增加健康检查端点。
4. 将 QA 修复的真实写入链路纳入 E2E。

## 改动

### API 安全边界

- 新增 `/health`。
- CORS 默认允许本地前端端口：
  - `http://127.0.0.1:5173`
  - `http://localhost:5173`
  - `http://127.0.0.1:5175`
  - `http://localhost:5175`
- 支持通过环境变量覆盖：
  - `API_CORS_ORIGINS`
  - `API_CORS_ALLOW_CREDENTIALS`

### 上传安全

- `/api/upload` 改为：
  - 清洗上传文件名。
  - 仅按安全 basename 落盘。
  - 校验落盘路径仍在上传目录内。
  - 拒绝空文件。
  - 拒绝超过 `UPLOAD_MAX_BYTES` 的文件。
  - 默认仅允许 `.txt / .md / .markdown`。
- 支持通过环境变量覆盖：
  - `UPLOAD_DIR`
  - `UPLOAD_MAX_BYTES`
  - `UPLOAD_ALLOWED_EXTENSIONS`

### QA 修复 E2E

- 新增 `npm run e2e:qa`。
- E2E 会自动创建临时项目 `#999901`，打开正式工作台 QA 修复页，并执行：
  1. 同步 QA issue。
  2. 预览修复 diff。
  3. 应用修复，生成剧本版本。
  4. 回滚修复版本。
  5. 清理临时项目数据。

### E2E 稳定性

- `e2e:smoke` 与 `e2e:qa` 启动 Vite 时增加 `--strictPort`。
- 端口被占用时直接失败，避免误连到漂移端口造成假阳性。

## 当前边界

- 本轮没有实现认证/授权；CORS 不是权限系统，只是浏览器来源边界。
- 后台任务状态仍主要依赖内存 dict，服务重启后任务查询不可恢复。
- 上传安全已覆盖文件名、类型和大小，但还没有做内容级恶意文本扫描。

## 后续建议

1. 新增持久化任务表，承接 `_pipeline_tasks / _storyboard_tasks / _creative_tasks`。
2. 增加最小 API key guard 或本地 token guard，作为生产前权限底线。
3. 扩展内容准备 E2E，覆盖“上传 -> 导入 -> 章节懒加载 -> 状态恢复”。
