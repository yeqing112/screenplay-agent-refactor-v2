# 场景资产四层语义拆分实施记录

## 决策

场景资产不再把空间本体、临时状态、摄影风格和设定板排版视为同一类事实。编译器采用四层语义：

1. `SceneCanonical`：可复用的空间身份、建筑结构、固定设施、空间关系和时代事实。
2. `SceneState`：本次时间、天气、灯具开关、地面状态、临时道具等可变状态。
3. `SceneLook`：色彩、曝光、对比度、摄影氛围和光线策略。
4. `SceneBoardSpec`：16:9、2×2 视图槽位、是否允许人物/文字等资产图呈现规范。

旧字段继续保留为审计和兼容来源；显式四层字段存在时优先使用显式值，不自动改写旧资产或已锁定参考图。

## 已实施

- `VisualLocation` 增加 `canonical_facts`、`state_variants`、`look_profile`、`board_spec` JSON 字段及 Alembic 迁移 `h1b2c3d4e5f6`。
- API 和分镜 Prompt Compiler 增加四层语义解析，保留旧 `canonical_prompt_profile` 字段以兼容既有诊断和版本。
- 场景参考图默认使用中性空间基准合同；只有显式状态/Look 存在时才叠加本次状态与风格。
- 增加 `SceneAssetPromptLinter` 等价的确定性诊断：状态写入场景本体、Look 写入场景本体、缺失空间事实、设定板槽位不足分别给出可解释结果；只有缺失空间事实阻断。
- 资产中心展示场景提示词检查结果，提醒用户哪些内容不应永久写入场景本体。
- 资产中心增加四层语义可视化编辑器：普通用户可分别编辑场景本体、状态、Look 与四视图槽位；保存通过既有 PATCH 契约完成，并保留未知字段。
- 场景参考图生成支持显式选择 `combined`、`canonical`、`state`、`look` 四种渲染模式；服务端在队列边界重新渲染所选层，避免旧浏览器提示词绕过语义分层。
- 道具资产增加 `PropCanonical / PropState / PropLook` 字段、迁移和资产中心编辑器，并复用同一组按层生成模式。
- 场景名不做强制改名，避免破坏已有引用；建议新资产使用中性场景名，雨夜等内容建立状态变体。

## 迁移与使用规则

- 旧资产不自动迁移；先在资产中心编辑四层字段，再重新生成参考图并人工审核锁定。
- 既有“雨夜旧公寓门厅”参考图可保留为 Look/State 参考，不作为中性空间基准图。
- 第四视图默认解释为 `spatial_verification_wide`；材质特写应作为独立细节资产，不挤占空间校验视角。
- 资产原始提示词始终保留，四层结构只作为编译输入和可解释诊断，不覆盖导演原文。
