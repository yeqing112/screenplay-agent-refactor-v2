# 分镜生成质量治理与可拍性校验方案

日期：2026-08-29  
状态：已纳入蓝图与生产级任务计划  
适用范围：正式工作台的剧本转分镜、导演分镜语言、Prompt Compiler、分镜图/视频生成

## 1. 背景

当前镜头 3 暴露出一个典型问题：镜头文本同时包含支付、取物、递物、情绪反应等多个动作，但镜头时长只有 4 秒。文本可能完整，提示词也可能通过字段审计，但实际拍摄和视频生成并不一定可执行。

因此，分镜质量不能只按“提示词是否足够长、是否提到资产”判断，还必须判断：镜头意图是否单一、动作是否能在时长内完成、起止状态是否连续、镜头是否具备可生成性。

## 2. 目标

将分镜生成从一次性文本写作升级为：

```text
镜头意图 → 时长与动作节拍 → 导演分镜语言 → 可拍性校验 → 自动修订/拆镜建议 → Prompt IR → 多模型机器提示词
```

导演分镜语言仍然保留创作表达，并允许用户编辑；可拍性校验和机器提示词编译属于系统生产层，不替代导演语言。

## 3. 分阶段职责

### 3.1 Shot Intent Planner

先确定镜头的唯一戏剧任务：

- 本镜头要让观众看到什么；
- 本镜头结束时发生什么信息或情绪变化；
- 本镜头的唯一核心动作是什么；
- 哪些动作属于上一镜或下一镜，不应强行塞入本镜头。

### 3.2 Action Timing Planner

把动作拆成带时间区间的节拍：

```json
{
  "duration": 6,
  "action_beats": [
    {"start": 0.0, "end": 1.2, "action": "手进入画面"},
    {"start": 1.2, "end": 3.8, "action": "取出折叠旧照片"},
    {"start": 3.8, "end": 5.2, "action": "将照片推到对方身前"},
    {"start": 5.2, "end": 6.0, "action": "对方视线落到照片上"}
  ]
}
```

初始约束：

- 4 秒：建议最多 2～3 个动作；
- 5～6 秒：建议最多 3～4 个动作；
- 7 秒以上：才允许完整动作链与较充分情绪反应。

### 3.3 Director Shot Language

输出自然、可编辑的导演语言，不直接输出机器字段清单。例如：

```text
特写。男人的手从画外伸入，把一张折叠旧照片推到林小夏面前。她没有立即拿起，只是盯着照片，收银台上方的冷白灯把照片折痕照得很清楚。
```

### 3.4 Shot Executability Validator

生成后执行确定性审查，至少检查：

- 动作数量与时长是否匹配；
- 是否存在多个并行核心动作；
- 是否发生跨空间、跨机位或无法在单镜头完成的变化；
- 是否承接上一镜结束状态；
- 是否形成可交给下一镜的结束状态；
- 镜头运动、构图和动作是否互相冲突；
- 道具是否在当前镜头真正被使用；
- 是否出现无依据新增人物、道具或状态。

### 3.5 自动修订与拆镜建议

当镜头过载时，系统不只返回“提示词有问题”，而是给出可执行方案：

- 延长镜头：例如 4 秒调整为 6 秒；
- 保持时长：删除非核心动作；
- 拆分镜头：把动作链拆为两个连续镜头；
- 由用户确认后，才写入正式 Shot Schema。

## 4. 建议数据结构

在 Shot Schema / Prompt IR 中增加或固化：

- `shot_intent`：镜头意图；
- `core_action`：唯一核心动作；
- `action_beats[]`：动作节拍及时间区间；
- `continuity_in`：入镜承接状态；
- `continuity_out`：出镜结束状态；
- `executability_status`：`pass / warning / blocked`；
- `executability_findings[]`：可拍性问题；
- `split_shot_suggestions[]`：拆镜候选；
- `recommended_duration`：建议时长；
- `duration_override_reason`：人工覆盖理由。

## 5. 当前镜头 3 的处理建议

当前镜头包含支付、取照片、递照片、收手和反应等多个动作。

- 推荐方案：6 秒，保留完整动作链；
- 4 秒方案：删除支付，只保留取照片、推到面前、视线落点；
- 最理想方案：拆成两个镜头，让支付承担节奏，照片揭示承担悬疑信息。

## 6. 验收标准

- 至少 30 个真实镜头完成动作节拍计算；
- 4 秒镜头不再默认塞入 5 个以上连续动作；
- 每个镜头都有唯一 `core_action`；
- 生成前可以看到时长来源、动作节拍和可拍性状态；
- 对过载镜头能输出延长、删减、拆镜三类建议；
- 导演语言、结构化 Prompt IR、机器提示词和 API 提交保持四层分离；
- 不通过可拍性校验的镜头不能直接进入真实视频提交，除非用户显式确认覆盖。

## 7. 实施优先级

1. 先落 `core_action`、`action_beats` 和时长承载规则；
2. 再实现 `Shot Executability Validator`；
3. 再接入自动修订和拆镜建议；
4. 最后将结果接入正式工作台、批量治理和真实 LLM clone-only 灰度。
