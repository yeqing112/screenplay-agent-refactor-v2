# 2026-08-26 五项目分镜提示词批量治理验收记录

## 背景

2026-08-25 已完成 `book 75 / 深夜便利店` 14 镜提示词生产治理，后审计达到 `0 error / 0 warning`。本轮目标是把同一套“审计 -> clone 验证 -> dry-run preflight -> confirmation token -> protected deterministic apply -> 后审计”的门禁扩展到其他真实项目，优先治理错误数量最高的 `book 5`，随后处理 `book 3` 与 `book 1` 的剩余短 prompt 与内部残留问题。

## 本轮实现

1. 扩展 `core/model_adapter.py` 的机器提示词清洗层：
   - 将导演分镜语言中的 `画面切到`、`画面切出`、`镜头切到`、`镜头切出` 编译为连续镜头运动语言。
   - 将 `说出对白`、`念出对白`、`对白`、`台词` 编译为可观察的口型/动作描述。
   - 过滤 `legacy-*-fallback` 这类内部资产兼容标记，避免泄漏到机器提示词。

2. 补充 `tests/test_model_adapter.py`：
   - 验证剪辑口令不会进入机器运动提示词。
   - 验证对白/台词标记会被编译为视觉动作。
   - 验证 legacy fallback 内部标记不会进入静态提示词。

3. 完成真实项目受保护 apply：
   - `book 5 / 神农架历险记` 20 镜：
     - clone 验证：`40 errors -> 0`，`1 warning -> 1`
     - preflight：`40 errors -> 0`，real apply blockers = 0
     - protected deterministic apply：`40 errors -> 0`
     - 后审计：`0 error / 1 warning`
   - `book 3 / 金丝雀` + `book 1 / 苗疆道事` 第一批 10 镜：
     - preflight：`25 errors -> 0`，`30 warnings -> 6`
     - protected deterministic apply：`25 errors -> 0`，`30 warnings -> 1`
   - `book 3 / 金丝雀` + `book 1 / 苗疆道事` 第二批 20 镜：
     - preflight：`32 errors -> 0`，`59 warnings -> 10`
     - protected deterministic apply：`32 errors -> 0`，`59 warnings -> 0`
   - `book 14 / 三个和尚` warning 压降：
     - 新增 `BATCH_REPAIR_INCLUDE_WARNINGS=1` 与 `BATCH_REPAIR_WARNING_CODES`，允许显式治理 warning-only 样本，默认 error-only 行为不变。
     - 新增 `BATCH_REPAIR_TARGETS=book_id:episode:shot_id`，用于精确预检单镜头，避免被历史诊断排序误选。
     - 完成 30 镜场景名 warning 压降 apply、`book 3` 9 镜补充 apply、`book 14` 4 镜补充 apply、`book 14:1:23` 精确 apply。
     - 同步扩展审计脚本与 clone 预检脚本的合理无人物镜头识别，排除乱葬岗、铜钟、第一人称下坠、鱼鳞特写等场景/物件/主观镜头误报。
   - 新增固定门禁：
     - `npm run audit:storyboard:zero-error-gate`
     - 默认覆盖五项目最多 200 镜，要求至少审到 100 镜，strict error 失败。
   - 新增本地生产回归总入口：
     - `npm run check:production`
     - 串联提示词/编译相关 Python 单测、前端生产 build 与五项目 zero-error gate。

## 当前判断

五个真实项目的分镜提示词 hard error 与 warning 已清零，说明“导演分镜语言 -> Prompt IR / Rule Compiler -> Model Adapter -> 标准化机器语言”的确定性治理链路已经具备批量落地价值，并且已经具备固定回归门禁。

当前剩余工作不再是存量提示词质量问题，而是生产化运行问题：

1. 把 `npm run check:production` 作为发布前固定回归入口；待真实样本数据 fixture 化后再接入 CI。
2. 将受保护 apply 的成功路径沉淀到正式工作台/任务中心，减少命令行操作比例。
3. 推进真实 LLM / 真实模型灰度，保持 deterministic mode 作为低成本回归基线。
4. 继续完善完整导出历史中心与导演语言到结构事实变更建议。
