# 2026-07-25 改编方向服务端持久化与提示词重编译闭环验收记录

## 本轮目标

把长期停留在前端本地状态的 `改编方向锁定` 收敛为服务端真状态，并验证它对下游门禁与提示词重编译的真实影响。

本轮重点验证三件事：

1. 改编方向锁定不再只依赖浏览器 `localStorage`
2. 页面刷新后，锁定状态仍能从服务端恢复
3. 锁定后，镜头工作台不再被“未锁定改编方向”阻塞，提示词可重新编译并写回新版本

## 本轮实现

### 1. 服务端新增改编方向状态接口

- 文件：`api/server.py`
- 新增：
  - `GET /api/books/{book_id}/adaptation-state`
  - `PUT /api/books/{book_id}/adaptation-state`
- 持久化方式：
  - 复用现有 `KV` 存储
  - key：`product_workspace:adaptation:{book_id}`
- 结构化保存字段：
  - `selected_id`
  - `selected_name`
  - `custom_note`
  - `locked_at`
  - `updated_at`
  - `created_at`

### 2. 前端改为“服务端优先，本地兜底”

- 文件：`web/src/components/productWorkspaceUpstreamController.ts`
- 行为调整：
  - 进入项目时，优先从服务端读取改编方向状态
  - 如果服务端还没有数据，但浏览器本地有旧状态，则自动迁移到服务端
  - 状态变更后，同时写本地缓存与服务端
- 保留本地缓存的目的：
  - 兼容旧数据
  - 在网络失败时保留最小可用体验

## 当前仍需继续优化

### 1. 提示词重编译耗时过长

当前一次同步重编译约 `48 秒`，这会带来两类产品风险：

1. 用户误以为按钮无响应
2. 页面级短等待验收不容易直接看到成功反馈

建议下一步把提示词重编译升级为：

- 后台任务化
- 接回任务中心
- 页面显示明确的编译中 / 已完成 / 失败状态

### 2. 继续补“真页面可感知的成功反馈”

虽然服务端版本已成功写回，但在长耗时场景下，页面上的成功提示不一定总能在短时间验收里直接截到。

建议下一步：

- 给重编译动作增加更明显的持续状态条
- 在版本历史顶部显示“刚刚生成的新版本”
- 编译完成后自动滚动或高亮最新版本
