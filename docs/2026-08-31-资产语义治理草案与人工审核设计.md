# 资产语义治理草案与人工审核设计

## 目标

把“人物字段串位”和“场景资产混入镜头叙事”从人工排错，升级为系统主动提出的结构化修复草案。人工只审核、编辑或拒绝草案。

## 通用流程

```text
资产原始字段 + 权威提示词 + 关联镜头 → 语义归属编译 → 修复草案
→ 差异预览/影响镜头 → 人工编辑或确认 → 原子写入 + 重编译计划 + 回滚锚点
```

## 草案数据结构

```json
{
  "kind": "asset_semantic_normalization",
  "source_snapshot": {"asset_id": "...", "fields": {}},
  "proposed_fields": {},
  "field_moves": [
    {"source_field": "hair_style", "target_field": "refined_outfit", "text": "...", "confidence": 0.0}
  ],
  "shot_layer_extractions": [
    {"source_field": "lighting_mood", "target": "shot_lighting", "text": "...", "candidate_shot_ids": []}
  ],
  "rationale": [],
  "affected_shots": [],
  "requires_confirmation": true
}
```

## 规则边界

- 由模型根据字段语义与完整上下文分类，不用关键词直接删除或重写。
- 草案默认只读；确认前不修改资产、参考图、导演分镜或已生成媒体。
- 确认写入需绑定草案指纹，并为资产原状态与受影响镜头创建回滚锚点。
- 迁入镜头层的内容生成待重编译计划，不自动调用外部模型，也不自动生成图片/视频。

## 2026-08-31 落地状态

已完成第一版通用闭环：

- `POST /api/books/{book_id}/visual-assets/{asset_type}/{asset_id}/semantic-governance-drafts`：只读调用结构化 LLM，输入完整可写字段、权威提示词和**已声明的结构化镜头绑定**；不会调用图片或视频模型。
- 草案会持久化到 `asset_semantic_governance_records`，包含来源快照、提案与指纹；不以资产名、镜头号或关键词推断关联关系。
- `.../confirm` 必须同时传入 `confirmed=true` 与 `allow_write=true`。确认前会复核来源快照；资产已被其他编辑改动则草案作废，不能覆盖新状态。
- 写入时会为每个受影响镜头建立状态快照回滚锚点，标记 `recompile_required`，仅创建待重编译计划，不会自动调用 LLM、生图或生视频。
