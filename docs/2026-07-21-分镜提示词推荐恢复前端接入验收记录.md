# 2026-07-21 分镜提示词推荐恢复前端接入验收记录

## 本次目标

把后端已经完成的分镜提示词健康审计能力正式接入新版镜头工作台，让真实用户在页面上能够直接看到：

1. 当前提示词版本是否疑似跑偏
2. 跑偏的具体原因
3. 系统推荐恢复到哪个历史版本
4. 是否可以一键执行推荐恢复

## 本次实现

### 1. 前端数据模型补齐

文件：

- `web/src/prototyping/sceneComposerData.ts`

新增 `StoryboardShotOutput` 字段：

- `prompt_version_audit`
- `recommended_restore_version`

这样 `/api/pipeline/book/{book_id}/outputs` 返回的版本健康信息可以直接进入正式工作台数据流，不再丢失在接口层。

### 2. 镜头工作台增加版本跑偏提示

文件：

- `web/src/components/ProductWorkspaceStoryboardSection.tsx`

新增内容：

- 当 `prompt_version_audit.is_degraded_version = true` 时，在“编译诊断”区域展示显式告警卡
- 展示：
  - 缺失关键资产数量
  - 可恢复版本数量
  - 是否存在 scene-only 退化风险
  - 缺失的关键资产名称摘要

这解决了此前“后端知道有问题，但前端工作台没有显式告诉用户”的断层。

### 3. 接入推荐恢复动作

文件：

- `web/src/components/ProductWorkspaceStoryboardSection.tsx`

新增动作：

- `rollbackRecommendedPromptVersion()`

调用接口：

- `POST /api/books/{book_id}/storyboard/{episode}/{shot_id}/prompt-versions/recommended-rollback`

行为：

- 点击“恢复推荐版本 vX”
- 成功后自动：
  - 刷新镜头详情
  - 刷新提示词历史版本
  - 给出恢复成功提示

### 4. 历史版本区域补充恢复建议语义

文件：

- `web/src/components/ProductWorkspaceStoryboardSection.tsx`

补充内容：

- 若某个历史版本正好是 `recommended_restore_version`，会显示“系统建议优先恢复到这个版本”
- 若某个历史版本自身也是退化版本，会显示“该历史版本也存在退化风险”

这样用户不需要自己肉眼比较一长串版本文本，能更快做出恢复决策。

## 验收标准

### A. 页面可见性

满足以下条件时视为通过：

1. 分镜详情页能显示当前提示词版本是否疑似跑偏
2. 能显示缺失关键资产摘要
3. 能显示推荐恢复版本号
4. 能显示推荐恢复原因

### B. 交互闭环

满足以下条件时视为通过：

1. 页面存在“恢复推荐版本”按钮
2. 按钮调用的是推荐恢复专用接口，不是手工版本号拼接
3. 恢复成功后会刷新当前镜头详情与历史版本列表
4. 页面会给出成功或失败反馈

### C. 历史版本辅助判断

满足以下条件时视为通过：

1. 推荐版本在历史版本列表中有明确标识
2. 退化历史版本会被标记为风险版本
3. 用户无需额外打开开发者工具即可完成恢复判断

## 当前价值

这次不是继续堆后端规则，而是把“版本跑偏诊断”和“推荐恢复”真正变成用户可操作的工作台能力。

直接收益：

1. 分镜提示词跑偏不再只能靠人工读长提示词发现
2. 版本恢复从“知道可以做”变成“页面里直接做”
3. 正式工作台开始具备生产态自救能力，而不是纯展示态
