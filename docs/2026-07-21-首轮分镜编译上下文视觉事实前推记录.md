# 2026-07-21 首轮分镜编译上下文视觉事实前推记录

## 本轮目标

把“修复阶段才会拿到的结构化修复目标”前推到首轮分镜编译上下文，让首轮提示词编译也能直接看到：

1. 每个绑定资产至少该继承哪些视觉事实
2. 哪些绑定资产必须保留在 `used_assets`
3. 旧的 prompt compile context 在读取时也能自动刷新到这套新结构

## 本轮实现

### 1. 首轮编译上下文新增结构化约束

文件：

- `api/server.py`

新增能力：

- `_extract_compile_required_facts(...)`
- `_build_compile_visual_fact_targets(...)`
- `_build_compile_required_used_assets(...)`
- `_build_compile_prompt_contract(...)`

现在 `prompt_compile_context_v2` 会额外产出：

- `compile_prompt_contract`
- `visual_fact_targets`
- `required_used_assets`

其中：

- `visual_fact_targets` 会按人物 / 场景 / 道具提炼当前镜头最该继承的视觉事实
- `required_used_assets` 会把有参考图的关键绑定资产整理成一份正式清单
- `compile_prompt_contract.summary_lines` 会生成更接近“编译任务单”的摘要语句，帮助首轮 LLM 编译直接对准关键继承点

### 2. 旧上下文自动刷新

文件：

- `api/server.py`

更新：

- `_prompt_compile_context_needs_refresh(...)`

现在只要旧 `prompt_compile_context` 里缺少：

- `compile_prompt_contract`
- `visual_fact_targets`
- `required_used_assets`

系统就会自动判定需要刷新，而不是继续沿用老上下文。

### 3. 测试增强

文件：

- `tests/test_storyboard_prompt_authority_context.py`
- `tests/test_storyboard_prompt_context_legacy_refresh.py`

新增验证：

1. 首轮 `context` 中确实存在 `compile_prompt_contract / visual_fact_targets / required_used_assets`
2. 旧版上下文经接口读取后，会自动刷新出这批新字段
3. 人物 / 场景 / 高重要度道具都能进入视觉事实目标或关键使用约束中

## 本轮结论

这轮不是直接改提示词文案，而是把首轮编译输入变得更接近生产可控状态：

1. LLM 首轮编译不再只看到松散权威字段，还能看到“必须继承什么”的结构化目标
2. 老镜头历史上下文不会因为字段落后而永远停留在旧诊断语义里
3. 后续若还出现 `authority_prompt_inheritance`，就更能说明是真实提示词质量问题，而不是输入上下文不够硬
