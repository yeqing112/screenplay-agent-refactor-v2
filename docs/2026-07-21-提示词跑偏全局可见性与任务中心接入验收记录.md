# 2026-07-21 提示词跑偏全局可见性与任务中心接入验收记录

## 本次目标

在已经完成“分镜详情页提示词跑偏诊断 + 推荐恢复版本”之后，继续把这套能力推进到更靠前的工作台入口：

1. 镜头列表直接标记提示词跑偏镜头
2. `buildShotReadiness` 识别“缺提示词”和“提示词已跑偏待恢复”的区别
3. 任务中心把提示词跑偏作为正式任务信号展示出来
4. 任务中心详情可直接看到跑偏镜头与推荐恢复摘要

## 本次实现

### 1. 镜头 readiness 增加恢复态

文件：

- `web/src/components/productWorkspaceStoryboard.ts`

新增：

- `hasDegradedPromptVersion(shot)`

调整：

- 当镜头存在 `prompt_version_audit.is_degraded_version = true` 时
  - `buildShotReadiness(...)` 不再把它当成普通“已完成提示词”
  - 而是返回“待恢复”状态
  - 若存在 `recommended_restore_version`，下一步动作直接指向恢复版本

这解决了此前镜头虽然已经有静态/运动提示词，但实际上 prompt 已跑偏，列表侧却仍像“正常完成”的问题。

### 2. 镜头列表直接显示“提示词跑偏”

文件：

- `web/src/components/ProductWorkspaceStoryboardSection.tsx`

调整：

- 在镜头列表卡片上增加 `提示词跑偏` 标签
- `readiness.statusLabel` 在该场景下会显示为恢复态，而不是普通完成态

这样用户不需要先点进镜头详情，列表层就能看到风险镜头。

### 3. 任务中心正式接入提示词健康信号

文件：

- `web/src/components/productWorkspaceTasks.ts`

本次对该文件做了清理式重建，恢复为稳定可编译版本，并补入：

- `TaskCenterEntry.promptHealth`
- `buildPromptHealthSummary(...)`

接入点：

- `buildStoryboardTaskEntry(...)`
  - 当某一集已有镜头，但其中存在跑偏 prompt 时
  - 该集的分镜任务状态直接转为 `error`
  - 并附带：
    - 跑偏镜头数
    - 推荐恢复版本数
    - 具体镜头摘要

- `buildBatchPromptTaskEntry(...)`
  - 当全项目存在跑偏 prompt 时
  - 批量提示词任务不再只是“继续编译”
  - 而是转成“优先恢复提示词版本”

这让任务中心开始真正承担“提示词恢复调度”的职责，而不是只负责补缺失提示词。

### 4. 任务中心列表与详情补充恢复摘要

文件：

- `web/src/components/productWorkspaceTaskCenterListPanel.tsx`
- `web/src/components/productWorkspaceTaskCenterSelectedTaskPanel.tsx`

新增效果：

- 列表卡片可显示：
  - `跑偏镜头 N`
  - `可恢复 M`

- 详情面板可显示：
  - 哪些镜头跑偏
  - 当前 prompt 版本号
  - 是否是 scene-only 风险
  - 建议恢复到哪个版本

## 验收标准

### A. 镜头列表

满足以下条件视为通过：

1. 存在跑偏 prompt 的镜头，在列表中直接显示“提示词跑偏”

3. 列表中的下一步动作能体现恢复导向

2. 批量提示词任务可识别全项目 prompt 跑偏
3. 任务列表可显示跑偏镜头数与可恢复数量
4. 任务详情可查看具体跑偏镜头摘要

1. 前端相关测试通过
