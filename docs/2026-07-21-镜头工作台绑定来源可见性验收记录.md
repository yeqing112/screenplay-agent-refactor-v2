# 2026-07-21 镜头工作台绑定来源可见性验收记录

## 验收目标

确认正式工作台中的镜头工作台，已经把分镜编译所依赖的资产绑定来源明确展示给用户，而不是只在原始编译 JSON 中隐含存在。

本轮重点验收：

1. 人物 / 场景 / 道具绑定卡片是否展示 `绑定来源`
2. `绑定来源` 是否能区分正式结构化绑定与回退/待确认链路
3. 页面是否仍能结合真实项目数据显示引用 token、参考来源、参考状态与权威源摘要

## 本轮变更

- 为镜头绑定摘要补充 `bindingSourceLabel` 与 `bindingSourceDetail`
- 人物绑定来源支持区分：
  - `正式结构化绑定`
  - `编译期变体命中`
  - `基础定妆回退`
  - `旧链路回填`
  - `待确认绑定`
- 场景 / 道具绑定来源支持区分：
  - `正式结构化绑定`
  - `参考图回填`
  - `待确认绑定`
- 镜头工作台绑定卡片新增可视化字段：
  - `绑定来源`
  - 来源说明文案

## 验收结论

本轮通过。

镜头工作台已经从“只有编译结果，没有绑定来路说明”推进到“用户可直接看到绑定来源及其语义”的状态，满足蓝图里“提示词编译与资产引用必须可追溯”的要求。

## 当前剩余问题

真浏览器同时暴露出下一阶段仍需继续推进的生产问题：

1. `authority_prompt_inheritance` 仍在告警  
   当前静态提示词对场景、人物、道具的权威原文继承还不够稳定。
2. `critical_bound_asset_usage` 仍在告警  
   像 `木桶` 这样的关键绑定资产，虽然已经正式绑定，但仍可能掉出本次编译的 `used_assets`。
3. 这说明“绑定来源可见”已经成立，但“编译结果是否真正忠实继承绑定资产”还未完全收口。

## 下一步

下一轮应继续按蓝图推进以下问题：

1. 收紧关键绑定资产进入 `used_assets` 的门禁与自动修复链路
2. 提升静态提示词对权威原文的继承强度，减少只有名字引用、没有关键信息继承的情况
3. 把“绑定来源成立”继续推进到“提示词内容质量也与绑定来源一致”
