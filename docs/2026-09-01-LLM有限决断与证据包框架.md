# LLM 有限决断与证据包框架

> 状态：分镜领域的证据包与受控 LLM 草案调用已落地；后续按领域逐步接入。  
> 核心原则：LLM 可以基于充分证据提出判断与修复草案，但不能把推断伪装成事实，也不能绕过人工确认执行高影响操作。

## 1. 统一链路

```text
事实收集 → 证据分级 / 冲突检测 → 决断任务包
→ LLM 结构化判断与修复草案 → 规则校验
→ 人工审核、编辑、确认 → 版本化写入 / 回滚
```

所有领域使用同一返回结构：

```json
{
  "decision": "pass | warning | blocked | needs_information",
  "confidence": 0.0,
  "evidence": [{"id": "...", "tier": "locked_fact", "summary": "..."}],
  "unknowns": ["..."],
  "conflicts": ["..."],
  "proposals": [{"operation": "...", "before": {}, "after": {}, "rationale": "..."}],
  "human_confirmation_required": true
}
```

`confidence` 只描述“现有证据足以支持该判断”的程度，不是事实真实性声明；存在关键缺失或冲突时必须返回 `needs_information` 或 `blocked`。

## 2. 证据分级

| 级别 | 含义 | LLM 可以如何使用 |
|---|---|---|
| `locked_fact` | 人工锁定资产、确认版本、验收通过结果 | 可作为不可改写的约束 |
| `approved_fact` | 已人工确认但允许后续修订的内容 | 可作为默认事实，冲突时提示人工 |
| `source_text` | 原始剧本、导演分镜语言、用户编辑内容 | 可解释、可建议修改，不可静默覆盖 |
| `derived_fact` | Prompt IR、节拍、绑定、模型导出 | 必须带来源版本与生成规则 |
| `model_observation` | 图像/视频/文本模型的分析结果 | 仅作为建议证据，不能独立触发写入 |
| `unknown` | 缺失、不可访问或互相矛盾的信息 | 必须显式列出，不能脑补 |

优先级固定为：`locked_fact > approved_fact > source_text > derived_fact > model_observation`。低级证据不能覆盖高级证据。

## 3. 决断任务包

每个 LLM 调用都应传入最小但足够的 `DecisionPacket`：

```text
task / scope / target_version
facts[] / context_window[] / constraints[]
history[] / evidence_quality / conflicts / allowed_operations
```

- `scope` 明确到书、集、场、镜头、资产或版本，禁止只靠名称猜范围。
- `context_window` 按任务取必要前后文：剧本取前后场与人物线；分镜取相邻镜头；连续性取两帧和锁定资产。
- `allowed_operations` 是白名单，例如“建议重写动作节拍”不等于“直接拆镜”。
- 敏感字段、密钥、无关全文和未授权媒体不进入包。

## 4. 各领域最小证据要求

| 领域 | 决断前必须具备 |
|---|---|
| 剧本 | 当前稿、相邻场次、人物关系/阶段、世界观约束、历史 QA 与人工决策 |
| 分镜 | 导演分镜、Shot IR、前后镜起止状态、时长/节拍、场景/人物/道具绑定、可拍性结果 |
| 资产 | 原始字段、已锁定参考图、资产被哪些镜头绑定、同类资产冲突、历史治理记录 |
| 提示词 | 导演语言、锁定事实、Prompt IR、目标模型能力、导出格式、历史验收反馈 |
| 成片验收 | 目标成片/帧、锁定参考帧或资产、连续性合约、验收标准、上次失败分类 |

缺任一关键项时，系统应优先补信息或创建“待审核信息缺口”，而非调用 LLM 给出强结论。

## 5. 权限边界

LLM 可做：分析、分类、提出证据、生成草案、建议修复、指出信息缺口。

LLM 不可直接做：覆盖原稿、锁定/解锁资产、确认验收、批量改写、提交付费模型、发布、删除或迁移存储。

写入统一要求：当前证据指纹 + 草案指纹 + `confirmed=true` + `allow_write=true`；写入后保留前版本快照、模型/提示词版本、决断包摘要和操作者信息。

## 6. 实施顺序

1. 建立通用 `DecisionPacket`、证据序列化、冲突检测和草案审计表。
2. 先接入文本风险最低的剧本 QA 与分镜可拍性：LLM 只产出草案，规则层校验。
3. 接入资产治理与 Prompt Compiler，复用锁定事实和版本来源。
4. 接入连续性验收：视觉模型观察作为 `model_observation`，人工确认才形成验收事实。

## 7. 当前落地边界（2026-09-01）

- 已提供通用 `DecisionPacketRecord` 审计记录、稳定证据指纹，以及分镜、剧本 QA、资产治理和单镜头 Prompt Compiler 的证据包生成接口；生成证据包不调用 LLM。
- 已提供只读的 LLM 决断提示词预览，以及显式 `confirmed=true + allowExternalCall=true` 才能执行的一次真实 LLM 草案调用。
- LLM 输出必须通过操作白名单、证据缺口和冲突校验；有未解决缺口/冲突时只能返回 `needs_information` 或 `blocked`。
- 调用结果只更新同一证据包的可审阅 `proposal` 与不含密钥的模型审计信息，不执行分镜、剧本、资产、提示词、生产任务或验收写入；同一包已生成草案时去重，避免重复计费。
- 对剧本 QA，`propose_script_revision` 可以携带一段“供人工编辑的替换片段”；用户仍须显式带入现有编辑器、查看 diff、确认版本化写入并复检，草案本身不能写入剧本。
- 资产治理与 Prompt Compiler 均采用独立的“预览/确认外部调用”路径；候选提示词可人工编辑，确认后才创建新的可回滚 Prompt Version，且不会连带触发生图或视频任务。
5. 再开放受保护的批量执行器；所有跨模型 API 调用保持独立确认。

## 7. 验收标准

- 任一决断可追溯到证据、版本和范围。
- 关键缺失会返回 `needs_information`，不会生成伪确定结论。
- 低等级观察不能改写锁定事实。
- 人工可编辑草案并确认，也可拒绝并保留原因。
- 同一证据包的确定性前置校验结果稳定；LLM 输出只进入可审阅草案层。
