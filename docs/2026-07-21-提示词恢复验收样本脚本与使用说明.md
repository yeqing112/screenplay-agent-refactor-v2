# 2026-07-21 提示词恢复验收样本脚本与使用说明

## 背景

分镜提示词恢复链路现在已经具备以下产品能力：

1. 服务端输出 `prompt_version_audit`
2. 服务端输出 `recommended_restore_version`
3. 镜头工作台可执行推荐恢复
4. 任务中心可识别提示词跑偏并直达首个恢复镜头

但真实项目数据不一定长期保留“当前版本已跑偏、历史版本可恢复”的状态。
如果只依赖偶然存在的历史数据，真浏览器验收会变得不可重复。

因此本轮补充了一个正式脚本：

- `scripts/storyboard_prompt_recovery_fixture.py`

它把测试里已经验证过的“场景保留、人物/关键道具缺失”的跑偏样本，抽成可重复执行的验收工具。

## 脚本目标

这个脚本服务于三类场景：

1. 真浏览器验收前，先把某个镜头切成“提示词跑偏”状态
2. 验证任务中心是否出现恢复任务
3. 验证恢复动作是否真的把镜头恢复到推荐版本

## 支持模式

### 1. 查看状态

```bash
python scripts/storyboard_prompt_recovery_fixture.py status --book-id 14 --episode 1 --shot-id 1
```

输出内容包括：

- 当前版本号
- 当前版本审计结果
- 推荐恢复版本
- 全部提示词版本的精简摘要

### 2. 造一个提示词跑偏样本

```bash
python scripts/storyboard_prompt_recovery_fixture.py degrade --book-id 14 --episode 1 --shot-id 1
```

执行结果：

1. 读取当前最新提示词版本
2. 复制出一个新的提示词版本
3. 把该版本改造成“仅保留场景引用、缺失关键人物/道具”的场景型跑偏版本
4. 将镜头当前版本切到这个新版本
5. 自动计算推荐恢复版本

### 3. 恢复到推荐版本或指定版本

```bash
python scripts/storyboard_prompt_recovery_fixture.py restore --book-id 14 --episode 1 --shot-id 1
```

如果要指定恢复到某个版本：

```bash
python scripts/storyboard_prompt_recovery_fixture.py restore --book-id 14 --episode 1 --shot-id 1 --restore-version 9
```

## 快照文件

脚本每次执行 `degrade` 或 `restore` 前，都会把当时的镜头状态写到：

- `artifacts/prompt-recovery-fixtures/`

用途：

1. 留存验收证据
2. 避免忘记当前状态
3. 后续需要手工排查时可直接比对

## 建议验收步骤

建议使用下面这套顺序做真页面验收：

1. 先确认前后端服务是用当前仓库代码启动的
2. 执行：

```bash
python scripts/storyboard_prompt_recovery_fixture.py degrade --book-id 14 --episode 1 --shot-id 1
```

3. 打开正式工作台
4. 进入 `任务中心`
5. 确认出现：
   - 提示词跑偏任务
   - 待恢复镜头数量
   - 推荐恢复摘要
6. 点击恢复入口
7. 确认页面落到目标镜头
8. 在镜头工作台执行推荐恢复
9. 再次执行：

```bash
python scripts/storyboard_prompt_recovery_fixture.py status --book-id 14 --episode 1 --shot-id 1
```

10. 确认当前版本已不再是跑偏版本，或确认已新增回滚版本

## 对应验收标准

本脚本补齐的是“提示词恢复链路的可重复验收前提”，新增标准如下：

1. 项目必须提供可重复的提示词跑偏验收样本生成能力
2. 任务中心到镜头工作台的恢复链路不能只在测试数据里成立
3. 推荐恢复版本必须能通过真实数据样本稳定复现
4. 验收人员不应依赖偶然存在的历史脏数据进行恢复链路验证

## 当前已知限制

1. 脚本直接改写数据库中的分镜提示词版本状态，因此建议只在本地开发或验收环境使用
2. 如果目标镜头从未编译过提示词，脚本不会自动首次编译，而是要求先完成一次正常编译
3. 真浏览器是否能立即看到结果，仍取决于当前前后端服务是否已加载最新仓库代码
