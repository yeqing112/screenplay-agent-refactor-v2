# 2026-08-25 导演分镜语言到机器提示词编译与导出备忘

日期：2026-08-25

## 1. 本备忘要固定的产品口径

本项目的分镜提示词链路不应再被理解为“用户写 prompt -> 系统提交模型”。

正式口径调整为：

`导演分镜语言（系统生成 + 用户可改） -> 标准化机器语言（系统编译） -> 多模型导出（WebUI / Markdown / CSV / API JSON） -> 可选 API 提交`

这里的“用户写的导演分镜语言”包括两种来源：

- 系统根据剧本、场景、人物、道具和镜头意图生成的导演分镜。
- 用户在正式工作台中对该分镜进行的人工修改。

也就是说，导演分镜语言是创作层，不是最终给模型执行的机器 prompt。

## 2. 四层边界

### 2.1 Director Shot Text / 导演分镜语言

职责：

- 让导演、分镜编辑、制片能读懂和修改。
- 保留镜头意图、起始状态、动作过程、结束落点、机位、情绪、对白/声音线索。
- 允许具备自然语言、导演语言、片场语言和创意表达。

非职责：

- 不直接等同于某个模型的最终 prompt。
- 不承担模型参数、WebUI 字段、API payload 的格式约束。
- 不应该被模型 Adapter 的语法污染。

### 2.2 Shot Schema / 结构化镜头事实

职责：

- 作为编译事实源，保存镜头可验证的结构信息。
- 承载人物、场景、道具、参考图、首帧、连续性、时间线等稳定字段。
- 支持 QA、重编译、回滚、版本对比和导出追踪。

非职责：

- 不保存某个模型的私有语法。
- 不保存用户临时复制到第三方 WebUI 后的人工改写结果。

### 2.3 Machine Prompt / 标准化机器语言

职责：

- 由系统从导演分镜语言和 Shot Schema 编译出来。
- 把导演语言转为模型更容易执行的结构化机器描述。
- 明确动作时间线、可观察行为、首帧/尾帧、镜头运动、连续性约束、参考图使用策略、环境声/配乐和负面约束。
- 保持模型中立，可被多个 Model Adapter 消费。

非职责：

- 不直接提交 API。
- 不绑定单一模型。
- 不反向污染导演分镜语言。

### 2.4 Model Export / 多模型导出

职责：

- 将 Machine Prompt 转换为目标模型或目标 WebUI 需要的字段。
- 支持 WebUI 复制、Markdown、CSV、JSON、API JSON 等导出方式。
- 针对不同模型输出不同格式，例如 MiniMax H3 可输出：
  - `integrated_multimodal_description`
  - `overall_soundscape`
  - `non_diegetic_music`
  - 参考图清单
  - duration / aspect ratio / submission policy

非职责：

- 导出不等于提交。
- API 提交必须由独立 Generation Adapter 负责，并保留显式用户动作、任务记录和失败恢复。

## 3. 与外部 Prompt Compiler 方案的对应关系

本口径继续继承《AI影视生产系统_结构化分镜与Prompt_Compiler落地设计方案_V1.0》的核心原则：

- 结构化数据优先。
- 模型语法与 Shot Schema 解耦。
- 静态资产、动态动作和连续性约束分离。
- 首帧/参考图是资产一致性的优先锚点。
- 每次编译都必须可追溯。
- LLM 可参与润色或补全，但不应绕过结构化编译层直接生成不可审计的最终文本。

本轮进一步明确：Prompt Compiler 的职责是“编译和导出”，不是“提交生成”。

## 4. MiniMax H3 / WebUI 导出启发

参考 MiniMax H3 的导演/视频提示词风格后，后续 H3 Adapter 应重点补强：

- 可观察动作时间线，而不是抽象情绪词堆叠。
- 音景和非画内配乐字段，而不是只写视觉画面。
- 参考图语义，包括人物身份、场景空间、道具状态、首帧连续性。
- 终帧落点，保证短视频生成有明确收束。

这些 H3 风格要求属于 Adapter / Exporter 层，不应写回 Shot Schema。

## 5. 已开始落地的工程切片

本轮已新增只读预览链路：

- `core/machine_prompt.py`
- `scripts/preview-storyboard-machine-prompt-export.py`
- `tests/test_machine_prompt_export.py`
- `npm run preview:machine-prompt-export`
- `npm run preview:book75-h3-export`
- `npm run e2e:machine-prompt-export`
- `GET /api/books/{book_id}/storyboard/{episode}/{shot_id}/machine-prompt-export`
- `PATCH /api/books/{book_id}/storyboard/{episode}/{shot_id}/director-shot-text`
- `POST /api/books/{book_id}/storyboard/{episode}/{shot_id}/machine-prompt-export-records`
- 正式镜头工作台中的 `机器提示词导出预览` 只读入口
- 正式镜头工作台中的导演分镜语言编辑、保存并重编译导出、恢复系统版入口
- 正式镜头工作台中的 MiniMax H3 / 通用 WebUI 一键复制入口
- 正式镜头工作台中的 Markdown / CSV / API JSON 文件导出入口
- 基于 `ProductionExportRecord` 的单镜头机器提示词导出快照记录
- 正式镜头工作台中的当前镜头导出历史刷新/查看面板

该切片做三件事：

1. 从真实分镜生成人类可编辑的导演分镜语言。
2. 编译成标准化 Machine Prompt。
3. 同一份 Machine Prompt 导出为 MiniMax H3 WebUI 和通用中文视频 WebUI 两种格式。
4. 在正式工作台镜头详情中展示导演分镜语言、机器时间线、H3 字段和通用 WebUI 文本。
5. 支持复制 H3 全字段、H3 integrated、音景、配乐和通用中文 WebUI 文本。
6. 支持登记“仅导出、不提交 API”的机器提示词导出快照，用于后续回溯。
7. 支持在当前镜头详情里读取最近的机器提示词导出历史。
8. 支持下载 Markdown、CSV 和 API JSON 预览文件；其中 API JSON 仍明确 `api_submission = false`，只能作为后续 Generation Adapter 的输入草案。
9. 支持用户保存导演分镜语言覆盖层，导出预览优先使用用户编辑版重新编译；该动作不覆盖 Shot Schema，不创建 Prompt Version。
10. 已新增真实 Chromium 回归：默认以 `book 75 / episode 1 / shot 1` 跑通“进入正式工作台 -> 镜头工作台 -> 加载机器提示词导出预览 -> 编辑导演分镜语言 -> 保存并重编译导出 -> 复制 H3 全字段 -> 下载 Markdown / CSV / API JSON -> 保存导出记录 -> 刷新导出历史 -> 恢复系统版”，并在结束后恢复测试前 `meta_info` 与删除本次新增导出记录。

当前切片明确不做：

- 不调用 LLM。
- 预览不写数据库；只有用户显式点击“保存导出记录”时，才写入导出快照。
- 不提交任何生成 API。
- 不把导出结果直接作为生成任务提交。
- 不把用户编辑的导演分镜语言自动反写为 `start_state / action_process / end_state` 等结构事实；如需反写，必须另做可审计的结构化解析/确认流程。
- 真浏览器 E2E 默认会恢复被测镜头的导演语言覆盖层和导出记录；若未来改成保留测试痕迹，必须显式改脚本策略。

## 6. 后续验收标准

- 用户能在正式镜头工作台看到并修改导演分镜语言。
- 修改导演分镜后，系统能重新编译 Machine Prompt。
- 同一镜头不改源分镜和 Shot Schema，即可导出至少两种模型格式。
- WebUI 导出与 API JSON 导出并列存在，API 提交为可选动作。
- MiniMax H3 导出至少包含动作时间线、环境声、非画内配乐和参考图使用策略。
- 用户对最终导出 prompt 的临时人工修改，不得污染导演分镜语言和 Shot Schema。

## 7. 当前下一步

下一步应把只读预览推进到正式工作台产品面：

1. 把当前镜头导出历史升级为可展开查看完整快照、可复用复制、可筛选的导出历史中心。
2. 增加“导演语言 -> 结构事实变更建议”的可审计解析流程，但必须由用户确认后才更新 Shot Schema。
3. 再把 API 提交作为独立动作接入任务中心和 Generation Adapter。
4. 对最终导出 prompt 的 WebUI 临时人工修改建立“导出版本草稿”能力，但不得反向污染导演分镜语言和 Shot Schema。
