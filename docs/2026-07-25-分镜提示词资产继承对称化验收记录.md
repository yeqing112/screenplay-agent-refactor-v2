# 2026-07-25 分镜提示词资产继承对称化验收记录

## 1. 本轮目标

继续推进分镜提示词编译治理，不再只收人物一类资产，而是把三类关键资产统一纳入同一套编译约束：

1. 人物多变体继承
2. 场景变体继承
3. 道具变体继承

本轮重点不是改页面样式，而是补齐 prompt compile 的“生产级护栏”。

## 2. 本轮改动

### 2.1 重写分镜提示词编译模板

修复文件：

- `prompts/storyboard/prompt_compiler.txt`

处理内容：

1. 将模板改成正式中文、可读、可维护的版本。
2. 明确以下强约束：
   - 静态提示词只描述首帧画面
   - 运动提示词只描述镜头运动与动作推进
   - 不得残留任务说明和英文模板字段
   - `reference_token` 要作为显式参考锚点自然进入静态提示词
   - `required_used_assets` 不得漏资产
   - `visual_fact_targets` 中的视觉事实必须被显式吸收
3. 明确三类资产的权威继承策略：
   - 人物：基础定妆 + 当前状态变体
   - 场景：空间结构 + 光线氛围 + 色彩基调 + 当前变体状态
   - 道具：形制材质 + 功能状态 + 当前变体状态

### 2.2 扩展后端诊断：场景 / 道具变体纳入编译质检

修复文件：

- `api/server.py`

新增诊断项：

1. `scene_variant_state`
   - 当镜头命中 `scene_variant` 时，如果静态提示词没有吸收该场景变体的关键视觉状态，则给出 warning。
2. `prop_variant_state`
   - 当镜头命中 `prop_variant` 时，如果静态提示词没有吸收该道具变体的关键视觉状态，则给出 warning。

同时同步接入：

1. 自动修复重试判断 `_should_attempt_prompt_repair(...)`
2. 修复上下文视觉事实回填 `_build_repair_visual_fact_targets(...)`

说明：

- 这一步让“人物 / 场景 / 道具”的变体状态检查首次进入同一条 prompt compile 质检链。
