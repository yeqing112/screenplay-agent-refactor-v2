# 分镜视频生成流程方案

## 当前目标

把“小说/剧本 -> 分镜 -> 参考图 -> 分镜图 -> 视频 -> 成片序列”落成一个可生产、可追踪、可验收的单集无限画布工作台。

当前策略不是重做底层管线，而是在现有真实项目数据和原型任务适配层之上，逐阶段补齐：

- 真实项目加载
- 真实任务接入
- 参考图/分镜图/视频的依赖关系
- 成片序列与采用版本
- 浏览器可见、用户可理解的生产状态

## 画布分层

画布按三层表达：

1. 文本层
- 剧本
- 镜头节点

2. 参考资产层
- 角色
- 场景
- 道具
- 参考图

3. 生产层
- 分镜图版本
- 视频版本
- 成片序列

默认优先显示主生产链路：

`镜头 -> 分镜图 -> 视频 -> 成片序列`

展开参考资产层后，再显示：

`角色/场景/道具 -> 参考图 -> 镜头`

## 数据结构约定

后端优先复用现有结构：

- `VisualMakeup / VisualLocation / VisualProp`
- `StoryboardShot.asset_links`

前端统一先映射为 `CanvasDocument`，UI 不直接拼接数据库字段。

`asset_links` 目标结构：

```json
{
  "references": {
    "characters": {},
    "scene": [],
    "props": {}
  },
  "images": [],
  "videos": [],
  "audios": []
}
```

前端节点补充语义字段：

- `imageRole`: `reference | storyboard | video_preview`
- `assetScope`: `character | location | prop | shot`
- `assetSubject`: 角色名、场景名、道具名或镜号

## API 契约

前端统一发送 `snake_case`：

- `book_id`
- `episode`
- `shot_id`
- `source_node_id`
- `source_asset_id`
- `asset_scope`
- `asset_subject`
- `target_kind`
- `prompt`
- `reference_asset_ids`
- `aspect_ratio`
- `duration_seconds`
- `simulate_error`

当前使用的接口：

- `POST /api/prototyping/generate-reference-image`
- `POST /api/prototyping/generate-image`
- `POST /api/prototyping/generate-video`
- `GET /api/prototyping/tasks/{task_id}`
- `POST /api/prototyping/adopt-version`

## 分阶段计划

### Phase 0：打通真实任务基础链路

目标：
- 修复前后端字段命名不一致
- 让图片/视频真实任务能启动、轮询、落库、刷新回填

验收标准：
- `npm run test` 通过
- `npm run build` 通过
- 浏览器中真实图片、真实视频任务都能成功
- 刷新后真实资产仍可映射回画布
- 不再出现 `422`

### Phase 1：补完整画布生产表达

目标：
- 用分层画布表达真实工作流
- 左侧镜头卡片展示生产进度
- 右侧按节点类型展示不同操作

验收标准：
- 用户能一眼看出哪些镜头缺参考图、缺分镜图、缺视频
- 参考资产层可展开/收起
- 不影响旧导演模式和高级模式

### Phase 2：接入参考图生成与回填

目标：
- 支持从角色、场景、道具节点发起参考图生成
- 结果写回 `asset_links.references`
- 刷新后从真实项目重新映射为参考图节点

验收标准：
- 角色、场景、道具都能生成参考图
- 参考图节点带真实资产标识
- 刷新后参考图和连线仍正确
- 失败节点显示错误并可重试

### Phase 3：分镜图生成使用参考资产

目标：
- 生成分镜图时带上参考图资产 id
- 参考图不完整时给出一致性风险提示，但允许继续
- 分镜图节点能显示“生成所用参考图”

验收标准：
- 请求体包含 `reference_asset_ids`
- 缺少参考图时 UI 有明确风险提示
- 多次生成新增版本，不覆盖旧版本
- 刷新后分镜图版本和采用状态仍存在

### Phase 4：视频生成使用分镜图与参考资产

目标：
- 从分镜图节点发起视频生成
- 请求包含来源图片、运动提示词、时长、参考图资产
- 成功后视频节点进入成片序列

验收标准：
- 视频任务从 `running` 到 `done`
- 视频节点显示来源分镜图、提示词、参考资产数量、真实资产 id
- 新视频默认采用并连接成片序列
- 切换采用版本后，旧视频保留但不再进入序列

### Phase 5：成片序列与整集验收体验

状态：进行中

已完成：

  - 右侧展示失败队列
  - 可从预览面板直接回到对应节点
  - 失败节点可直接“立即重试”
  - 采用视频项可展示缩略图、时长、参考图数量

当前复验结果：
- 前端测试通过：`npm test -- --run`
- 前端构建通过：`npm run build`
- 浏览器验收：
  - 顶栏已能看到整集概览

目标：

## Cross-phase 要求

每个阶段完成后都要执行：

- `npm run test`
- `npm run build`
- 至少一轮真实项目浏览器验收
- 把验收结果回写到本文件

最终总体验收至少覆盖：

1. 打开真实项目
2. 选择第 1 集
3. 生成人物参考图
4. 生成场景参考图
5. 生成道具参考图
6. 选择镜头生成分镜图
7. 选择分镜图生成视频
8. 采用视频版本
9. 检查成片序列
10. 刷新页面
11. 确认资产、连线、采用状态完整回填
