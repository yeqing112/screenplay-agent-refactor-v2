# 2026-08-04 本地服务恢复与真浏览器回归验收记录

## 1. 背景

用户反馈 `http://127.0.0.1:5175` 无法打开。经现场检查，问题不是页面功能回归，而是本地前后端服务未处于可访问状态，且前端一度因端口冲突自动漂移到 `5176`，导致固定验收地址 `5175` 失效。

本次目标：

- 恢复本地联调端口
- 确认前端固定回到 `5175`
- 确认后端固定在 `18765`
- 完成一轮真浏览器回归，验证首页到正式工作台关键模块可访问

## 2. 问题定位

初始检查结果：

- `http://127.0.0.1:5175` 连接失败
- `http://127.0.0.1:18765/api/books` 连接失败
- 本地未发现对应监听中的 `5175 / 18765`

后续排查发现：

- 后端未启动
- 前端重启过程中因端口占用/残留进程探测问题，一度自动切到 `5176`
- 这会让“页面看似启动了，但固定验收地址 `5175` 打不开”

## 3. 本次恢复动作

### 3.1 后端恢复

启动方式：

```powershell
python -m uvicorn api.server:app --host 127.0.0.1 --port 18765
```

恢复结果：

- `127.0.0.1:18765` 监听成功
- `http://127.0.0.1:18765/api/books` 返回 `200`

### 3.2 前端恢复

处理策略：

1. 清理残留前端进程
2. 避免继续使用会自动漂移端口的临时运行态
3. 改为固定 `5175` 的 `build + vite preview --strictPort` 方案
4. 构建时显式绑定 `VITE_API_PROXY_TARGET=http://127.0.0.1:18765`

恢复结果：

- `127.0.0.1:5175` 监听成功
- `http://127.0.0.1:5175` 返回 `200`
- 真浏览器首页明确显示：
  - `API Proxy: http://127.0.0.1:18765`

## 4. 服务状态验收

最终确认：

- 前端：[http://127.0.0.1:5175](http://127.0.0.1:5175)
- 后端：[http://127.0.0.1:18765/api/books](http://127.0.0.1:18765/api/books)

验收结论：

- `5175` 已恢复为正式可访问入口
- `18765` 已恢复为当前前端实际指向的后端入口
- 不再是“实际跑在 5176，但用户仍被要求访问 5175”的混乱状态
