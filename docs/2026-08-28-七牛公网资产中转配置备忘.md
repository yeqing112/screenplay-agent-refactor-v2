# 2026-08-28 七牛公网资产中转配置备忘

## 背景

项目当前运行在本地局域网，MiniMax H3 / metaso 这类云端视频模型无法直接访问本地 `/api/prototyping/assets/...` 或已经失效的外部首帧 URL。

因此，H3 图生视频真实提交前必须获得一个 provider 可拉取的图片 URL。

## 当前七牛空间

- Bucket：`ai-ku01`
- 区域：华南-广东，项目配置值为 `z2`
- 访问控制：私有
- 当前测试域名：`tkgj4ur0t.hn-bkt.clouddn.com`
- 限制：七牛控制台提示该测试域名每日限回源流量、30 天回收且不支持 HTTPS

结论：`ai-ku01` 可以作为临时开发资产层；测试域名不应作为生产级 H3 首帧 URL 依据。

## 后台配置入口

对象存储不再只依赖 `.env`。正式工作台的 `模型管理 -> 对象存储 / 首帧公网中转` 已提供后台配置入口，可用于添加或更换对象存储配置。

当前支持字段：

- Provider：第一版支持七牛 Kodo。
- 本地后端地址：本地资产路径转公网前，用于读取 `/api/prototyping/assets/...` 等资源。
- Bucket / Region / 公网访问域名 / 对象前缀。
- AccessKey / SecretKey：保存后只显示“已保存”，不会回显明文；留空保存会保留后台已有密钥。
- 私有 Bucket：开启后提交给 H3 的首帧使用限时签名 URL。

配置 API：

- `GET /api/public-asset-storage/config`
- `PUT /api/public-asset-storage/config`

## 本地 `.env` 兼容配置

AccessKey / SecretKey 只允许写入本地 `.env`，不要提交到仓库。

```env
PUBLIC_ASSET_STORAGE_PROVIDER=qiniu
PUBLIC_ASSET_LOCAL_BASE_URL=http://127.0.0.1:18765

QINIU_ACCESS_KEY=你的AccessKey
QINIU_SECRET_KEY=你的SecretKey
QINIU_BUCKET=ai-ku01
QINIU_REGION=z2
QINIU_PUBLIC_BASE_URL=http://tkgj4ur0t.hn-bkt.clouddn.com
QINIU_BUCKET_PRIVATE=true
QINIU_KEY_PREFIX=screenplay-agent
QINIU_UPLOAD_TOKEN_EXPIRES_SECONDS=3600
QINIU_PUBLIC_URL_TTL_SECONDS=86400
```

生产替换：

```env
QINIU_PUBLIC_BASE_URL=https://你的自定义HTTPS-CDN域名
```

## 当前代码行为

- 公网 HTTP/HTTPS 首帧：先 GET 检查是否可访问；可访问则直接提交。
- 本地 API URL、data URI、本地路径：配置七牛后可上传到七牛，再生成签名 URL。
- 已经 404 的外部 URL：无法凭空恢复源文件，会阻断真实提交，需要重新生成或重新上传首帧。
- 私有 Bucket：默认生成限时签名下载 URL。
- H3 灰度脚本默认只检查，不上传；显式传 `--publish-first-frame` 才允许上传七牛。

## 更换 OSS 与迁移规划

正式工作台已新增只读迁移规划入口：`模型管理 -> 对象存储 / 首帧公网中转 -> 生成迁移计划`。

迁移规划会扫描：

- `VisualReferenceAsset.image_url`
- `VisualReferenceAsset.local_path`
- `StoryboardShot.asset_links` 中的 `images / videos / audios` 的 `uri / previewUrl`

并把资产分为：

- `already_target_storage`：已经在当前目标对象存储域名下。
- `needs_publish`：本地、内联或文件资产，需要发布到对象存储。
- `external_accessible`：外部 URL 当前可读，可作为迁移源。
- `external_unreachable`：外部 URL 当前不可读，不能直接迁移。
- `external_unchecked`：快速规划模式下识别为外部 URL，但尚未逐条联网检查。
- `unknown_source`：无法识别来源。

当前版本只做迁移计划，不会自动写入对象存储或改写数据库资产引用。默认迁移计划采用快扫模式，不逐条访问外部 URL，避免后台按钮被坏外链长时间拖住；执行迁移前必须再做深度可读性检查。

后续如果实现“一键迁移”，必须满足：

1. 默认 dry-run，只生成迁移计划和影响范围。
2. 用户显式确认目标 Bucket、域名、迁移数量和确认令牌。
3. 迁移时先上传新对象，再改写引用，并保留旧 URL 和迁移记录。
4. 失败资产不应阻断已成功资产的回写，但必须生成可重试报告。
5. 禁止自动删除旧对象；清理旧对象必须作为单独的受保护操作。

## 验收标准

- `npm run validate:minimax-h3-gray -- auto` 不应把 404 外部首帧误判为可提交。
- 没有可访问首帧时，`readiness.blockers` 应包含 `selected_first_frame_url_not_provider_accessible`。
- 配置七牛并提供可读取源图后，H3 提交入口应使用七牛签名 URL 作为 `first_frame_url`。
- 没有自定义 HTTPS CDN 域名前，只能算临时灰度，不算生产上线完成。
- 后台迁移计划必须只读，不应在“生成迁移计划”时上传云对象或改写任何资产引用。
