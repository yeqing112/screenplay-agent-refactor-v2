# 场景资产四视图提示词合同修正记录

## 问题与根因

场景资产编译曾使用“单张 16:9 横构图、不得分格、不得多视角排版”的历史模板。该模板适合单张背景图，但不符合本项目约定的场景空间参考板：模型需要同时看到主视角、反向关系、侧向纵深和关键空间细节，才能在后续分镜中稳定继承入口、门窗、固定陈设和光线方向。

问题还被两处重复实现放大：正式 API 的资产合同和 `scripts/plan-storyboard-scene-reference-assets.py` 各自维护一份模板，导致展示、计划和实际生成请求存在漂移风险。

## 现行确定性合同

场景参考图是“一张 16:9 横向四视图场景设定板”，固定为 2×2 四宫格：

| 位置 | 视图职责 | 必须保持 |
| --- | --- | --- |
| 左上 | 主视角空间全景 | 场景总体布局、入口和主要空间关系 |
| 右上 | 反向视角 | 与主视角同一空间，验证前后关系与固定陈设 |
| 左下 | 侧向视角 | 验证纵深、出入口、墙体和门窗位置 |
| 右下 | 关键细节视角 | 材质、关键陈设、局部结构和光线落点 |

四格必须是同一场景、同一时间、同一天气、同一套固定陈设；不允许因为换视角而新增或移动固定物。画面只展示场景空间，不出现人物、角色、人脸、文字、标注、标题、水印或 logo。

## 落地边界

- `api.server._build_scene_asset_prompt_contract` 生成 `rendered_prompt_preview`、`reference_layout=2x2_four_view` 和稳定的 `reference_view_schema`。
- `scripts/plan-storyboard-scene-reference-assets.py` 复用 API 合同常量，不再维护冲突的单视图副本。
- `reference-image` 排队前服务端按实时资产快照重编译场景提示词、负向提示词，并强制场景画布比例为 `16:9`。
- 负向约束允许目标四宫格和四视图，只阻止额外分格、错位拼图、三/六/九宫格和文字污染。
- `confirmed_prompt_raw` 仍保留用户/LLM 原文；四视图合同只作为供应商请求的确定性渲染结果，不覆盖审计源。
- 导入/就绪流程产生的“最小场景资产”及其操作备注属于元数据，不属于场景事实；API 与只读计划均会过滤这类占位内容，避免污染生图提示词，同时保留原始字段供审计。

## 验收

- 场景资产接口和场景参考图计划均检查四视图四个槽位及 `2x2_four_view` 结构。
- 旧页面携带单张或错误比例提示词时，生成边界会替换为四视图提示词并改为 16:9。
- 旧场景图片不会自动迁移；重新生成后仍需人工审核并锁定，才可进入分镜生产。
