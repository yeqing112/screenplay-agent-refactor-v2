# 正式工作台真实项目回归样本库 v1 记录

日期：2026-08-24

## 背景

`npm run e2e:business` 已经能用可控 fixture 跑通正式工作台写入型主链路，但生产级上线清单要求至少 3 个真实项目进入回归样本库。

本轮新增一个独立真实样本巡检命令：

```bash
npm run e2e:real-samples
```

它和 `e2e:business` 的职责不同：

- `e2e:business`：可写 fixture，验证候选选择、Production Skill 锁定、主方向锁定、提示词锁定、验收记录、QA 修复与回滚真实落库。
- `e2e:real-samples`：真实项目非破坏性巡检，验证多个真实项目能从项目列表进入正式工作台，并连续覆盖内容、改编、剧本、镜头、资产、QA、导出、画布、任务、模型管理。

## 样本覆盖

默认样本：

| 项目 | 类型 | 覆盖价值 |
| --- | --- | --- |
| `book 14 / 三个和尚` | 小型完整项目 | 章节、剧本、分镜、资产、QA 数据较完整，适合验证标准链路 |
| `book 5 / 神农架历险记` | 较复杂历史项目 | 章节计数、剧本、分镜、资产规模较大，适合验证旧数据兼容 |
| `book 75 / 深夜便利店` | 近期真实项目 | 多章节、多剧本、多 QA 问题，适合验证近期数据结构 |

脚本也支持通过环境变量覆盖：

```bash
E2E_REAL_SAMPLE_BOOK_IDS=14,5,75 npm run e2e:real-samples
```

## 关键安全设计

真实项目巡检默认阻止所有非安全 API 方法：

- 允许：`GET`、`HEAD`、`OPTIONS`
- 阻止并记录为失败：`POST`、`PUT`、`PATCH`、`DELETE`

这保证真实样本回归不会因为浏览器自动行为污染真实项目数据。

## 本轮发现与修复

首次运行时发现正式工作台只读浏览会触发以下服务端写请求：

- `/api/books/{book_id}/adaptation-state`
- `/api/books/{book_id}/production-skill-state`

原因是 `useProductWorkspaceUpstream` 在加载服务端状态失败或缺失时，会把浏览器 localStorage 中的旧状态自动回写到服务端；同时状态变化 effect 会把普通本地状态变化同步到服务端。

已调整为：

- 页面加载和切模块只读，不再自动 PUT。
- 本地草稿仍写入 localStorage。
- 只有用户显式点击 Production Skill 锁定/解锁、主方向锁定/解锁时才写服务端。

同时修正 `e2e:business` fixture：改编方向从未锁定状态开始，避免依赖旧的自动回写行为。

## 验证结果

已通过：

```bash
npm --prefix web run build
npm run e2e:real-samples
npm run e2e:business
```

`e2e:real-samples` 结果：

- 3 个真实项目均可从项目列表进入正式工作台。
- 每个项目均完成 10 个模块巡检：
  - 内容准备
  - 改编方向
  - 剧本工作台
  - 镜头工作台
  - 资产中心
  - QA 修复
  - 导出中心
  - 创作画布
  - 任务中心
  - 模型管理
- 必选模块无业务门禁阻断。
- 浏览器巡检期间未发生真实数据写请求。

## 后续仍未完成

该 v1 样本库证明的是“真实项目非破坏性主链路可达”，还不等于生产级闭环完全完成。

下一步仍需继续：

1. 在样本项目中做分镜 prompt 质量抽检，至少覆盖 30 个镜头。
2. 检查多变体资产继承与资产中心/镜头工作台显示一致性。
3. 收口 QA 放行与导出阻塞标准。
4. 扩展到至少 5 个代表性项目，覆盖更多脏数据与历史数据形态。

## 2026-08-24 补充：真实项目回归样本库 v2 扩展到 5 项目

本轮将 `npm run e2e:real-samples` 默认样本从 3 个扩展到 5 个：

| 项目 | 覆盖价值 |
| --- | --- |
| `book 14 / 三个和尚` | 小型完整项目，适合验证标准链路 |
| `book 5 / 神农架历险记` | 较复杂历史项目，资产规模较大 |
| `book 75 / 深夜便利店` | 近期真实项目，适合验证近期数据结构 |
| `book 3 / 金丝雀` | 旧项目，34 个分镜、70 个视觉资产，适合暴露旧资产/任务兼容问题 |
| `book 1 / 苗疆道事` | 大体量旧项目，21 个分镜、33 个视觉资产、30 个 QA 问题，适合验证脏数据承载能力 |

对应默认配置已更新：

```bash
E2E_REAL_SAMPLE_BOOK_IDS=14,5,75,3,1
E2E_REAL_SAMPLE_MIN_COUNT=5
```

本轮扩展试跑时暴露一个真实历史数据问题：`book 3` 与 `book 1` 的旧创意任务记录中存在 `/api/prototyping/assets/image-*` 占位预览 URL，但当前正式工作台已不再提供旧原型资产静态路由，导致真浏览器出现 404。

处理方式：

- 任务中心数据归一化时会过滤这类旧占位预览 URL。
- 后端补充 `/api/prototyping/assets/{asset_id}` 兼容路由；当旧原型资产实体已不存在时，返回 `image/svg+xml` 占位图与 `X-Legacy-Prototyping-Asset` 头，避免正式工作台真实浏览器巡检被历史预览图 404 打断。
- 任务本体、任务 ID、首帧资产 ID、参考资产 ID 仍保留。
- 页面降级显示为“无可预览图片”，不再让丢失的旧预览图污染真实项目回归。

这不是放宽主链路标准，而是把旧原型资产缺失从“浏览器资源错误”收敛为“任务记录可见但图片不可预览”的产品兼容态。

本轮验证结果：

```bash
npm run e2e:real-samples
```

通过。输出确认：

- 默认样本已覆盖 `#14, #5, #75, #3, #1` 共 5 个真实项目。
- 每个项目均完成正式工作台 10 个模块巡检。
- 必选模块无业务门禁阻断。
- `book 3`、`book 1` 中的旧 `/api/prototyping/assets/image-*` 预览 URL 已降级为 200 占位响应，不再产生浏览器 404。

结论：真实项目非破坏性回归样本库已从 v1 的 3 项目扩展为 v2 的 5 项目，且历史原型预览图缺失已纳入兼容基线。下一步不再扩大只读巡检本身，而应继续增加可回滚写入型样本与 QA/导出阻塞链路验证。
