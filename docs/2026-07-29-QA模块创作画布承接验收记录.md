# 2026-07-29 QA 模块创作画布承接验收记录

## 本轮目标

把 `创作画布 Beta -> QA 修复` 的承接体验从“仅跳到 QA 页面”推进到“进入 QA 后已定位到当前问题上下文”。

## 本轮实现

- `ProductWorkspaceQaSection` 新增 `canvasHandoff` 承接能力。
- 当 QA 从创作画布进入时：
  - 顶部仍显示统一横幅 `来自创作画布的下一步`
  - 选中问题详情区域额外显示：
    - `创作画布承接中`
    - `已从创作画布定位到 ...`
    - 当前承接说明
- 如果当前已经命中具体问题，则详情卡会优先显示问题标题与当前承接说明。

## 自动化验证

- `cd web && npm run test -- ProductWorkspaceQaSection ProductWorkspaceSectionContent ProductWorkspaceCanvasBetaSection productWorkspaceCanvasBeta`
- `cd web && npm run build`

结果：

- 31 个测试全部通过
- 前端构建通过

## 真浏览器验收

项目：`三个和尚`

路径：

- `三个和尚 -> 创作画布 Beta -> 第 1 集质检 -> 打开对应模块`

结果：

- 画布右侧存在推荐动作：
  - `前往 QA 修复处理问题`
  - 或 `前往 QA 修复复核结果`
- 进入 QA 模块后顶部出现统一横幅：
  - `来自创作画布的下一步`
  - `当前承接：第 1 集`
- 进入 QA 模块后问题详情区出现局部承接卡：
  - `创作画布承接中`
  - `已从创作画布定位到 第 1 集`

## 结论

QA 模块已经不再只是被动接收来自画布的导航，而是开始表现为真正的“连续创作修复入口”。

这一步的意义是：

- 画布推荐动作与 QA 问题详情建立了连续关系
- 用户进入 QA 后更容易理解“为什么我被带到这里”
- 为后续把承接提示继续下沉为 QA 内部首个可执行修复动作打下基础
