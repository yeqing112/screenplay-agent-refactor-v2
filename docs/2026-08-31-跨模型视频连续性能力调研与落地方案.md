# 跨模型视频连续性能力调研与落地方案

> 状态：调研第一版；实施前必须按本文灰度矩阵复验。  
> 原则：不按模型名写业务特例；以能力声明、策略路由、版本化交接帧和可审计验收实现连续性。

## 1. 结论

“相邻镜头强连续”必须使用上一镜的真实视觉结果，而不是只复述文字提示词。统一生产链路为：

```text
已验收上一镜视频 → 提取并锁定交接末帧 → 连续性合约
→ 按模型能力组装输入 → 生成 → 抽取新视频首帧 → 连续性验收
```

不存在适用于所有模型的一种请求体。系统必须依据模型能力在下列策略中路由：

1. `strict_first_frame`：上一镜末帧作为下一镜严格首帧；
2. `strict_start_end`：上一镜末帧作首帧，当前镜目标状态图作尾帧；
3. `reference_anchor`：上一镜末帧作为参考锚点，与资产参考共同输入；
4. `video_extension`：直接延展上一镜成片；
5. `soft_continuity`：只导出状态合约和机器提示词，不能承诺画面级强连续。

## 2. 官方资料核验（2026-08-31）

| 平台/模型 | 已确认能力 | 关键限制 | 系统策略 |
|---|---|---|---|
| MiniMax H3 | 文生、首帧、尾帧、首尾帧、多模态参考图/视频/音频 | `first_frame/last_frame` 与 `reference_*` **互斥**；首帧≤1、尾帧≤1、参考图≤9 | 首尾帧严格交接，或多参考资产一致性，二者不得混传 |
| MiniMax H3 Max | 文生、首帧、尾帧、首尾帧 | 不支持中间帧与多模态参考 | 仅严格交接模式 |
| Luma Ray 2 | `keyframes.frame0` 起始图、结束帧、视频延展 | 图片须自有 CDN 公网 URL；新 Agents API 的字段需灰度复验 | 首帧/首尾帧交接，或延展 |
| Google Veo（Vertex AI） | 官方产品页列出首帧图生、首尾帧、参考、延展、编辑 | 具体型号/区域/版本字段不同，接入前需锁定 model revision | 能力配置驱动，先做官方样本灰度 |
| Runway | 官方 API 目录确认 image-to-video、video-to-video、multi-shot 等端点类别 | 当前公开目录未在本轮提取到首尾帧字段；不得推断 | 先登记为 `pending_field_verification`，不开放强连续 |

### 2.1 关键证据

- [MiniMax H3 v2 创建任务](https://platform.minimaxi.com/docs/api-reference/video-generation-v2-create)：明确列出 `first_frame`、`last_frame`、`reference_image`，并声明图生首尾帧与多模态参考互斥。
- [Luma Video Generation](https://docs.lumalabs.ai/docs/video-generation)：公开请求示例使用 `keyframes.frame0`，并要求用户自己的 CDN 图片 URL。
- [Google Veo 视频生成概览](https://cloud.google.com/vertex-ai/generative-ai/docs/video/generate-videos)：官方导航明确列出 First frame、First and last frames、References、Extend videos。
- [Runway API Reference](https://docs.dev.runwayml.com/api/)：确认图生视频、文生视频、视频转视频和多镜头相关 API 类目；参数仍需逐端点核验。

## 3. 统一能力协议

模型注册表在 `default_params.video_capabilities` 保存连续性能力协议，禁止由业务层从 provider 名称猜行为：

```json
{
  "first_frame": false,
  "last_frame": false,
  "start_end_frames": false,
  "reference_images": false,
  "reference_video": false,
  "reference_audio": false,
  "video_extension": false,
  "reference_and_keyframe_compatible": false,
  "max_reference_images": 0,
  "requires_public_media_url": true,
  "webui_export": true,
  "evidence_status": "confirmed|pending_field_verification|experimental"
}
```

`reference_and_keyframe_compatible` 是硬门禁字段。H3 的值必须为 `false`。

## 4. 新的数据模型

### 4.1 TransitionFrame

```text
id, book_id, source_episode, source_shot_id, target_episode, target_shot_id
source_video_asset_id, frame_time_ms, frame_kind(last|near_last)
storage_key, public_url, checksum, width, height
status(candidate|selected|locked|superseded)
extraction_profile, created_at, locked_at, operator
```

仅从已持久化且已验收的视频资产提取；原视频和帧均写入对象存储，供应商临时 URL 不能作为唯一来源。

### 4.2 TransitionContract

```text
continuity_level(strict|soft|narrative|independent)
source_shot / target_shot
inherit: 人物身份、服装、发型、场景、关键道具、时间、光线
allowed_changes: 本镜可发生变化
forbidden_changes: 不允许突变
entry_state / exit_state
required_transition_frame_id
```

## 5. 生成路由与门禁

1. 仅 `strict` 连续性可申请交接帧；
2. 检查上一镜视频已验收、交接帧已锁定、当前资产参考已锁定、公网 URL 可访问；
3. 按能力选择策略；无匹配能力时拒绝严格连续并给出降级原因；
4. 请求、参考图顺序/角色、策略、提示词版本、能力快照全部存入任务审计；
5. WebUI 导出必须输出同样的交接帧文件、顺序和互斥说明，不等同 API 提交。

## 6. 生成后验收

从当前成片抽取首帧，与锁定交接帧比较：人物、服装/发型、场景布局、关键道具、相对站位、光色与构图。结果按 `identity_drift`、`costume_drift`、`scene_drift`、`prop_drift`、`composition_jump` 分类；失败重试必须复用同一交接帧和资产包，不得随机换参考。

## 8. 灰度验收矩阵

每个模型至少验证：首帧、首尾帧（若支持）、参考图（若支持）、互斥组合、无公网 URL、URL 过期、任务回收、末帧提取、下一镜首帧比对、WebUI 导出。真实调用必须由用户二次确认，单模型至少三组不同人物/场景样本。

## 9. 当前项目决策

- MiniMax H3：优先实现 `strict_first_frame` 与 `strict_start_end`；资产多参考模式作为独立策略，不能和交接首尾帧混传。
- 现有“多参考 H3”流程不得被改写为“首帧流程”；工作台应让用户显式选择策略并展示能力限制。
- 尚未经真实 API 样本验证的模型不得显示为“支持强连续”。

## 10. 2026-09-01 实施记录（P0 第一段）

- 新增 `storyboard_transition_contracts`、`storyboard_transition_frames` 和 Alembic 迁移；仅允许同一集内相邻镜头建立交接关系。
- 合约草案接口完全只读；确认合约、登记交接帧、锁定交接帧均要求 `confirmed=true` 和 `allow_write=true`，锁定新帧会将同一交接对的旧锁定帧标为 `superseded`。
- 生成前只会在存在**已确认 strict 合约**时启用强连续门禁：没有锁定且公网可访问的交接帧、或当前模型不支持首帧，均返回 `409`，绝不静默降级。
- H3 的多参考图与首帧组合现在在 Adapter 和二次真实提交接口双重阻断；正式工作台的 H3 提交明确选用多参考图模式，不再发送“首帧仅作兜底”的矛盾请求。
- 第一段未自动提帧、上传七牛、锁定资产或提交模型生成；后续媒体写入已在第二段以双确认边界实现，模型生成仍需独立确认。

## 11. 2026-09-01 实施记录（P0 第二段）

- 新增受保护的 `transition-frames/extract`：只接收相邻上一镜已采纳且验收为 `approved/accepted` 的视频；没有双确认、视频未验收、对象存储未配置时一律拒绝。
- 执行时使用 FFprobe 获取时长、FFmpeg 在确定性的 `near_last` 偏移点提取 PNG，保留本地持久化副本，再经对象存储发布为公网 URL。
- 帧以 SHA-256 校验和去重；提取结果仅登记为 `candidate`，绝不自动提升为 `selected/locked`，也不触发任何视频模型调用。
