# 2026-07-25 分镜提示词质量治理补强验收记录

## 本轮目标

围绕分镜静态提示词 / 运动提示词质量问题，补强三类能力：

1. 让“对白稿残留、高重要度道具缺失”在镜头工作台中被直接看见。
2. 让 prompt repair 上下文对 LLM 提供更强的重写约束，而不是只给模糊告警。
3. 让历史镜头在读取时自动刷新到新的诊断集合，避免旧诊断掩盖真实问题。

## 本轮实现

### 1. 镜头工作台新增重点诊断可视化

文件：

- `web/src/components/ProductWorkspaceStoryboardSection.tsx`
- `web/src/components/ProductWorkspaceStoryboardSection.test.tsx`

新增聚焦卡片：

- `screenplay_prompt_residue`
- `high_importance_prop_presence`

同时扩展“重新编译提示词”修复入口，使其能优先处理：

- 对白稿 / 舞台提示残留
- 高重要度道具未进入静态提示词
- 视觉事实继承不足

### 2. Prompt repair 上下文补强

文件：

- `api/server.py`
- `prompts/storyboard/prompt_compiler.txt`
- `tests/test_storyboard_prompt_repair_context.py`

新增 repair 上下文字段：

- `priority_fixes`
- `screenplay_residue_details`
- `rewrite_constraints`

新增约束重点：

- 若检测到 `screenplay_prompt_residue`，要求整体重写，不允许轻微修补。
- 明确禁止角色名加冒号、方括号舞台提示、剪辑口令、对白正文继续出现在结果中。
- 明确要求优先修复最高优先级失败项。

### 3. 历史诊断自动刷新补强

文件：

- `api/server.py`
- `tests/test_storyboard_prompt_context_legacy_refresh.py`

修复点：

- `_prompt_compiler_diagnostics_need_refresh()` 现在要求以下新检查项必须存在，否则判定旧诊断需要刷新：
  - `screenplay_prompt_residue`
  - `character_variant_state`
  - `scene_variant_state`
  - `prop_variant_state`
  - `high_importance_prop_presence`

这解决了一个关键根因：旧镜头虽然提示词已经明显退化，但因为诊断对象是旧版本格式，API 读取时不会自动重算，导致 UI 和统计低估问题。
