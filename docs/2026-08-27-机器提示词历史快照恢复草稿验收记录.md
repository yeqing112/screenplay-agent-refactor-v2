# 2026-08-27 机器提示词历史快照恢复草稿验收记录

## 背景

项目级导出资产库已经统一保存和检索机器提示词导出快照，但历史快照此前只能“看”和“复制快照 JSON”。生产中更常见的需求是：用户发现某个历史版本更适合第三方 WebUI，就希望把它临时恢复为当前可复制、可下载的导出草稿，而不是改写当前镜头事实。

## 本轮改动

- 新增 `buildMachinePromptDraftFromExportRecord(...)`：
  - 将 `ProductionExportRecord.meta_info` 中的 `director_shot_text / machine_prompt / model_exports` 恢复为机器提示词导出预览对象。
  - 恢复对象标记为 `mode=history_webui_draft`。
  - `source_layers.is_temporary_webui_draft=true`。
  - `source_layers.history_export_record_id` 记录来源快照。
- 当前镜头导出历史记录新增操作：
  - `恢复为 WebUI 草稿`
- 恢复后：
  - 主导出预览切换为历史草稿。
  - 页面显示 `历史草稿 #...` 状态徽章。
  - 仍可复制 `H3 全字段`，也可继续导出 Markdown / CSV / API JSON。
- 明确安全边界：
  - 不反写导演分镜语言编辑框。
  - 不更新 Shot Schema。
  - 不创建或回滚 Prompt Version。
  - 不提交生成 API。

## 当前边界

- 当前“草稿”只存在于前端导出预览状态中，刷新页面后需要重新从历史记录恢复。
- 暂未支持在恢复草稿上直接人工编辑最终机器提示词字段。
- 暂未把恢复草稿作为独立 `draft` 记录保存。
- API 提交仍未接入，仍必须作为后续独立任务链路设计。

## 后续建议

1. 增加“最终导出 prompt 人工临时修改”能力，并明确它只属于导出草稿，不反向污染导演语言、Shot Schema 或 Prompt Version。
2. 将导出草稿保存为独立 draft record，方便刷新页面后继续使用。
3. 接入 API 提交独立任务链路，保留 `api_submission=false` 的默认安全边界，只有用户明确提交时才进入模型任务。
