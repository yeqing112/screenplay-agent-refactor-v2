# 分镜提示词真实样本质量审计 v1 记录

日期：2026-08-24

## 背景

真实项目回归样本库 v1 已验证正式工作台主链路可达，但生产级上线清单还要求分镜提示词质量达标，不能只停留在页面能打开、模块能切换。

本轮新增审计命令：

```bash
npm run audit:storyboard
```

默认样本：

- `book 14 / 三个和尚`
- `book 5 / 神农架历险记`
- `book 75 / 深夜便利店`
- `book 3 / 金丝雀`
- `book 1 / 苗疆道事`

默认抽检不少于 50 个真实分镜镜头，约等于每个默认项目 10 个镜头。

## 审计口径

当前 v1 审计覆盖：

1. 静态提示词是否存在，且长度不低于 80 字符。
2. 运动提示词是否存在，且长度不低于 50 字符。
3. 场景名、静态提示词、运动提示词是否存在疑似乱码/坏编码。
4. 运动提示词是否包含明确镜头运动或调度语义。
5. 静态提示词是否包含基本视觉构图、光线、环境或质感语义。
6. `structured_shot.scene_asset_id` 是否存在。
7. `structured_shot.character_asset_ids` 与 `action_beats` 是否具备结构化追踪基础。
8. `prompt_compile_context.required_used_assets` 是否被 `used_assets` 覆盖。
9. 已绑定且有参考图的资产是否进入 `reference_images`。
10. 绑定资产名称是否至少有一部分进入提示词正文。

默认是报告模式，不阻断开发流程；后续质量门槛稳定后，可用：

```bash
AUDIT_STORYBOARD_STRICT=1 npm run audit:storyboard
```

切换为严格失败模式。

## 结论

当前真实样本主链路已经可达，但分镜提示词质量还不能按生产级通过。

尤其需要优先处理：

1. 旧项目或近期项目中短 prompt 的重编译/修复路径。
2. `structured_shot.scene_asset_id` 的补齐与资产绑定回填。
3. 场景名、关键资产名进入最终提示词正文的硬约束。
4. 把该审计逐步接入严格模式，作为 prompt 质量门禁。

## 下一步建议

1. 先用可控 fixture 增加“短 prompt -> 重编译后达标”的单元/接口测试。
2. 再在真实项目样本上做可回滚重编译验证，不直接污染原项目。
3. 将审计扩展到至少 5 个代表性项目。
4. 把 `scene_asset_id` 缺失修复链路接入资产中心/镜头工作台的显式修复入口。

4. 生成 JSON 与 Markdown 预检报告，包含：
   - 样本影响清单；
   - 修复前后 error / warning；
   - 真实落库建议接口；

重要发现：

落库前门禁更新为：

1. 必须先运行 `npm run plan:storyboard-batch-repair` 生成预检报告。
2. 用户必须明确确认预检报告和确认令牌。
3. apply 命令必须要求确认令牌，不能靠默认参数写真实项目。
