# 2026-08-22 生产级推进：旧执行层前端残留清理记录

## 背景

前端已收敛为单一正式工作台，但代码库中仍残留一组旧 DevCanvas/节点执行层组件。这些组件不再被正式工作台引用，却仍指向 `/api/nodes*`、`/api/runs*` 等旧执行层接口，容易造成维护者误判“旧控制台仍是有效产品面”。

本轮目标不是删除历史数据，也不是直接关停后端兼容接口，而是先完成低风险、可验证的前端不可达代码清理，并把文档同步到当前真实架构。

## 审计结论

### 正式工作台现状

- 项目入口：`ProjectsPage` -> `CanvasPage` -> `ProductWorkspace`
- 当前工作台模块：
  - 项目控制台
  - 内容准备
  - 改编方向
  - 人物质检
  - 剧本工作台
  - 镜头工作台
  - 创作画布
  - 资产中心
  - QA 修复
  - 任务中心
  - 导出中心
  - 模型管理

### 已删除的旧前端残留

- `web/src/components/AgentNode.tsx`
- `web/src/components/HistorySidebar.tsx`
- `web/src/components/PromptSelector.tsx`
- `web/src/components/ResultsPanel.tsx`
- `web/src/components/pipelineLayout.ts`
- `web/src/types/nodes.ts`

删除前复核结果：上述文件只在自身和过期文档中出现，当前 `web/src` 无正式工作台 import 依赖。

### 暂不删除的后端兼容层

以下接口和 `nodes/` 后端执行层仍保留为 legacy 兼容层：

- `/api/workflows*`
- `/api/nodes*`
- `/api/runs*`
- `nodes/runner.py`
- `nodes/registry.py`
- `nodes/handlers/*`

原因：

1. 历史 workflow/run 数据不属于本轮清理对象。
2. 现有后端 HTTP 错误测试仍覆盖 `/api/workflows/{id}` 缺失场景。
3. 直接删除后端兼容接口会扩大到 API 契约、历史数据迁移和测试口径调整，应作为独立迁移/封存任务推进。

## 文档同步

- `README.md`：同步为单一正式工作台入口、模块说明和当前前端目录结构。
- `ARCHITECTURE.md`：同步 UI 架构图、前端目录、legacy 后端执行层边界。
- `docs/产品重构蓝图.md`：将旧 `ProductionMode` 拆分表述更新为“防止正式工作台重新形成巨型组件”。
- `docs/产品重构实施方案.md`：同步禁止事项。
- `docs/产品重构阶段任务与验收标准.md`：加入旧节点执行层前端残留清理验收口径。

## 后续建议

1. 对 `/api/workflows*`、`/api/nodes*`、`/api/runs*` 做后端兼容层专项：统计真实调用、测试依赖、历史数据体量，再决定封存、只读化或删除。
2. 为正式工作台建立“禁止导入 legacy node UI/type”的轻量守卫，可放在源码扫描脚本或 E2E 前置检查中。
3. 继续保留 `/api/prototyping/*` 中正式工作台仍使用的创意任务接口，待创作画布领域接口收敛后再迁移。
