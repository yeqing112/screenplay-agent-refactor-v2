# 智能导演台主动汇报与项目驾驶舱方案

日期：2026-09-07  
状态：需求基线，进入 Phase 1 实施

## 1. 产品定位

智能导演台不是“等待用户提问的聊天机器人”，而是一个持续观察项目、解释项目状态、发现风险并在必要时请求确认的项目助理。

用户可以自由对话、上传图片和文档。普通问答、分析、识图、建议和进度汇报直接完成；只有会改变项目或产生外部成本的动作才进入确认门槛。

## 2. 运行分层

```text
项目事实层 → 状态与风险判断层 → Agent 回复/汇报层 → 动作提案与确认层
```

- 项目事实层：剧本、分镜、资产、Prompt Version、QA、生成任务、导出和锁定状态。
- 状态与风险判断层：确定性规则先判断完成度、阻塞、失败、过期和待处理项；LLM 只在证据完整时负责解释、排序和提出建议。
- Agent 回复/汇报层：生成自然语言答复、进度汇报、问题说明和完成/失败通知。
- 动作提案与确认层：修改、覆盖、提交生成或其他外部付费动作生成结构化提案，等待用户确认后执行。

## 3. 统一输出类型

| 类型 | 用途 | 是否需要用户确认 |
| --- | --- | --- |
| `answer` | 普通问答、识图、解释和创作建议 | 否 |
| `progress` | 项目阶段、完成数量、当前工作和下一步 | 否 |
| `issue` | 质量问题、失败、缺失、冲突和阻塞 | 否（查看/分析） |
| `recommendation` | 建议优先处理的事项 | 否 |
| `action_proposal` | 修改、覆盖、生成、提交等副作用动作 | 是 |
| `completion` | 任务完成、结果回填和链路收口 | 否 |
| `failure` | 任务失败、原因和恢复路径 | 否 |

## 4. 主动汇报触发器

- 生成任务完成、失败、超时或需要回收。
- QA 新增问题、问题升级为阻塞或修复后重新通过。
- 资产、参考图、Prompt Version 或镜头锁定状态发生变化。
- 连续性检查发现相邻镜头冲突。
- 项目阶段或主链路完成度发生变化。
- 用户重新打开项目、恢复会话或进入工作台时进行一次状态摘要。
- 后台周期性检查发现新的阻塞项。

同一事实在没有变化时不得重复打扰用户。汇报使用 `dedupe_key + evidence_fingerprint` 去重；事实变化后才产生新的汇报。

## 5. `AgentProjectUpdate` 契约

```text
id
book_id
type: progress | issue | recommendation | action_proposal | completion | failure
severity: info | warning | blocking | critical
title
message
source_refs
evidence_fingerprint
action_proposal
requires_confirmation
status: unread | acknowledged | resolved | dismissed | snoozed | expired
dedupe_key
created_at
updated_at
```

每条汇报必须能追溯到来源对象和证据快照；证据过期时，相关动作提案自动失效，不允许按旧状态执行。

## 6. 用户界面

- 右侧抽屉内直接显示自然对话和“项目动态”，不再要求用户点击“预览 AI 分析”才能得到普通回复。
- 抽屉入口显示未读数量；项目顶部显示一句当前状态摘要。
- 任务中心同步显示阻塞事项、失败事项和待确认动作，但不复制完整聊天内容。
- 普通进度、问题和建议使用自然语言消息；需要副作用时才显示动作确认卡。
- 证据、指纹、模型和审计详情默认折叠，供需要追溯的用户查看。
- 支持“已知悉 / 稍后提醒 / 去处理”；`critical` 阻塞不能被静默为已解决。
- “去处理”先记录 Agent 的承接确认，再打开正式工作台；任务中心在工作台完成前仍显示“已确认，待工作台处理”，避免把意图误报为生产完成。

## 7. 权限与安全

- 只读分析和主动汇报可自动执行，不需要用户确认调用 Agent 模型。
- 修改剧本、资产、分镜、Prompt Version、覆盖版本、提交生图/生视频和外部付费任务必须确认。
- Agent 不能绕过服务端 DecisionPacket、资产锁定、证据指纹、预算、版本和回滚门禁。
- 汇报内容不得凭空推断；证据不足时必须明确标记“需要更多信息”。
- 所有汇报、确认、执行和失败都进入审计日志，可回放。

## 8. 实施阶段

1. 新增 `AgentProjectUpdate` 持久化模型、迁移、状态机和去重规则。
2. 建立项目事实采集器与确定性进度/风险检测器。
3. 增加汇报查询、确认、已读、稍后提醒和事件流 API。
4. 将自由对话接入 Agent 回复；普通分析直接返回，不再经过旧的预览确认流程。
5. 改造智能导演台抽屉和任务中心，接入未读、动态和动作卡。
6. 使用只读 SSE 推送，保留轮询作为浏览器、代理或开发环境回退。
7. 完成后端、前端、业务回归和真实浏览器验收。

## 9. 验收标准

- 新任务完成或失败后，项目动态能产生一条可追溯汇报且不重复刷屏。
- 用户发送普通问题或图片后直接得到自然语言回复，不出现“先预览/确认调用”的技术流程。
- 问题汇报能指出影响对象、严重程度和下一步。
- 修改或生成类请求显示确认卡；未确认不能产生副作用。
- 证据变化后旧提案变为过期，确认执行会被服务端拒绝。
- 抽屉、任务中心和审计回放显示同一条汇报的统一状态。
- SSE 连接只读取已持久化动态，不会自行创建汇报；无新事件时以心跳关闭并由客户端重连，连接失败自动回退轮询。
