# 2026-07-29 创作画布恢复后继续创作动作验收记录

## 目标

把 `创作画布 Beta` 从“恢复调度面”继续往前推进，验证恢复横幅不只会引导跳转，还能直接接住下一步创作动作。

本轮重点：

1. 在 `closed` 恢复态下，画布横幅直接出现 `继续生成视频` / `继续生成首帧` / `重编后生成首帧` / `重编后继续生成视频` 这类动作
2. 至少验证其中一条动作可以在真浏览器里真正触发

## 本轮实现

新增恢复后继续创作动作推导规则：

- `frame + closed` -> `继续生成视频`
- `prompt + closed`
  - 若已有首帧 -> `继续生成视频`
  - 若还没有首帧 -> `继续生成首帧`
- `reference + closed`
  - 若已有首帧 -> `重编后继续生成视频`
  - 若还没有首帧 -> `重编后生成首帧`
- `video + closed` -> 不再额外给继续创作动作

同时在恢复横幅中新增：

- `继续创作建议`
- 对应动作按钮

## 真浏览器验收

### 场景：首帧恢复已收口后，直接继续生成视频

受控写入恢复上下文：

```json
{
  "section": "canvas",
  "canvasNavigationTarget": {
    "episode": 1,
    "shotId": "1",
    "recoveryKind": "frame"
  }
}
```

页面实际结果：

1. 出现 `恢复链路已收口`
2. 出现 `继续创作建议`
3. 出现动作按钮 `继续生成视频`

### 点击动作后的真实行为

浏览器中对以下接口做拦截式验收，避免触发真实付费模型：

- `POST /api/books/14/storyboard/1/1/generate-video`
- `GET /api/prototyping/tasks/canvas-continue-video-001`

验收结果：

1. 点击 `继续生成视频` 后，请求真实发出
2. 请求体里携带：
   - `generationChain: "canvas_recovery_continue_after_frame"`
3. 页面出现成功回显

### 场景：提示词恢复已收口后，直接继续生成首帧

受控写入恢复上下文：

```json
{
  "section": "canvas",
  "canvasNavigationTarget": {
    "episode": 1,
    "shotId": "4",
    "recoveryKind": "prompt"
  }
}
```

页面实际结果：

1. 出现 `恢复链路已收口`
2. 出现动作按钮 `继续生成首帧`

点击后的请求结果：

1. 真实发起 `generate-frame`
2. 请求体里携带：
   - `generationChain: "canvas_recovery_continue_after_prompt"`
3. 页面出现成功回显

### 场景：参考资源恢复已收口后，重编后继续生成视频

受控写入恢复上下文：

```json
{
  "section": "canvas",
  "canvasNavigationTarget": {
    "episode": 1,
    "shotId": "1",
    "recoveryKind": "reference"
  }
}
```

页面实际结果：

1. 出现 `恢复链路已收口`
2. 出现动作按钮 `重编后继续生成视频`

点击后的请求结果：

1. 先真实发起 `compile-prompts/async`
2. 编译请求体里携带：
   - `compileReason: "canvas-recovery-reference-before-video"`
3. 随后真实发起 `generate-video`
4. 视频请求体里携带：
   - `generationChain: "canvas_recovery_recompile_then_video"`
   - `triggeredByPromptRecompile: true`
5. 页面出现成功回显

### 本轮补充追溯增强

当前恢复横幅直接触发的继续创作动作，已经不再沿用普通画布链路名，而是改为显式恢复来源链路，例如：

- `canvas_recovery_continue_after_frame`
- `canvas_recovery_continue_after_prompt`
- `canvas_recovery_recompile_then_video`

这样任务中心、运行摘要和后续审计可以明确区分：

- 普通画布生成
- 恢复收口后继续生成

## 验收结论

本轮通过。

当前 `创作画布 Beta` 已经从“恢复后告诉你去哪”继续推进到“恢复后直接在画布里继续创作”。虽然现在只接住了第一批最小连续动作，但方向已经对了，且真实浏览器行为成立。
