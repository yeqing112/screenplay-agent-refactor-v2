# MiMo 前缀缓存优化方案与执行记录

## 目标

针对 `mimo-v2.5` 输入缓存命中为 0 或偏低、重复调用成本高的问题，把 Prompt Compiler 和智能导演台的请求组织成可复用的稳定前缀，并让系统能够用供应商真实返回值验证效果。

本方案只依赖 MiMo 已公开的 OpenAI 兼容协议：请求仍使用 `chat/completions`；不猜测或强行发送未经验证的 `cache_control`、`prompt_cache_key` 等私有字段。MiMo 官方接口返回 `usage.prompt_tokens_details.cached_tokens`，该字段作为命中率的唯一运行时证据。

## 现状审查

- 当前默认文本模型为 `mimo-v2.5`。
- `core/llm.py` 每次使用新的 `system + user` 请求，仅读取 `total_tokens`，没有记录 `cached_tokens`、提示词 Token 数和延迟。
- Prompt Compiler 的通用规则和镜头证据已经放在同一请求中，但镜头专属 `candidate_delivery_contract`、连续性修订内容此前被拼入 system prompt，导致不同镜头从 system 层就产生分叉。
- DecisionPacket 已对相同证据包的草案做业务层去重；底层 LLM 客户端不应擅自复用非幂等响应，因此本阶段先做指纹和遥测，业务去重继续由证据包层负责。
- Agent 当前运行策略的思考开关与缓存无关；是否关闭思考必须由用户在 Agent 设置中决定，不能以缓存优化为理由自动修改。

## 目标请求结构

每次请求按以下顺序组织：

1. **L0 全局稳定规则**：固定 system prompt、输出 JSON 约束、资产引用规则、禁止项。
2. **L1 项目稳定事实**：项目风格与已批准的全局设定；不把无关资产全文塞进每个镜头。
3. **L2 集/版本稳定事实**：当前批准剧本、版本号、集级资产快照。
4. **L3 当前任务动态后缀**：镜头证据、绑定资产、连续性合同、修复要求、镜头号和用户临时指令。

任何版本变更都创建新的缓存分支，不改写历史版本。与缓存无关的时间戳、请求 ID、随机值不得出现在 L0–L2。

## 已实施（Phase 0/1）

### 1. 稳定 Prompt Compiler system 前缀

- 将镜头专属 delivery contract 从 system prompt 移到 user prompt 末尾的动态任务区。
- 将连续性修订说明和 `repair_request` 从 system 前缀移到动态任务区；system 只保留“遇到 REVISION MODE 时遵循任务要求”的固定规则。
- Prompt 上下文采用 canonical JSON（UTF-8、`sort_keys=True`、固定分隔符），减少同义 JSON 的字节差异。

### 2. LLM 请求遥测

每次外部调用的非敏感审计记录新增：

- `prompt_tokens`
- `cached_tokens`
- `completion_tokens`
- `total_tokens`
- `cache_hit_rate`
- `latency_ms`
- `request_fingerprint`

供应商未返回缓存明细时记录 `null`，不伪造为 0。现有审计仍只保存哈希和长度，不保存密钥、完整提示词或完整响应。

### 3. 公共缓存工具

新增 `core/prompt_cache.py`，提供 canonical JSON、请求指纹和兼容 OpenAI/MiMo 的 usage 解析。它不改变模型选择，不触发外部调用。

## 后续阶段

### Phase 2：业务去重与分支复用

- 以 `model_profile_id + 参数快照 + evidence_fingerprint + prompt_fingerprint` 作为草案去重键。
- 仅对已确认、幂等的“候选草案”复用成功结果；资产写入、Prompt Version 写入、图片/视频生成不允许直接复用绕过确认。
- 证据指纹变化时旧草案标记过期，不把旧结果伪装成当前版本。

#### 本轮推进（2026-09-10）

- Agent 草案预览现在把安全模型参数（模型、温度、thinking、JSON response format 等）纳入 `request_fingerprint`；同一项目只有在证据、计划和请求身份全部一致时才复用成功草案。
- Agent 对话与草案调用统一采集供应商返回的输入/缓存/输出 Token、命中率、延迟和请求指纹；审计只保存指纹与汇总，不保存密钥或完整提示词。
- 资产语义治理与可拍性拆镜 LLM 调用接入同一遥测回调；资产重复请求会校验冻结证据与请求身份，不再仅凭“已有草案”复用。
- `agent_audit_logs` 新增 `request_fingerprint`、`llm_usage` 字段，并由迁移 `c6f7a8b9c0d1` 创建索引；旧审计记录保持可读但不会被错误地当作新请求的幂等命中。

### Phase 3：真实命中率灰度

用同一模型、同一稳定前缀、仅改变末尾任务的两次请求做小样本验证：

1. 首次请求应允许 `cached_tokens` 为 0。
2. 第二次请求检查 `cached_tokens / prompt_tokens`。
3. 修改项目/集版本后应产生新分支，不能要求旧前缀继续命中。
4. 若供应商不返回明细，报告“不可观测”，不将其当作命中或未命中。

#### 首次真实灰度（2026-09-10）

- 已在用户明确确认后，对当前默认 `mimo / mimo-v2.5` 执行两次最小请求；两次仅改变动态任务尾部，未写入任何项目数据或生成媒体。
- 两次均 HTTP 200；供应商返回 `prompt_tokens=4526`、`cached_tokens=2240`、`completion_tokens=14`、`total_tokens=4540`，累计缓存命中率 `49.4918%`，缓存明细可观测。
- 该数值仅代表本次样本，不是 SLA；首次请求可能为 0 命中，事实/版本变化必须切换缓存分支。报告：`artifacts/mimo-prefix-cache-gray-20260910.json|md`。

### Phase 4：成本可视化与门禁

- Agent 高级审计回放已显示最近调用的命中率、输入/输出 Token 与延迟；新增只读 `GET /api/agent/usage-summary`，支持按项目汇总跨会话用量，抽屉回放区已展示该摘要。
- 任务中心级别的统一成本汇总仍待补齐。
- 估算成本需要各供应商费率配置后再展示，当前不根据未知费率猜测金额。
- 命中率偏低只产生诊断和优化建议，不自动切换模型、不自动关闭思考、不自动重试计费请求。
- 连续失败或供应商拒绝缓存字段时回退普通 OpenAI 兼容请求，并保留审计。

## 验收标准

- 未授权时不产生外部调用。
- 相同证据包不重复生成候选草案。
- Prompt Compiler 的 system prompt 在不同镜头之间保持相同；镜头专属合同只出现在动态后缀。
- 单元测试覆盖 canonical JSON、指纹、MiMo `cached_tokens` 解析及缺失字段安全处理。
- 真实灰度报告同时给出命中率和“不可观测”状态；不以营销数据作为 SLA。

## 当前边界

- 当前实现已完成“缓存友好请求 + 遥测”，尚未把供应商缓存命中率承诺为固定数值。
- 真实 MiMo 灰度需要用户明确确认，因为会产生计费调用。
- Agent 思考开关仍按现有独立策略生效，与缓存优化分开治理。

## Prompt Compiler 复测补充（2026-09-11）

- 对证据完整样本 `990301 / 第1集 / 镜头1` 连续完成两次真实 `mimo-v2.5` clone-only 调用，均通过 after-audit，且均在临时克隆上回滚清理。
- 第二次调用返回 `prompt_tokens=28841`、`cached_tokens=28800`，命中率 `99.8578%`，验证 Prompt Compiler 当前稳定前缀确实可被供应商复用。
- 这是单样本、单时间窗口的观测值；在切换模型、修改模板、变更事实/版本后必须重新观测，不将命中率写死为质量或成本承诺。

## 多样本动态后缀观察补充（2026-09-11）

- 对共享同一稳定场景/人物资产、仅改变动态镜头证据的 3 个请求完成真实灰度，均通过审计且无 fallback。
- 聚合输入 `87,052` tokens、缓存 `12,288`，命中率 `14.1157%`；每个请求约命中 `4,096` tokens。相同完整请求重复时仍可达到约 `99.8578%`，但不同动态后缀不能复用全部上下文。
- 结论：当前稳定前缀组织已按公开协议实现并可观测，但供应商对跨请求缓存有窗口/粒度限制；不添加未经文档确认的私有字段，不把观测值承诺为 SLA。
