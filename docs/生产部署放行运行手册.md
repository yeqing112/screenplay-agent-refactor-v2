# 生产部署放行运行手册

日期：2026-09-12

本手册只描述部署放行，不改变本地开发默认配置。生产或预发布环境必须先通过配置门禁，再开放正式工作台。

## 1. 必需配置

在部署环境注入密钥，不提交到仓库：

```text
DEPLOYMENT_ENV=production
API_AUTH_ENABLED=true
API_AUTH_ROLE_TOKENS={"viewer":"<32+ chars>","editor":"<32+ chars>","admin":"<32+ chars>"}
API_CORS_ORIGINS=https://studio.example.com
API_RATE_LIMIT_ENABLED=true
API_RATE_LIMIT_REQUESTS=120
API_RATE_LIMIT_WINDOW_SECONDS=60
API_RATE_LIMIT_DISTRIBUTED_ASSERTED=true
ENABLE_LEGACY_NODE_API=false
PUBLIC_ASSET_STORAGE_PROVIDER=qiniu
QINIU_PUBLIC_BASE_URL=https://cdn.example.com
QINIU_ACCESS_KEY=<secret>
QINIU_SECRET_KEY=<secret>
QINIU_BUCKET=<bucket>
```

生产对象存储地址必须是稳定 HTTPS 域名；临时 `clouddn.com` 域名只能用于灰度。
配置校验会拒绝 `<secret>`、`<32+ chars>`、`<bucket>`、`replace-me` 等模板占位值，以及 `localhost`/`example.com`/`example.org` 示例域名；部署前必须替换为真实值。

## 2. 放行顺序

推荐使用统一门禁入口；它会运行全部步骤，即使前一步失败也不会短路，并在 `artifacts/` 生成 JSON/Markdown 报告：

```powershell
npm run gate:production
```

该入口返回非零即表示仍不可放行。需要单独定位时，可按以下顺序运行各步骤：

```powershell
npm run config:verify:production
npm run validate:sample-registry
npm run audit:shot-planning:gate
npm run audit:storyboard:zero-error-gate
npm run check:production
npm run e2e:real-samples:release
```

任一步骤失败都不得放行。统一门禁还会运行生产专用真浏览器回归；当前 `production-sample-registry.json` 只有 1 个真实项目、3 个真实镜头，尚未满足 3 项目 / 30 镜头质量门禁。

`validate:sample-registry` 的 `available_candidates` 字段只读列出已具备剧本和镜头证据、但尚未注册的项目；登记前仍需人工确认其确为真实生产样本，工具不会自动激活项目。

登记真实样本时使用受控命令。默认只做预览；只有显式确认字符串才会原子更新注册表：

```powershell
npm run register:production-sample -- --book-id <book-id>
npm run register:production-sample -- --book-id <book-id> --confirm REGISTER_PRODUCTION_SAMPLE
```

该命令只登记已有数据库证据的项目，不创建、复制或修改镜头；已退休项目还必须额外提供 `--unretire`。

## 3. 备份与恢复演练

```powershell
npm run backup:database -- --output <backup-path>
npm run verify:database-restore -- --backup <backup-path>
```

备份应写入独立磁盘或异地对象存储；恢复演练使用临时数据库，不会覆盖线上库。部署环境应由 Windows Task Scheduler、cron 或等价调度器定期执行，并保留成功/失败日志。

可用时间戳调度入口接入系统任务调度器；它不会覆盖或删除旧备份：

```powershell
npm run backup:database:scheduled -- D:\Backups\screenplay
npm run backup:database:scheduled:restore-drill
```

定时入口使用跨平台 Node 转发；Windows npm 可能吞掉未知长参数，因此恢复演练使用独立的 `:restore-drill` 命令。该命令只负责本地创建与校验，异地复制、保留周期和告警由部署环境配置；生产仍需完成一次真实调度与恢复演练。

## 4. 反向代理最低要求

- 终止 TLS，仅向 API 转发 HTTPS 流量。
- 仅允许明确的前端 Origin；禁止生产通配符 CORS。
- 将认证 Token 通过安全的服务端注入机制提供给前端或调用方，不能写入公开构建产物。
- 在代理层配置分布式限流；应用层 `API_RATE_LIMIT_*` 只是单进程兜底。只有共享/反向代理限流实际部署完成后，才允许设置 `API_RATE_LIMIT_DISTRIBUTED_ASSERTED=true`；它是放行声明，不会自行提供分布式能力。
- 限制上传请求体大小、超时和允许的方法；保留 `/health` 与 CORS 预检可达。
- 正式部署关闭旧执行层：`ENABLE_LEGACY_NODE_API=false`。

## 5. 上线后抽查

1. 未携带 Token 的 `/api/*` 请求返回 `401`。
2. viewer Token 的写入请求返回 `403`，editor/admin 按策略放行。
3. 超过限额返回 `429` 与 `Retry-After`。
4. 健康检查、CORS 预检、正式工作台主链路可用。
5. 备份文件可通过恢复演练完整性校验。
6. 外部图片/视频调用仍要求页面显式确认，不因代理或调度器绕过门禁。
