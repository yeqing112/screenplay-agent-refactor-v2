本轮真实灰度暴露并修复的问题：

1. clone fidelity 问题：`book 3` 源结构存在人物资产 id，但克隆脚本在无法映射旧 id 时把 `character_asset_ids` 清空，造成 clone-only 灰度出现源项目没有的人物资产 warning。已修复为：可映射则映射，不可映射但源结构已有值则保留，并同步保留 `character_blocking.character_id`。
2. 真实 LLM 润色残留导演句式：`book 14` 的 mimo 修复候选曾输出 `镜头推进为...` 这类标签化句式，被诊断正确拦截。已新增 `sanitize_machine_prompt_text()`，并在 Prompt Compiler 接收 LLM 首次输出与 repair 输出后、诊断前统一清洗。
3. 复合场景名误报：`水房·清晨` 被真实提示词写作“寺庙后院水房……清晨……”，旧规则要求整串连续包含，导致 `scene_name_not_in_static_prompt` 误报。已升级为复合场景名分词匹配，同时同步 JS 全量审计与 Python clone 灰度审计。
4. 灰度报告口径不足：原报告只统计脚本级 `after_audit` warning，没有展开 API `compiler_diagnostics` warning。已补 `compiler_diagnostics_summary` 和 Markdown 摘要，后续可区分“外层审计 warning”和“编译器诊断 warning”。
