# 2026-07-21 分镜提示词版本审计与恢复建议能力补充记录

## 本次补充目标

在已经完成“关键绑定资产门禁”和“真实自动绑定补全”之后，继续补齐生产现场恢复能力：

- 不只允许人工回滚
- 还要让系统能识别当前 prompt version 是否疑似跑偏
- 并在版本列表中给出可恢复版本建议

## 本次实现

### 1. 修复 prompt-versions 的旧版本诊断口径

文件：`api/server.py`

调整点：

- `get /api/books/{book_id}/storyboard/{episode}/{shot_id}/prompt-versions`
  在刷新旧版本运行态时，不再错误复用当前 shot 的 `visual_prompt_static` / `visual_prompt_motion`
- 改为对每个版本使用：
  - 该版本自己的 `prompt_static`
  - 该版本自己的 `prompt_motion`

这样版本审计结果才真正对应“那一版自己”，而不是被当前镜头内容污染。

### 2. 修复 prompt-versions 的自动绑定种子过瘦问题

文件：`api/server.py`

版本列表刷新旧版本上下文时，现在也补齐：

- `dialogue`
- `start_state`
- `end_state`
- `duration`
- `camera_angle`
- `camera_movement`
- `transition`

避免版本审计阶段再次出现“人物/道具在真实文本里存在，但旧版本上下文没绑定出来”的假阴性。

### 3. 新增版本健康审计

文件：`api/server.py`

新增：

- `_build_storyboard_prompt_version_audit(...)`
- `_recommend_storyboard_restore_version(...)`

每个版本现在会额外给出：

- `critical_bound_assets`
- `missing_critical_assets`
- `missing_critical_count`
- `used_asset_names`
- `used_asset_types`
- `failed_check_keys`
- `is_scene_only_candidate`
- `is_recoverable_version`
- `is_degraded_version`

### 4. 新增恢复建议

接口：

- `GET /api/books/{book_id}/storyboard/{episode}/{shot_id}/prompt-versions`

新增返回：

- `recommended_restore_version`

推荐规则分两层：

1. 若存在“可恢复版本”
   - 即没有缺失关键绑定资产
   - 不是 scene-only
   - 不是 blocked
   - 取最新一版

2. 若不存在完全健康版
   - 则推荐“比当前更接近正确状态”的旧版本
   - 优先缺失关键资产更少的版本
   - 再按版本号取更新者

返回的 `reason` 目前包括：

- `latest_recoverable_version`
- `best_partial_recovery_version`

### 5. 新增推荐恢复执行入口

接口：

- `POST /api/books/{book_id}/storyboard/{episode}/{shot_id}/prompt-versions/recommended-rollback`

行为：

- 服务端先实时计算 `recommended_restore_version`
- 若当前没有推荐恢复版本，则返回 `409`
- 若存在推荐版本，则直接复用原有 rollback 流程
- 返回中额外带上：
  - `recommended_restore_version`
  - `restored_from_version`

这样前端或验收工具不再需要：

1. 先请求版本列表
2. 再手动取出版本 id
3. 再拼单独的 rollback 请求

而是可以直接走“按推荐版本恢复”的链路。

### 6. 主输出链路补充恢复摘要

接口：

- `GET /api/pipeline/book/{book_id}/outputs`

现在每个 storyboard shot 直接返回：

- `prompt_version_audit`
- `recommended_restore_version`

这意味着前端主工作台、任务中心、分镜验收页不需要再额外请求一次 `prompt-versions`，
就可以直接知道：

- 当前提示词版本是否 degraded
- 是否是 scene-only 退化
- 缺了哪些关键绑定资产
- 当前建议恢复到哪一版

## 自动化回归

### 新增 / 更新测试

文件：

- `tests/test_storyboard_prompt_compile.py`
- `tests/test_storyboard_prompt_compile_repair.py`
- `tests/test_storyboard_structure.py`

覆盖点：

1. 当前版本跑偏为 scene-only 时，版本列表会识别其为 degraded
2. 当存在更健康旧版本时，接口会返回 `recommended_restore_version`
3. 版本审计不会再错用当前 shot 的提示词去评估旧版本
4. 结构层和编译层回归继续覆盖“从 `end_state` / `dialogue` 自动绑定人物”的真实事故路径
5. 推荐恢复接口会真正把镜头恢复到系统建议的版本，而不是只返回建议对象
6. `/outputs` 主链路会直接暴露版本健康摘要与恢复建议

## 真实本地数据验证

对象：

- `book_id = 14`
- `episode = 1`
- `shot_id = 1`

调用：

```text
GET /api/books/14/storyboard/1/1/prompt-versions
```

真实结果：

- `current_version = 11`
- `recommended_restore_version = { version: 9, reason: "best_partial_recovery_version" }`

版本健康差异：

- `v11`
  - `missing_critical_count = 4`
  - `is_scene_only_candidate = true`
  - 缺失：`和尚丙 / 和尚乙 / 和尚甲 / 木桶`
- `v10`
  - `missing_critical_count = 4`
  - `is_scene_only_candidate = true`
  - 缺失：`和尚丙 / 和尚乙 / 和尚甲 / 木桶`
- `v9`
  - `missing_critical_count = 1`
  - `is_scene_only_candidate = false`
  - 仅缺失：`木桶`

说明系统已经能够：

- 识别当前版本是否严重跑偏
- 判断它是不是典型的 scene-only 退化版本
- 在不存在“完美版本”时，仍给出更合理的部分恢复建议

补充调用：

```text
GET /api/pipeline/book/14/outputs
```

在 `episode = 1 / shot_id = 1` 的真实返回中，已经直接包含：

- `prompt_version = 11`
- `prompt_version_audit.is_degraded_version = true`
- `prompt_version_audit.is_scene_only_candidate = true`
- `recommended_restore_version = { version: 9, reason: "best_partial_recovery_version" }`

说明这套能力已经进入主输出链路，而不只是存在于版本查询接口里。

本次对真实数据保持只读验证，没有直接对 `book 14 / shot 1` 执行恢复写操作。
推荐恢复执行链路通过自动化测试做强验证，避免为了验收而改动真实现场版本栈。

## 当前意义

这次补充不是最终修复提示词质量本身，而是把“生产现场怎么读懂版本栈、怎么恢复”补得更可用。

对当前项目的直接价值：

- 验收时不再只能肉眼翻版本
- 跑偏版本能被更快定位
- 回滚决策开始有机器辅助依据
- 已具备“推荐一键回滚”的后端基础
- 主工作台链路已经能直接读到恢复建议
- 为后续前端接入推荐恢复按钮留出了稳定基础
