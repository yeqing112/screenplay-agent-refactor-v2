# 2026-08-27 导出草稿人工临时修改边界验收记录

## 背景

机器提示词历史快照已经可以恢复为 WebUI 临时草稿，但真实生产里还会出现最后一公里微调：用户在粘贴到第三方 WebUI 前，需要临时调整最终机器提示词字段。这个修改不能反向污染导演分镜语言、Shot Schema 或 Prompt Version，否则会把“交付前微调”误变成“结构事实改写”。

## 本轮改动

- 在机器提示词导出预览的高级区新增 `临时编辑最终 WebUI 草稿`。
- 支持临时编辑：
  - H3 `integrated_multimodal_description`
  - H3 `overall_soundscape`
  - H3 `non_diegetic_music`
  - 通用中文视频 WebUI `prompt`
- 新增 `应用到临时草稿`：
  - 只更新当前前端导出预览对象。
  - 复制 H3 全字段、Markdown / CSV / API JSON 下载会使用临时修改后的字段。
  - 页面显示 `人工临时修改` 状态徽章。
- 新增 `撤销临时修改`：
  - 回到本次加载或历史恢复的基线草稿。
- 新增纯函数：
  - `buildMachinePromptTemporaryDraftFields(...)`
  - `applyMachinePromptTemporaryDraft(...)`

## 安全边界

- 不 PATCH 导演分镜语言。
- 不更新 Shot Schema。
- 不创建或回滚 Prompt Version。
- 不提交生成 API。
- 不把临时修改写入历史导出记录；后续如需持久化，应设计为独立 draft record。

## 当前边界

- 临时修改只存在于当前页面状态，刷新页面后需要重新加载/恢复并编辑。
- 保存导出记录仍调用后端重新生成当前镜头快照，不会把人工临时修改写入历史。
- 还未接入 API 提交独立任务链路。

## 后续建议

1. 如果用户需要保留人工临时修改，应新增独立 `machine_prompt_export_draft` 记录，而不是复用正式导出记录。
2. API 提交应作为独立任务链路接入任务中心，默认仍为 `api_submission=false`。
3. 后续可补“导出前差异视图”，让用户看清临时草稿相对机器编译结果改了哪些字段。
