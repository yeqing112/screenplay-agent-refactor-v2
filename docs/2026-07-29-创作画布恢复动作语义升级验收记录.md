# 2026-07-29 创作画布恢复动作语义升级验收记录

## 目标

把 `创作画布 Beta` 的恢复横幅从“泛跳转按钮”继续推进成“更接近创作动作的下一步入口”。

本轮不改恢复链路本身，而是改用户看到的动作语义：

- `closed` 场景不再只显示 `前往镜头工作台`
- `missing` 场景不再只显示 `前往镜头工作台 / 回任务中心`

而要让按钮更像真实创作动作。

## 本轮改动

新增恢复动作文案生成规则：

1. `pending / syncing`
   - `tasks` 按钮显示为 `继续回收任务`
2. `closed`
   - `storyboard` 按钮显示为 `继续当前镜头创作`
   - `assets` 按钮显示为 `继续当前资产创作`
   - 辅助文案明确提示：应继续创作，而不是停留在恢复说明里
3. `missing`
   - `tasks` 按钮显示为 `回任务中心确认`
   - `storyboard` 按钮显示为 `检查当前集镜头`
4. `refocus`
   - 在已命中恢复目标时，按钮文案升级为 `回到恢复节点`

## 真浏览器验收

### 场景 A：closed 恢复态

通过本地恢复上下文写入：

```json
{
  "section": "canvas",
  "canvasNavigationTarget": {
    "episode": 1,
    "shotId": "1",
    "recoveryKind": "frame"
  }
}
```

页面结果：

- 出现 `恢复链路已收口`
- 出现 `继续当前镜头创作`
- 辅助文案出现“下一步应直接回到镜头或资产继续创作”

### 场景 B：missing 恢复态

通过本地恢复上下文写入：

```json
{
  "section": "canvas",
  "canvasNavigationTarget": {
    "episode": 1,
    "shotId": "999",
    "taskId": "missing-task-001",
    "recoveryKind": "frame"
  }
}
```

页面结果：

- 出现 `暂未定位到恢复目标`
- 出现 `回任务中心确认`
- 出现 `检查当前集镜头`

## 验收结论

本轮通过。

创作画布的恢复横幅已经不再只是“告诉用户去哪里”，而是开始用更接近真实创作流程的动作语言引导下一步。这是从“恢复调度面”走向“继续创作面”的一个小但正确的推进。
