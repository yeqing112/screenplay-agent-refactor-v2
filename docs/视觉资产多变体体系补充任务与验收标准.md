# 视觉资产多变体体系补充任务与验收标准

## 1. 目标

本补充计划用于把人物、场景、道具统一从“单资产模型”升级为“主档案 + 多变体 + 多参考图 + 镜头显式绑定”的正式生产模型。

该补充计划默认并入：

- `Phase 6：资产中心重构`
- `Phase 7：提示词编译体系重构`

不另起孤立模块，而是直接作为蓝图主链路中的补强任务执行。

---

## 2. 统一建模任务

### 2.1 主档案层

为三类资产统一建立主档案：

- `Character Master`
- `Location Master`
- `Prop Master`

主档案只承载稳定识别信息，不直接等于镜头最终引用状态。

### 2.2 变体层

为三类资产统一建立变体层：

- `base_identity`
- `episode_default`
- `scene_variant`
- `shot_variant`

每个变体至少支持：

- `scope_type`
- `episode_start / episode_end`
- `story_phase`
- `state_tags`
- `priority`
- `is_default`

### 2.3 参考图层

每个变体支持多张参考图，并区分：

- `candidate`
- `selected`
- `locked`
- `detail_support`

### 2.4 镜头绑定层

镜头必须显式绑定到某个具体变体，不能只绑定到主资产名称。

统一命中优先级：

1. 显式绑定变体
2. `shot_variant`
3. `scene_variant`
4. `episode_default`
5. `base_identity`

---

## 3. 人物资产补充任务

### 3.1 多变体支持

同一人物至少支持：

- 跨集默认造型
- 剧情阶段变化
- 服装变化
- 发型变化
- 妆容 / 情绪变化
- 身体状态变化

### 3.2 权威提示词保护

每个人物变体都必须保留：

- `confirmed_prompt_raw`
- `structured_variant_fields`
- `rendered_prompt_preview`

禁止系统用模板重渲染结果覆盖用户确认过的定妆原文。

### 3.3 人物验收标准

1. 同一人物可存在多套跨集、跨阶段、跨状态变体
2. 镜头页可直接看出绑定的是哪一个人物变体
3. 同一人物跨镜头换装或状态变化时，提示词能稳定切换到正确变体
4. 删除某变体主参考图后，相关镜头 readiness 实时更新

---

## 4. 场景资产补充任务

### 4.1 多变体支持

同一场景至少支持：

- 白天 / 夜晚
- 晴天 / 雨天 / 雾天
- 冷光 / 暖光 / 自然光
- 常态 / 混乱 / 破坏后
- 不同剧情阶段痕迹

### 4.2 权威提示词保护

每个场景变体都必须保留：

- `confirmed_prompt_raw`
- `structured_variant_fields`
- `rendered_prompt_preview`

禁止只展示摘要字段而丢失完整场景确认稿。

### 4.3 场景验收标准

1. 同一场景可存在多套时间 / 天气 / 光线 / 陈设状态变体
2. 镜头页可直接看出绑定的是哪一个场景变体
3. 跨集或跨状态时，静态提示词能稳定切换到对应场景变体
4. 场景变体参考图删除或切换后，镜头引用状态实时更新

---

## 5. 道具资产补充任务

### 5.1 多变体支持

同一道具至少支持：

- 完整 / 破损
- 干净 / 污损
- 静置 / 使用中
- 附着血迹 / 水渍 / 泥点等剧情痕迹
- 镜头精调用状态

### 5.2 权威提示词保护

每个道具变体都必须保留：

- `confirmed_prompt_raw`
- `structured_variant_fields`
- `rendered_prompt_preview`

### 5.3 道具验收标准

1. 同一道具可存在多套完整度 / 污损 / 使用状态变体
2. 镜头页可直接看出绑定的是哪一个道具变体
3. 道具状态变化时，静态提示词能稳定切换到对应道具变体
4. 道具变体主参考图变更后，镜头 readiness 与引用状态实时更新

---

## 6. 提示词编译补充任务

### 6.1 三层提示词机制

人物、场景、道具统一采用：

1. `confirmed_prompt_raw`
2. `structured_variant_fields`
3. `rendered_prompt_preview`

### 6.2 编译约束

- 静态提示词、运动提示词、人物定妆提示词、场景提示词、道具提示词都必须引用“具体变体”
- 禁止只引用主资产名称或摘要字段
- 编译记录必须可追溯：
  - 主资产
  - 具体变体
  - 参考图
  - 权威原文
  - 渲染预览稿

### 6.3 编译验收标准

1. 用户确认过的原文不会被模板重渲染覆盖
2. 任一镜头都能看见本次编译实际引用的是哪一个人物 / 场景 / 道具变体
3. 同一人物、场景、道具跨状态切换时，编译结果切换稳定
4. QA 问题能追溯到具体变体和具体 prompt version

---

## 7. 前端工作台补充任务

### 7.1 资产中心

必须支持：

- 主档案与变体分层展示
- 每个变体的参考图列表
- 当前默认 / 锁定参考图
- 当前影响镜头列表

### 7.2 镜头工作台

必须支持：

- 显示当前绑定的人物变体
- 显示当前绑定的场景变体
- 显示当前绑定的道具变体
- 显示引用来源是显式绑定还是规则回退

### 7.3 前端验收标准

1. 资产中心能清楚区分主档案和变体
2. 镜头页不再只显示主资产名，而能显示具体变体名
3. 参考图预览、删除、默认、锁定操作都作用于具体变体

---

## 8. 建议执行顺序

1. 先补统一数据模型与前端展示
2. 再补镜头显式绑定与回退优先级
3. 最后补提示词权威原文与渲染预览分离

---

## 9. 完成判定

满足以下条件，可视为该补充计划完成：

1. 人物、场景、道具都完成多变体建模
2. 资产中心可管理主档案、变体、多参考图
3. 镜头工作台可显示具体绑定变体
4. 提示词编译链路不再覆盖用户确认原文
5. QA 与任务中心可追踪到具体变体和具体版本
