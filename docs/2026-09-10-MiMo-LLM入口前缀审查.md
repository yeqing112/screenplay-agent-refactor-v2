# MiMo LLM 入口前缀复用审查

## 目的

在不改变模型选择、不增加供应商私有参数、不绕过显式确认的前提下，检查除 Prompt Compiler 外的 LLM 入口是否能复用稳定前缀，并明确尚未纳入持久化审计的入口。

## 结论

| 入口 | 稳定 system 前缀 | 动态内容位置 | 当前请求指纹/用量审计 | 结论 |
| --- | --- | --- | --- | --- |
| 智能导演台普通对话 | 固定受控助手规则 | user：消息、历史、项目证据、附件 | 已接入 AgentAuditLog；缓存明细按供应商返回记录 | 可跨会话复用规则前缀；历史和证据必须留在动态区 |
| 智能导演台候选草案 | 固定规则 + Skill 版本 | user：冻结 DirectorPlan、附件摘录 | 已接入请求身份去重与用量审计 | 同一 Skill/协议形成缓存分支；Skill 变化必须新分支 |
| 资产语义治理 | 固定规范化规则 | user：资产快照、绑定镜头 | 已接入候选去重与用量审计 | 只对未变化证据复用；锁定事实仍由服务端校验 |
| 可拍性拆镜 | 固定拆镜规则 | user：镜头事实快照 | 已接入用量审计 | 仅保存候选；不能因缓存命中直接写入镜头 |
| Prompt Compiler / 连续性修订 | 固定编译规则 | user：canonical JSON、delivery contract、修订合同 | 已接入真实请求审计与分支指纹 | 当前主链路已满足 L0–L3 分层 |
| 剧本 QA 修复/改写 | 大部分为固定规则 | user：问题片段、QA 证据、修复目标 | 尚未统一持久化请求审计 | 后续纳入共享审计包装器；不得把历史全文放入 system |
| Reader / Outline / Scene Setup | 默认规则可稳定 | user：章节或场景素材 | 尚未统一持久化请求审计 | 优先按任务类型固定 system，证据 canonical JSON 化 |

## 已执行的通用约束

1. `core.prompt_cache` 只提供 canonical JSON、非敏感请求指纹和真实 usage 解析；不发送未经验证的 `cache_control`、`prompt_cache_key` 等供应商私有字段。
2. 供应商不返回 `prompt_tokens_details.cached_tokens` 时记录为不可观测（`null`），不把缺失当作 0 命中。
3. 受控外部调用使用 `json_parse_retries=0`，一次确认只对应一次 provider 请求；解析或传输失败由用户重新确认，不自动追加计费调用。
4. 缓存层只影响请求复用和观测，不改变 DecisionPacket、人工确认、版本写入或媒体生成门禁。

## 后续工作

- 为剧本 QA、改写、Reader、Outline、Scene Setup 建立统一的审计回调适配器，持久化请求指纹、模型安全快照和用量汇总。
- 将这些入口的长上下文拆为稳定任务规则 + canonical JSON 动态证据；任何项目/集/版本变化都创建新的缓存分支。
- 完成后再做两次最小真实 MiMo 灰度：第一次建立前缀，第二次只改动态末尾；需要用户明确确认并以供应商 `cached_tokens` 为唯一证据。
