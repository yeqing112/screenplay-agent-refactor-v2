# User Journey V3

## Primary user

短剧导演、编剧和制片协作成员。用户希望从故事快速推进到可审核的镜头媒体，同时保留人工判断和版本回退能力。

## Journey map

| 阶段 | 用户目标 | 页面 | 主行动 | 成功信号 |
|---|---|---|---|---|
| 1. 选择项目 | 找到要继续的项目 | 项目列表 | 继续制作 | 显示当前阻塞和上次位置 |
| 2. 稳定内容 | 确认原始内容和集数 | 内容准备 | 确认内容基础 | 内容来源、规模、目标集数明确 |
| 3. 锁定方向 | 统一风格、节奏和平台 | 改编方向 | 锁定主方向 | 项目级方向有版本和时间 |
| 4. 完成剧本 | 审阅集级剧本 | 剧本工作台 | 查看证据并锁稿 | 脚本 QA 可解释，版本可回退 |
| 5. 设计镜头 | 把场景转为可执行镜头 | 镜头工作台 | 编辑并审核镜头计划 | 每个镜头有 shot context 和连续性规则 |
| 6. 准备资产 | 补齐人物、场景、道具 | 资产中心 | 绑定或修订资产 | 正式资产可追溯，缺失项可聚合 |
| 7. 生成候选 | 产生图片/视频候选 | 镜头工作台 | 生成候选 | 候选与正式版本分离 |
| 8. 人工审核 | 选择、批注、退回 | 审核抽屉 | 批准 / 退回 / 需要修订 | 记录 reviewer、原因、版本 |
| 9. QA 与交付 | 检查成片并导出 | QA 修复、导出中心 | 处理阻塞并导出 | 导出包显示版本和证据 |

## Required end-to-end journeys

### 创建项目与导入内容

用户从项目列表选择“新建项目”，导入长篇、短篇或已有项目内容，确认章节规模、目标集数和 Production Skill。导入过程显示处理中、失败原因和可恢复动作；完成后进入“改编方向”，不要求用户理解 pipeline task。

### AI 导演

用户在“剧本与导演”查看本集证据、剧情节拍、视觉策略、摄影策略和情绪曲线。系统先生成只读方案，再允许调用已配置模型生成候选。候选进入待审核，用户可以修改、批准或查看历史；批准后才解锁场面调度和镜头规划。

### 分镜审核

用户在 Shot Studio 看到场景、镜头目的、景别、机位、运动、时长和连续性约束。分镜候选以卡片呈现，审核结果为“批准并继续”“要求修改”“驳回”，不把 `ShotPlan` 或 materialization code 当作主界面。

### 关键帧审核

用户进入镜头后查看 START / MIDDLE / END 三张关键帧卡片。每张卡片显示时间、画面描述、人物和场景状态、情绪、摄影和运动。用户可以逐帧要求修改，或批准整组并进入图片生产；批准动作明确会触发编译和刷新生产状态。

### 图片审核

用户在视觉网格中比较多个图片候选，查看人物一致性、场景一致性和当前关键帧关联。用户选择采用、要求重做或驳回；采用后候选才成为正式图片，并成为视频来源。

### 视频审核

用户使用播放器观看视频，旁边显示 START/END 对照、Prompt 摘要、ShotDirection 摘要和连续性检查。审核通过形成正式视频；要求重做保留原因和上一版，不需要用户处理 provider task id。

### Episode 自动制作

用户在制片台点击“自动制作”后先看到本轮范围、预计镜头数、关键帧数、视频数和预计人工审核次数。用户确认开始后看到逐镜头活动流；到达人工节点时进入 Review Inbox，只有技术或依赖异常才显示“阻塞”。

### 交付

用户在交付中心选择集和版本，系统汇总 QA、正式媒体、审核记录和导出配置。导出前显示仍未完成的审核和 stale 项；导出记录可追溯到正式版本和 lineage。

## Journey success checks

- 创建项目到内容基础稳定：不超过一个主入口和一个确认动作。
- 任意 review item：一次点击进入正确对象。
- 任意 shot：3 秒内看到阶段、已有结果、待办和下一步。
- Episode 自动制作：启动前可见范围，运行中可见活动，人工节点可直接接管。

## Handoff rules

- 每次跨页面跳转都携带 `book_id`、`episode`、`scene_id`、`shot_id`、`task_id`、`blocker_code`。
- 进入页面后先定位对象，再展示全局背景。
- 用户修改只能写入草稿或新版本；Source Fact 和 ScriptIR 作为只读事实层。
- AI 只生成建议和候选，确认按钮必须明确写入范围。

## Recovery journey

当任务失败或等待上游时，用户看到：发生了什么、影响范围、等待谁、可做什么、是否可跳过。失败操作提供“查看日志”“重试当前版本”“回退到上一个正式版本”三个动作。
