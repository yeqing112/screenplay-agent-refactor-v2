# User Journey V3

## Primary user

短剧导演、编剧和制片协作成员。用户希望从故事快速推进到可审核的镜头媒体，同时保留人工判断和版本回退能力。

## Journey map

| 阶段 | 用户目标 | 页面 | 主行动 | 成功信号 |
|---|---|---|---|---|
| 1. 选择项目 | 找到要继续的项目 | 项目列表 | 继续制作 | 显示当前阻塞和上次位置 |
| 2. 稳定内容 | 确认原始内容和集数 | 内容准备 | 确认内容基础 | 内容来源、规模、目标集数明确 |
| 3. 锁定方向 | 统一风格、节奏和平台 | 改编方向 | 锁定主方向 | 项目级方向有版本和时间 |
| 4. 完成剧本 | 审阅集级剧本 | 剧本工作台 | 查看证据并锁稿 | 脚本 QA 可解释，版本可回退 |
| 5. 设计镜头 | 把场景转为可执行镜头 | 镜头工作台 | 编辑并审核镜头计划 | 每个镜头有 shot context 和连续性规则 |
| 6. 准备资产 | 补齐人物、场景、道具 | 资产中心 | 绑定或修订资产 | 正式资产可追溯，缺失项可聚合 |
| 7. 生成候选 | 产生图片/视频候选 | 镜头工作台 | 生成候选 | 候选与正式版本分离 |
| 8. 人工审核 | 选择、批注、退回 | 审核抽屉 | 批准 / 退回 / 需要修订 | 记录 reviewer、原因、版本 |
| 9. QA 与交付 | 检查成片并导出 | QA 修复、导出中心 | 处理阻塞并导出 | 导出包显示版本和证据 |

## Handoff rules

- 每次跨页面跳转都携带 `book_id`、`episode`、`scene_id`、`shot_id`、`task_id`、`blocker_code`。
- 进入页面后先定位对象，再展示全局背景。
- 用户修改只能写入草稿或新版本；Source Fact 和 ScriptIR 作为只读事实层。
- AI 只生成建议和候选，确认按钮必须明确写入范围。

## Recovery journey

当任务失败或等待上游时，用户看到：发生了什么、影响范围、等待谁、可做什么、是否可跳过。失败操作提供“查看日志”“重试当前版本”“回退到上一个正式版本”三个动作。
