# 75api MiniMax H3 接入说明

## 模型能力

75api 使用的模型名为 `minimax_h3_no_audios`。该模型不是文生视频模型，必须提供首帧图或一组参考图；模型不接收音频输入。

支持的输入模式：

- `image_to_video`：`images` 中提供一张首帧图。
- `reference_to_video`：`images` 中提供多张参考图。

## API 合同

- Base URL：`https://www.75api.com`
- 提交：`POST /v1/videos`
- 查询：`GET /v1/videos/{task_id}`
- 结果回收：`GET /v1/videos/{task_id}/content`
- 鉴权：`Authorization: Bearer <API_KEY>`
- `model`：`minimax_h3_no_audios`
- `seconds`：字符串，5–15 秒
- `resolution`：`480p` 或 `768p`
- `aspect_ratio`：`16:9` 或 `9:16`
- `images`：最多 8 张 HTTP(S) 图片 URL

请求体只允许使用以下字段：

```json
{
  "model": "minimax_h3_no_audios",
  "prompt": "...",
  "seconds": "6",
  "aspect_ratio": "9:16",
  "resolution": "768p",
  "images": ["https://example.com/reference.png"]
}
```

## 系统策略

- provider 使用独立标识 `75api-minimax-h3`，不覆盖现有 `minimax-h3-async`（Metaso 兼容接口）。
- 75api 路径拒绝没有图片的请求、首帧与多参考混用、超过 8 张图片以及 5–15 秒以外的时长；不做静默截断或时长改写。
- 正式工作台在登记真实提交意图时冻结当前视频模型配置 ID；确认提交如果发现模型配置已漂移，会拒绝提交并要求重新登记，避免把同一份导出误发给另一家 provider。
- 提交模式由实际输入决定：存在锁定多参考图时使用 `reference_to_video`，否则在有采纳首帧时使用 `image_to_video`；不会把“始终多参考”作为默认假设。
- 查询响应兼容 `id` / `task_id`，状态兼容 `queued`、`processing`、`completed` 等；完成响应没有 URL 时回退到鉴权的 `/content` 地址。
- `/content` 回收会携带 provider Bearer 鉴权并写入本地生成视频存储。

## 与现有 Metaso H3 的边界

Metaso 继续使用 `/v2/video_generation`、`content[]`、`duration`、`ratio` 和可区分的图片角色；75api 适配器只负责转换到自身的顶层字段，不共享不兼容参数。
