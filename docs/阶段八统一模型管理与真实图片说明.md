# 阶段八统一模型管理与真实图片说明

## 本阶段完成内容

- 模型注册表新增 `embedding` 能力。
- 内容准备链路里的向量检索默认读取模型注册表中的向量默认项。
- 图片能力已支持 `openai-compatible` 真实图片 provider。
- 视频能力仍保留为 Mock 默认，后端会阻止真实视频配置成为默认项。
- 前端模型管理弹窗已展示 `LLM / 向量 / 图片 / 视频` 四类配置。
- 真实图片任务会透传并持久化 `model_profile_id / provider / uses_mock`。

## 当前支持的 provider

### LLM

- `openai-compatible`

### 向量

- `ollama`
- 使用接口：`POST /api/embed`

### 图片

- `prototype-task-adapter`
- `openai-compatible`

### 视频

- `prototype-task-adapter`
- `openai-compatible` 目前仅允许预配置和测试连接，不允许成为默认视频模型

## 默认模型解析规则

1. 前端优先读取 `/api/model-registry/defaults`。
2. 如果某项默认配置缺失、禁用或不合法，后端自动回退到内置默认项。
3. `embedding` 默认项只参与内容准备链路与模型管理，不会出现在分镜生产页顶部模型提示。
4. 视频默认项存在额外保护：
   - 当真实视频 adapter 未接入时，默认视频模型只能落到 `builtin-mock-video`。
5. 向量默认项如果没有用户自定义配置，会自动回退到：
   - `base_url = OLLAMA_BASE_URL`
   - `model_name = EMBEDDING_MODEL`

## 真实图片配置方式

在模型管理中新增 `图片` 配置时：

- `provider` 选择 `openai-compatible`
- 填写 `base_url`
- 填写 `model_name`
- 填写 `api_key`

保存并设为默认后：

- 分镜图真实生成会走该配置
- 参考图真实生成也会走该配置
- 任务结果会保留 `modelProfileId`、`provider`、`usesMock`

## 向量模型配置方式

在模型管理中新增 `向量` 配置时：

- `provider` 选择 `ollama`
- `base_url` 指向 Ollama 服务
- `model_name` 填写 embedding 模型名
- 可选 `default_params.dimension`

保存并设为默认后：

- 内容准备链路中的检索与向量化会优先使用该配置
- 若该配置不可用，运行时会回退到环境变量默认值

## 当前限制

- 真实视频 provider 尚未接入生成 adapter。
- 模型管理里可以预配置真实视频模型，但：
  - UI 不会把它作为推荐默认项
  - 后端也会拒绝把它解析成默认视频模型

## 验收建议

- 先用假图片 provider 验证真实图片链路。
- 再用本地 Ollama 验证向量模型连接测试。
- 最后确认：
  - `/api/model-registry/defaults` 返回 `embedding`
  - 真实视频默认项仍解析为 `builtin-mock-video`
