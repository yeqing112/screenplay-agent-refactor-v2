# 2026-07-29 创作画布 Beta 缺失恢复目标回镜头工作台闭环验收记录

## 验收目标

确认以下恢复链路已经真正闭环，而不是只停留在代码层：

`任务中心 / 其他恢复入口 -> 创作画布 Beta（缺失恢复目标） -> 前往镜头工作台`

重点验证：

1. 画布能识别“恢复目标不存在”
2. 画布能给出正确的人工确认动作
3. 跳到镜头工作台后，仍然保留任务上下文，而不是只剩普通镜头列表

## 验收环境

- 日期：2026-07-29
- 前端：`http://127.0.0.1:5175`
- 后端：`http://127.0.0.1:18765`
- 项目：`三个和尚`
- 验收方式：真浏览器自动化模拟真实用户操作

## 验收步骤

1. 打开项目首页并进入 `三个和尚`
2. 在浏览器本地写入恢复导航状态：

```json
{
  "section": "canvas",
  "canvasNavigationTarget": {
    "episode": 1,
    "shotId": "999",
    "taskId": "missing-task-001",
    "recoveryKind": "frame"
  }
}
```

3. 刷新页面，等待正式产品工作台恢复到 `创作画布 Beta`
4. 检查画布顶部恢复横幅
5. 点击 `前往镜头工作台`
6. 检查镜头工作台顶部是否出现“恢复目标未命中”横幅，并保留任务 ID
7. 清理本地恢复导航状态

## 实际结果

### 1. 创作画布缺失态成立

画布页成功显示：

- `创作画布 Beta`
- `暂未定位到恢复目标`
- `恢复收口待人工确认`
- `回任务中心`
- `前往镜头工作台`

同时未再显示误导性的：

- `定位恢复节点`

说明当前画布已经能区分：

- 数据仍在同步
- 目标真实缺失

而不是把两种情况混成一个“空态”。

### 2. 从画布进入镜头工作台后，上下文没有丢

点击 `前往镜头工作台` 后，镜头工作台成功显示缺失恢复横幅：

- `恢复目标未命中`
- `第 1 集 / 镜头 999`
- `任务 ID：missing-task-001`
- `回任务中心`
- `我知道了`

这说明从画布到镜头工作台的恢复跳转，现在已经保留了：

- `episode`
- `shotId`
- `taskId`
- `recoveryKind`

不再是“跳到了镜头页，但丢了这次恢复到底在处理什么”。

## 验收结论

本轮闭环验收通过。

当前 `任务中心 / 画布 / 镜头工作台` 三者之间，针对“恢复目标不存在”的异常场景，已经具备可解释、可继续操作、可回退的真实恢复链路。
