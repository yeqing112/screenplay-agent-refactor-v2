# 2026-09-08 智能导演台动作提案真浏览器验收记录

## 验收范围

验证正式工作台中的 Agent 动作提案 UI 链路：

1. 普通对话直接回复；
2. 副作用请求显示确认卡；
3. 用户确认后关闭抽屉并承接到精确的镜头工作台对象；
4. 原工作台的上游放行门禁仍然可见，Agent 不绕过生产安全门；
5. 浏览器控制台无错误。
6. 资产中心与 QA 工作台可以承接 Agent 提案；过期证据不会继续导航。

## 执行方式

- 命令：`npm run e2e:agent-browser`
- 浏览器：独立 Playwright Chromium（headless）
- 样本：`book 75 / 第 1 集 / 镜头 3`
- 聊天与承接接口使用隔离 mock，避免触发真实模型或生产写入；真实服务端协议由 `tests/test_agent_chat_api.py`、`tests/test_director_agent_draft_api.py` 覆盖。

## 结果

- Agent 抽屉正常打开，项目动态和未读徽标可见。
- 普通进度请求直接返回自然语言回复。
- “请帮我生成这个镜头的视频”显示“这一步需要你的确认”确认卡。
- 点击“确认并打开工作台”后，抽屉关闭并进入 `storyboard`；通过 `data-episode="1" + data-shot-id="3"` 精确定位镜头 3。
- 镜头工作台继续显示“项目改编方向尚未正式锁定”的上游门禁，未出现自动生成或绕过确认的行为。
- 浏览器控制台错误：0。

### 扩展承接回归（2026-09-08）

- 资产提案确认后进入“资产中心”，精确选中 `book 75` 的“神秘女人”资产；页面仍保留资产治理、参考图与最终写入门禁，未自动修改资产。
- QA 提案确认后进入“QA 修复”工作台，真实 QA 问题列表可见；候选修复仍需 QA 工作台原有确认流程。
- 模拟项目事实变化后再次确认提案，页面保持抽屉打开并显示“动作提案已过期：项目事实发生变化，请重新发起请求”，没有错误导航。
- 项目动态支持“已知悉 / 稍后提醒 / 已解决”三种用户可理解的处理动作，并通过状态接口持久化；浏览器回归验证了状态依次变化为 `acknowledged → snoozed → resolved`。
- 抽屉交互补充键盘焦点管理：打开后焦点进入消息输入框，关闭后回到浮动入口；对话框声明 `aria-modal`，窄屏（390px）宽度不溢出视口。
- 浏览器控制台错误：0（预期的 409 过期响应已从测试噪声中过滤并单独计数）。
