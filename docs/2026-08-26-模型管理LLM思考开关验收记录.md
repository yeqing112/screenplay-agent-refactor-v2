# 2026-08-26 模型管理 LLM 思考开关验收记录

## 背景

真实 LLM clone-only 灰度已接入 `mimo / mimo-v2.5`。灰度结果显示主要耗时集中在真实 LLM compile 阶段；同时 mimo-v2.5 支持在 Chat Completions 请求体中通过 `thinking.type = disabled` 关闭思考。

因此模型管理需要把“是否开启思考”从隐藏 JSON 参数提升为显式配置项，避免后续只能手工改 `default_params`。

## 本轮改动

- 模型管理弹窗的 LLM / openai-compatible 配置新增“开启思考”开关。
- 新建 LLM 配置的推荐默认参数新增：
  - `thinking.type = disabled`
- 开关与“默认参数 JSON”双向保持同源：
  - 关闭：`default_params.thinking = {"type": "disabled"}`
  - 开启：`default_params.thinking = {"type": "enabled"}`
- LLM 配置列表卡片新增思考状态徽章：`思考：关闭 / 思考：开启`。
- 正式工作台模型管理概览的 LLM 健康线与指标卡展示当前思考模式。
- 后端 `core.llm.call_llm(...)` 会从模型注册表默认参数读取 `thinking`，并透传到 `/chat/completions` 请求体。
- 内置 env LLM profile 也默认包含 `thinking.type = disabled`，确保新环境或回退到环境变量配置时行为一致。

## 边界

- 已有 LLM 配置如果从未保存过 `thinking`，界面会按“关闭思考”展示；后续在模型管理保存一次后会写入显式参数。
- 本轮已把当前默认 `mimo / mimo-v2.5` 配置补写为 `thinking.type = disabled`，保留原密钥且未输出密钥。
