# 2026-07-29 创作画布 Beta 恢复上下文验收记录

## 本轮目标

继续沿着 LibTV 化融合路线，补强 `任务中心 -> 创作画布 Beta` 的真实恢复链路，让画布不再只是“跳到某个节点”，而是明确接住：

1. 我是从哪条恢复链路进来的
2. 当前围绕哪个任务继续确认
3. 下一步可以回哪里继续处理

## 本轮实现

涉及文件：

- `web/src/components/productWorkspaceSectionContracts.ts`
- `web/src/components/productWorkspaceAssetViewController.ts`
- `web/src/components/productWorkspaceCanvasBeta.ts`
- `web/src/components/ProductWorkspaceCanvasBetaSection.tsx`
- `web/src/components/productWorkspaceCanvasBeta.test.ts`

关键改动：

1. 扩展 `CanvasNavigationTarget`
   - 新增 `recoveryKind`
   - 新增 `recoveryIntent`

2. 保留跨工作面恢复语义
   - 从任务中心或其他入口跳转到 `canvas` 时，不再只传 `episode / shotId / assetId / taskId`
   - 同时把 `recoveryKind / recoveryIntent` 一并带入画布

3. 画布新增恢复上下文摘要
   - 在 `productWorkspaceCanvasBeta.ts` 中新增 `buildCanvasNavigationSummary`
   - 生成可读标题与说明，例如：
     - `第 1 集 / 镜头 3 / 第 1 集 · 3 / 视频回收`
     - `当前正在围绕任务 runtime-verify-pending-001 的恢复结果继续定位与确认`

4. 画布头部新增恢复上下文条
   - 在 `ProductWorkspaceCanvasBetaSection.tsx` 中渲染 `恢复上下文`
   - 支持动作：
     - `回任务中心`
     - `前往镜头工作台`
     - 当只有资产上下文时支持 `前往资产中心`

## 结论

- 通过

这一步说明 `任务中心 -> 创作画布 Beta` 已经从“只会跳页”推进到“带着恢复语义进入画布并给出下一步动作”。

- 在刚切到画布的瞬间，页面可能先短暂呈现空画布文案

这不阻塞本轮验收通过，但值得在后续继续收敛成更平滑的加载体验。
