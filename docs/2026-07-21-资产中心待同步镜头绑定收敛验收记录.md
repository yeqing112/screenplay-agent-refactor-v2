# 2026-07-21 资产中心待同步镜头绑定收敛验收记录

## 验收背景

在真实项目数据中，资产中心已经可以识别“某资产影响了哪些镜头”，但很多资产仍停留在：

- 页面显示 `待同步绑定 N`
- 资产记录里 `已保存绑定 0`
- 用户还需要手工逐个把镜头重新勾一遍再保存

这会导致资产中心虽然“看见了引用关系”，却没有把识别结果真正收敛成结构化绑定数据，后续提示词编译、QA 和导出仍然更依赖推断而不是正式记录。

## 本轮目标

让资产中心在真实页面里具备以下能力：

1. 当资产已有系统识别出的影响镜头、但还没有正式写回绑定时，自动把这些镜头放入绑定草稿
2. 用户能明确看到“这些镜头尚未写回资产绑定”
3. 用户保存后，可以把草稿一次性写回正式的镜头绑定字段

## 本轮实现

### 前端行为调整

1. 新增绑定草稿初始化规则：
   - 如果资产已经有正式 `shotIds`，优先沿用正式绑定
   - 如果资产还没有正式绑定，但系统已识别出 `impactShots`，则自动用这些镜头初始化 `linkedShotDraft`

2. 新增待同步提示层：
   - 当 `impactShots` 中仍有镜头未写回 `shotIds` 时，在资产中心显示醒目的待同步提示
   - 如果这些镜头已经自动加入草稿，则提示“保存后会真正写回资产记录”
   - 如果草稿还没覆盖全部待同步镜头，则显示 `加入待同步镜头` 操作

3. 保持原有保存入口不变：
   - 用户仍通过 `保存镜头绑定` 完成最终写回
   - 不额外引入新的后端接口，沿用现有资产 PATCH 链路

3. 用户现在只需要点击一次 `保存镜头绑定`，就可以把推断结果收敛成正式记录

### 关于 `加入待同步镜头` 按钮

本轮在 `和尚甲` 的真实数据里，没有出现 `加入待同步镜头` 按钮。

原因不是功能失效，而是当前页面已经更进一步：

- 待同步镜头已经被自动放进草稿
- 因此无需再额外点一次“加入”

也就是说，当前真实体验优于“先看到按钮、再手动加入”的保底方案。
