# 智能导演台 Agent：阶段任务与验收标准

日期：2026-09-06  
落档：[智能导演台 Agent 用户决策与落档方案](./2026-09-06-智能导演台Agent-用户决策与落档方案.md)
本文件状态：阶段任务与验收标准，与生产链路并行推进。

## 共享原则

- Agent 不得绕过既有 `DecisionPacket`、`Prompt Version`、资产锁定、对象存储生产门禁与真实媒体双确认。
- 所有外部模型调用、对象存储写入、版本覆盖必须由用户在 UI 显式确认。
- 不为 book、角色、资产或镜头做特例；规则须通用、可审计、可回滚。
- 审计与回放必须独立可查，并与生产链路审计对齐。

## Phase 1：抽屉式对话 UI（自由对话 + 受控草案）

状态：**进行中（2026-09-08）**。抽屉、当前上下文、自由对话、主动项目汇报、权限展示、独立模型选择、受控真实 LLM 草案协议、任务中心只读联动及首批内置 Skill 已完成；生产执行仍只由原工作台门禁承接。

### 任务

- 全局悬浮按钮 + 右侧抽屉，覆盖工作台。
- 会话 / 计划与草案 / 输入与确认三层内容。
- 工作台当前项目对象作为上下文注入对话。
- 对话输出必须链接到具体对象和版本。
- Agent 模型接入：使用“模型管理 → 管理员配置”中的独立 Profile 引用。

### 当前完成项

- App 全局右下角“智能导演台”触发器与右侧可关闭抽屉已完成；默认隐藏，不影响工作台首屏。
- 抽屉展示当前项目上下文和自然语言对话；普通消息调用 `/api/agent/chat` 直接返回答复，不要求先生成计划或确认调用模型。旧的 `POST /api/agent/plan` 仍作为专家级只读计划接口保留。
- 真实浏览器已验证：A/B 计划可展示；勾选 C/D 操作后，计划明确显示“需你确认”，但不会执行写入或外部调用。普通聊天不展示这层技术审批流程；只有模型返回副作用动作提案时才显示确认卡。
- 模型管理新增“管理员配置：智能导演台模型”：只引用既有 LLM Profile，不复制密钥，不改生产默认 LLM；默认“不配置（Phase 1 只读模式）”。
- 已接入受控真实 LLM 草案：先冻结 DirectorPlan 证据并给出完整 system/user prompt、模型标识、预计 token 与计费提示；预览绝不调用模型。
- 真实调用必须同时提交 `confirmed=true` 与 `allowExternalCall=true`，并校验预览草案、计划和证据指纹未变化；相同指纹会复用既有候选草案，避免重复计费。
- 调用结果仅写入 `AgentSession`、`AgentPlan`、`AgentAuditLog` 和候选建议；不创建 Prompt Version、不改动资产或镜头、不提交图片/视频任务。
- Agent 预览前会在服务端冻结项目事实包，不信任浏览器传入的摘要。证据包按范围收集项目、剧本、镜头、人物/场景/道具与锁定参考状态、QA、任务、Prompt Version、DecisionPacket；内容有上限且不含密钥或原始公网地址。
- 候选草案可读取“承接预览”：只列出与冻结作用域匹配的既有 Prompt、QA、版本或媒体工作台入口及其 A/B/C/D 门禁；Agent 不会通过该预览直接创建版本、修改生产对象或提交媒体任务。
- 自由对话的副作用动作提案现在携带审计编号；用户点击“确认并打开工作台”后，`POST /api/agent/audit/{id}/handoff-confirm` 只记录承接意图并通过统一事件打开原工作台，不执行生产写入或媒体提交。
- 任务中心会读取 Agent 会话时间线，将“等待审核 / 调用失败 / 暂停 / 历史”以独立来源呈现；点击只会打开智能导演台，绝不将 Agent 会话伪造为媒体或生产任务。
- 动作提案确认后可安全承接到镜头、资产或 QA 工作台；承接只导航并记录意图，不执行生产写入。项目事实变化时确认会返回过期错误并保持抽屉打开，要求重新发起请求。
- 项目动态提供“已知悉 / 稍后提醒 / 已解决”三种用户动作，均复用审计状态接口；抽屉打开后焦点进入输入框，关闭后回到入口，窄屏宽度不溢出。
- 已注册四个内置、声明式 Skill：短剧生产、连续性、TVC、儿童教育。Skill 只允许约束候选操作、要求的证据范围及真实 LLM 的系统提示词，不能执行插件代码、访问数据库、密钥、网络或任意 Shell。

### 验收

- 抽屉默认隐藏；显示时不遮挡首屏当前阶段、原因与唯一下一步。
- 只读计划不会触发模型、写入或外部调用。
- C/D 档计划步骤必须标记为“需你确认”。
- 后端受控协议：19 项相关测试通过，覆盖未确认不调用、过期指纹拒绝、候选草案不触碰生产对象、重复调用去重与 Agent 模型脱敏。
- 动作承接协议补充回归：确认可重复请求且幂等；非副作用对话、未知工具和已处理提案均被拒绝。
- 前端生产构建及抽屉相关测试通过；`npm run e2e:agent-browser` 已覆盖自由对话、镜头/资产/QA 承接、项目动态状态流转、过期证据失败提示、焦点管理和 390px 窄屏。

## Phase 3：首批 4 个 Skill

状态：**基础注册与抽屉选择已完成（2026-09-06）**；各 Skill 的领域表单和完整灰度样本留在后续生产验收中。

### 任务

- 短剧生产 Skill：承接当前全链路。
- TVC Skill：Brief、卖点、时长、品牌禁忌、平台规格、镜头节奏。
- 儿童教育 Skill：年龄段、知识目标、安全、语言难度、互动节奏。
- 连续性 Skill：相邻镜头连续性诊断与衔接建议。
- Skill 注册表、版本化、灰度开关与第三方受控扩展。

### 验收

- 每个 Skill 仅输出结构化计划与草案；不复制独立数据表或前端。
- 第三方 Skill 必须有受控清单与沙箱；不允许直接访问数据库、密钥或任意 Shell。

### 当前实现边界

- `GET /api/agent/skills` 是唯一的 Skill 清单来源；未知 Skill 在服务端拒绝，不能借由前端自定义名称注入提示词。
- 每个 Skill 都包含 `id / version / description / input_schema / allowed_operations / required_evidence / prompt_block`；计划 API 会删去不在白名单内的候选操作，再冻结 Skill 元数据进入计划和证据指纹。
- 第三方或自研扩展的下一步是“受审查的声明式清单 + 隔离执行器”设计；在此之前不接受可执行脚本形式的扩展。

## Agent 运行策略（2026-09-07）

模型管理与 Agent 设置采用两层职责：模型管理仅维护供应商、模型标识及客观能力事实（例如是否声明视觉输入能力）；智能导演台单独维护“开启思考”和“允许读取对话图片”策略。两者同时满足时才会向真实模型发送图片。保存 Agent 策略不会切换生产默认模型，也不会写回模型注册表；预览仍为只读，真实调用继续要求 `confirmed=true` 与 `allowExternalCall=true`。

## 主动汇报与项目驾驶舱（2026-09-07）

智能导演台新增产品基线：Agent 必须主动掌握项目进度、发现问题并汇报下一步，而不是只在用户提问后返回结果。详细方案见[《智能导演台主动汇报与项目驾驶舱方案》](./2026-09-07-智能导演台主动汇报与项目驾驶舱方案.md)。

- 普通问答、分析、识图、建议、进度汇报和失败说明直接回复，不要求用户先预览或确认调用 Agent。
- 修改剧本、资产、分镜、Prompt Version、覆盖版本、提交生图/生视频和其他外部付费动作仍必须生成结构化动作提案并等待用户确认。
- 主动汇报统一使用 `AgentProjectUpdate` 契约，包含类型、严重程度、来源对象、证据指纹、去重键、处理状态和可选动作提案。
- 任务完成、失败、超时、QA 阻塞、资产/版本变化、连续性冲突、项目阶段变化和用户重新打开项目都可以触发汇报。
- 抽屉显示自然对话与项目动态，入口显示未读数量；任务中心同步阻塞和待确认事项；证据与审计细节按需展开。
- 汇报必须基于服务端事实和冻结证据，不能凭空推断；证据变化后旧动作提案自动过期。

### 新增阶段任务

1. 新增 `AgentProjectUpdate` 模型、迁移、状态机和 `dedupe_key + evidence_fingerprint` 去重。
2. 建立项目事实采集器和确定性进度/风险检测器。
3. 增加汇报查询、已读/已知悉、稍后提醒和事件流 API。
4. 改造自由对话回复和智能导演台抽屉，移除普通分析的“预览 LLM → 确认调用”体验。
5. 接入任务中心、SSE 推送和轮询回退，完成后端、前端及真浏览器验收。
