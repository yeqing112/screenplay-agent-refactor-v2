# 2026-07-21 Phase 7 关键绑定资产编译安全门补充验收标准

## 背景

在真实本地数据验收中，已出现过如下退化场景：

- 当前镜头已绑定场景、人物、道具资产
- 人物和关键道具已经存在参考图
- LLM 编译结果却只保留场景描述与场景 `used_assets`
- 编译接口此前会把该退化结果保存为新版本，覆盖掉可用旧版本

这会直接破坏分镜提示词编译的生产可用性，因此需要把“关键绑定资产不能在编译结果里消失”提升为 Phase 7 的强制验收口径。

## 新增任务

- 在分镜编译诊断中新增 `critical_bound_asset_usage` 检查。
- 将以下资产定义为“关键绑定资产”：
  - 已绑定且已有参考图的场景资产
  - 已绑定且已有参考图的人物资产
  - 已绑定、已有参考图、且 `importance = high` 的道具资产
- 若候选编译结果的 `used_assets` 丢失关键绑定资产，系统必须先进入一次自动修复。
- 若自动修复后仍然丢失，编译接口必须返回 `422`。
- 被阻断时，不得覆盖上一版已保存的提示词版本。
- 阻断响应必须返回：
  - `compiler_diagnostics`
  - `repair_attempted`
  - `candidate_output`

## 新增验收标准

1. 当 LLM 候选结果只保留场景、遗漏已绑定人物或高重要度道具时，系统不能直接保存该版本。
2. 自动修复后若仍遗漏关键绑定资产，`POST /api/books/{book_id}/storyboard/{episode}/{shot_id}/compile-prompts` 必须返回 `422`。
3. 被拦截后，数据库中的上一版 `visual_prompt_static`、`visual_prompt_motion`、`used_assets` 必须保持不变。
4. `compiler_diagnostics.checks` 中必须出现 `critical_bound_asset_usage` 失败项。
5. `critical_bound_asset_usage.details` 必须输出具体丢失资产，例如：
   - `和尚甲：已绑定人物且有参考图，但本次编译未纳入 used_assets`
   - `木桶：高重要度道具已绑定且有参考图，但本次编译未纳入 used_assets`
6. 该规则必须通过两层验证：
   - 回归测试验证接口行为与旧版本保护
   - 真实本地数据的进程内验收验证运行态一致性
