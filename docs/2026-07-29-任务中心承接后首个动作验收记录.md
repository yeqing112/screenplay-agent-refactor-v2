# 2026-07-29 任务中心承接后首个动作验收记录

## 验收范围

- 模块：正式产品工作台 -> 任务中心
- 目标：把“恢复上下文说明”升级为“承接后的首个动作 + 立即继续”
- 核验对象：真实项目 `三个和尚`

## 本次实现

- 在任务中心选中任务详情区新增 `承接后的首个动作` 卡片。
- 卡片会根据当前任务真实状态自动推荐一个最优下一步，并直接接到真实动作：
  - `queued` -> `刷新状态`
  - `running` -> `继续回收结果`
  - `error + frame/video` -> `按最新状态重生成`
  - `error + 其他恢复任务` -> `按原始输入重发`
  - `done / 已成功恢复` -> `在创作画布查看`
  - 已存在明确业务入口时 -> 优先跳转对应正式模块
- 卡片按钮统一使用 `立即继续`，不移除原有详细恢复操作面板。

## 自动化验收

- 通过：`cd web && npm run test -- productWorkspaceTaskCenterSelectedTaskPanel`
- 通过：`cd web && npm run build`

## 真浏览器验收

### 路径

`三个和尚 -> 正式产品工作台 -> 任务中心 -> 首帧结果回收`

### 结果

1. 任务中心详情区出现 `承接后的首个动作`
2. 当前真实任务状态为 `已完成`，首个动作正确推荐为 `在创作画布查看`
3. 点击 `立即继续` 后，页面成功跳转到 `创作画布 Beta`
4. 创作画布顶部正确显示恢复上下文：`第 1 集 / 镜头 3`
5. 画布已自动聚焦到对应镜头，可继续沿镜头链路执行后续动作

## 验收结论

本轮验收通过。

任务中心已经不再只是展示恢复任务状态，而是具备“根据当前任务状态给出首个可执行动作，并把用户送回正确创作上下文”的能力。这条链路与 QA、交付模块的承接逻辑已经形成一致产品语义。
